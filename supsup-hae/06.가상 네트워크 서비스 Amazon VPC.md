## 6.1 Amazon VPC

### 6.1.1 Amazon VPC(Amazon Virtual Private Cloud)

> **AWS 계정 전용 가상 네트워크 서비스로 AWS에서 제공하는 리소스만 설치 가능**

- EC2, RDS의 경우 사용하지 않으면 서버 생성이 불가능하기 때문에 반드시 사용해야 한다.

### 6.1.2 구성

- VPC는 논리적으로 격리된 가상 네트워크로 구성되며, 서브넷과 게이트웨이를 통해 네트워크 환경을 구축한다.

### 6.1.3 기능

> **네트워크, 서브넷 범위, 라우팅 테이블, 네트워크 게이트웨이 등의 가상 네트워킹 환경 구성 설정 가능**

| 항목              | 내용                                                                                                    |
|-------------------|---------------------------------------------------------------------------------------------------------|
| CIDR 블록         | 서버에서 사용할 네트워크를 나타낸다. VPC를 생성할 때 네트워크 블록을 CIDR로 정한 다음 이를 더 작은 서브넷으로 나누어 사용된다. |
| 서브넷 마스크     | 네트워크의 크기를 가늠하는 것이다. CIDR는 서브넷 마스크의 표기법 중 하나이다.                           |
| 가용 영역         | 서버를 구축할 물리적인 장소이다.                                                                        |
| 인터넷 게이트웨이 | 인터넷과 연결을 위한 출입구 역할. VPC를 인터넷에 연결하지 않으면 외부에서 들어오는 것과 나가는 것 모두 차단된다. |
| 라우팅            | 어떤 네트워크를 어디로 보낼지 결정하고, 이러한 게이트웨이의 관련 설정이 있다.                          |
| 라우팅 테이블     | 경로 설정에 대한 정보가 기록된 테이블이다.                                                             |
| 보안 그룹         | AWS가 제공하는 가상 방화벽이다. 인스턴스 단위로 설정하여 들어오는 네트워크를 제어하는 기능이다.        |
| 네트워크 ACL      | AWS가 제공하는 가상 방화벽이다. 서브넷 단위로 설정된다.                                               |

### 6.1.4 네트워크 특징과 라우팅 테이블

> **물리적인 라우터가 아닌 소프트웨어가 라우터 역할을 수행한다**

- 라우팅은 라우팅 테이블에 따라 동작하는데 테이블 하나에 서브넷을 여러 개 설정 가능하다.
- 서브넷 사이의 통신을 라우터 없이 직접 통신 가능하다.
- VPC 하나에 인터넷 게이트웨이 1개만 설정 가능하다 (명시적인 IP 주소가 부여되지 않는다).


## 6.2 VPC 사용 절차

### 6.2.1 VPC 설정

> **VPC 생성 시 고려해야 할 주요 설정 사항들**

- **인터넷 연결 여부**: 인터넷 게이트웨이 설정
- **오토 스케일링**: 서버 확장을 위한 IP 주소 확보 필요
- **보안 그룹, 네트워크 ACL 사용**: 포트 기본 설정을 커스터마이징 진행할 필요가 있다
    - 기존 VPC를 제공하므로 이를 사용해도 된다.

### 6.2.2 사용 절차

1. **AWS 로그인**
    - 리전 선택 및 관리 콘솔 접속, VPC 대시보드 접속
2. **VPC 생성**
    - VPC 이름 지정, CIDR 블록 설정(네트워크 범위), 테넌시(Tenancy) 형태 선택
3. **서브넷 설정**
    - 서브넷 이름 지정, 특정 VPC 선택, 가용 영역 선택, CIDR 블록(서브넷) 설정
4. **인터넷 연결**
    - 인터넷 게이트웨이(IGW) 생성, IGW와 VPC 연결, 라우팅 설정 및 트래픽 구성

## 6.3 기본 VPC

### 6.3.1 정의

> **네트워크에 대한 지식이 없어도 이용할 수 있는 리전별 VPC**

- 특별한 설정 없이 사용 가능하며, 특별한 요건이 없을 때는 기본 사용
- ELB 같은 서비스 이용 가능

### 6.3.2 구성

| 네트워크                  | CIDR            | 네트워크의 범위                    |
|---------------------------|-----------------|-----------------------------------|
| VPC 전체의 네트워크 범위  | 172.31.0.0/16   | 172.31.0.0 ~ 172.31.255.255      |
| 서브넷 1                  | 172.31.0.0/20   | 172.31.0.0 ~ 172.31.15.255       |
| 서브넷 2                  | 172.31.16.0/20  | 172.31.16.0 ~ 172.31.31.255      |
| 서브넷 3                  | 172.31.32.0/20  | 172.31.32.0 ~ 172.31.47.255      |
| 서브넷 4                  | 172.31.48.0/20  | 172.31.48.0 ~ 172.31.63.255      |

- 서브넷과 인터넷 게이트웨이가 기본적으로 구성
    - 네트워크 범위: 172.31.0.0/16이 부여되며 기본 서브넷이 가용 영역별 1개씩 생성 (서울은 4개)

## 6.4 서브넷과 DHCP

### 6.4.1 서브넷

> **커다란 네트워크를 작게 나눈 네트워크로 직접 통신할 수 있는 범위를 좁히고 방화벽을 설정하여 보안을 강화하는 것을 목적 → 물리적인 장소를 특정**

- 서브넷별 역할을 다르게 부여 가능하며 기존 네트워크와 달리 VPC는 라우팅 없이 서브넷끼리 통신 가능

### 6.4.2 네트워크 범위와 CIDR 표기

> **CIDR: 네트워크와 서브넷의 범위를 나누는데 사용되는 표기법으로 IP 주소의 수**

- 네트워크 범위는 첫 번째 IP 주소와 CIDR 순으로 표기
    - 172.31.0.0/16이라면 /16은 65,536개라는 의미이므로 172.31.0.0부터 172.31.255.255까지가 네트워크 범위

### 6.4.3 네트워크 클래스

- 기본 VPC는 B 클래스로 설정되어 있으며 /20으로 분할한 가용 영역이 구분되어 있다 (4096개)
    - 서브넷 활용 범위는 /16까지이다.

### 6.4.4 주소 할당과 DHCP

> **일반적인 경우 IP 주소 할당이 가능한 것은 EC2, RDS 인터페이스**

- VPC는 인터넷 게이트웨이의 IP 주소로 예약 주소 사용 가능
- IP 주소 범위는 관리자 설정, DHCP에서 각 호스트에 IP를 자동으로 할당한다.
- 인스턴스 추가 시 해당 서브넷 범위 IP 주소 중 1개가 할당
- 예약주소: 서브넷의 1~4번째 IP 주소 및 마지막 IP 주소로, 사용할 수 없다.

## 6.5 라우팅과 NAT

### 6.5.1 네트워크와 라우팅

> **네트워크: PC 여러 대가 서로 통신할 수 있도록 연결되어 있는 상태**

- PC 보급 전 (1대1) → LAN, WAN 인터넷을 연결, 라우터를 통해 데이터를 주고받음
- 라우팅: 데이터를 라우터로 보내서 목적지에 도달하도록 보내는 방식

### 6.5.2 IP 주소와 게이트웨이

> **IP 주소: 네트워크 안의 모든 호스트에 할당된 주소로 대상을 식별하기 위함**

- 데이터 전송 시 목적지 IP 주소 지정 → 라우터로 보냄 → 목적지가 자신의 네트워크에 있다면 전송, 없다면 다른 라우터로 전송 → 목적지 도착 및 전송
- 라우터에는 네트워크 전송 경로 정보가 설정되어 있다.
- 라우터 = 게이트웨이: 네트워크의 관문
    - 기본 게이트웨이: 자신 이외의 접속되어 있는 모든 것 (대부분의 경우 인터넷과의 연결점)

### 6.5.3 IP 마스커레이드

> **사설 IP → 공인 IP 변환을 담당**

- LAN 내부의 PC에는 전부 사설 IP 주소를 할당하지만, 공인 IP 주소가 없다면 식별이 불가능
- 게이트웨이에서 사설 IP를 공인 IP로 변환하여 가정 내에서 혹은 회사 내의 공인 IP 주소를 공동으로 사용
- 내부에서 외부로 나갈 수 있지만 반대는 불가능하다 (응답 구조와 일치)
- 1:1 매핑 포트 변환 가능

### 6.5.4 NAT

> **서버가 여러 대일 경우 사용되며 공인 IP 주소를 여러 개 설정할 수 있다.**

- LAN 환경에 서버를 설치한 경우 외부 요청에 응답하기 위해 서버만 양방향 IP 마스커레이드 설정 가능
    - 하지만 마스커레이드 1개당 공인 IP 1개만 설정할 수 있다
- NAT N:M, 포트 변환 불가능

## 6.6 인터넷 게이트웨이, NAT 게이트웨이

### 6.6.1 인터넷 게이트웨이

> **인터넷 연결을 담당**

- EC2 인스턴스의 웹 페이지 접속 요청 → DNS에서 변환되어 공인 IP 주소로 전달
- EC2 인스턴스는 사설 IP 주소밖에 설정할 수 없기 때문에 요청된 EC2 인스턴스의 연결 정보를 가진 게이트웨이가 공인 IP 주소를 사설 IP 주소로 변경하여 해당 인스턴스에 요청을 보낸다.

### 6.6.2 NAT 게이트웨이

> **회사 내부 소프트웨어 업데이트 진행 시 인터넷 연결 필요 시에 사용**

- 서브넷에서 인터넷으로 접속할 수 있지만 인터넷에서 서브넷으로 접속은 불가능

## 6.7 VPC의 가상 방화벽

### 6.7.1 보안그룹과 네트워크 ACL

> **네트워크 통신을 제어하는 방화벽 기술로 인바운드, 아웃바운드 트래픽을 제어하며, 명시하지 않을 경우 기본 설정 적용**

| 항목           | 보안 그룹                                                    | 네트워크 ACL                                                |
|----------------|--------------------------------------------------------------|-------------------------------------------------------------|
| 상태 범위      | 인스턴스에 대해 생성된다(보안 그룹을 최대 5개 할당할 수 있다) | 서브넷에 설정된다                                           |
| 규칙           | 규칙 허용만 가능하다                                         | 규칙 허용과 거부가 가능하다                                 |
| 상태           | 스테이트풀(stateful) - 규칙과 상관없이 반환된 트래픽은 자동으로 허용 | 스테이트리스(stateless) - 반환된 트래픽도 규칙에 따라 명시적으로 허용 |
| 규칙 적용 순서 | 모든 규칙을 확인하여 트래픽의 허용 여부를 결정               | 순서대로 규칙을 처리하면서 트래픽의 허용 여부를 결정        |

- 네트워크 ACL: 서브넷 단위로 설정하기 때문에 개별 인스턴스 설정할 필요 없음
    - 인스턴스에 보안 그룹을 설정하지 않아도 처리 가능
    - 서브넷 여러 개를 설정 가능하지만 반대는 안 된다.

### 6.7.2 InBound, OutBound

> **트래픽: 인바운드와 아웃바운드 각각에 포트 단위(포트 번호)의 허가 여부를 설정**

- 포트: 통신의 입구로 어떤 서비스가 동작 시 해당 서비스를 사용하는 포트는 수신 대기 상태
- well-known ports: 서비스별 주로 사용되는 포트가 존재하여 이를 주로 이용한다.
- 인바운드 허가 X, 아웃바운드 허가 O, 네트워크 ACL은 양쪽 모두 허용하는 것이 각 기본 설정
