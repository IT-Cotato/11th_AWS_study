## 7. Amazon RDS

### 7.1 데이터베이스와 RDB

#### 7.1.1 데이터베이스

> **구조적으로 정리된 데이터 집합체**

- 데이터가 구조화되어 있기 때문에 데이터 검색이나 특정 데이터 추출 등의 데이터를 쉽게 조작할 수 있다.

#### 7.1.2 데이터베이스와 DBMS

> **데이터베이스 관리 시스템으로 데이터 저장, 삭제, 검색 등과 같이 데이터베이스를 실제로 조작하는 역할**

- SQL: 데이터베이스를 조작할 때 사용하는 프로그래밍 언어
    - 구문과 문법으로 정의되어 표준화되어 있으며 대부분 동일한 문법을 사용한다.
    - 대부분 프로그램을 사용하며 사용할 시스템이나 소프트웨어가 DB를 가지고 있어서 사용하는 경우가 많다.

#### 7.1.3 DBMS

- MySQL, PostgreSQL, MariaDB, Oracle, SQL Server 등 다양한 소프트웨어가 존재
- 기능이 다르거나 처리속도 중시, 네트워크 안정성, 확장성에 특화된 기능을 각각 다르게 가지고 있다.
- 대규모 시스템은 유료 DBMS를 사용하고 소규모 시스템은 무료 DBMS를 사용한다.

#### 7.1.4 관계형 DB, 비관계형 DB

**관계형 DB**

- 구축 시 시간이 많이 소요되지만 그만큼 정밀한 조작이 가능하다 → SQL을 많이 사용한다.

**비관계형 DB**

- 구조가 단순하고 설정이 적어 구축이 간단하고 액세스가 빠르다.
- Key-value, 문서형 데이터 구조를 가지며 NoSQL을 사용한다.
- AWS는 모든 종류의 DB를 제공한다.

### 7.2 Amazon RDS

#### 7.2.1 Amazon RDS

> **Amazon Relational Database Service, 관계형 데이터베이스를 클라우드에 최적화하여 제공되는 서비스**

- Aurora, PostgreSQL, MySQL, MariaDB, Oracle Database, SQL Server를 지원한다.
- 메모리, 성능, I/O 등 최적화된 데이터베이스 인스턴스를 제공한다.
- VPC 상의 인스턴스 형태로 구축하며 다양한 인스턴스 클래스를 사용 가능하다.
- 매니지드 서비스이기 때문에 AWS에 의해 업데이트 등의 관리가 자동으로 이루어지며 백업도 자동화된다.
- AWS Database Migration Service를 이용하면 기존 데이터베이스를 이전하거나 복제하는 것도 가능하다.

#### 7.2.2 인스턴스 클래스

| 용도           | 인스턴스 클래스 | 내용                                                                                          |
|----------------|----------------|-----------------------------------------------------------------------------------------------|
| 표준           | db.m5 등       | 범용적인 인스턴스 클래스이다.                                                                |
| 메모리 최적화  | db.x1e         | 메모리를 많이 사용하는 애플리케이션에 최적화된 인스턴스 클래스이다. 일부 리전에서만 제공된다. 한국 리전에서는 이용할 수 없다. |
|                | db.x1          | 메모리를 많이 사용하는 애플리케이션에 최적화된 인스턴스 클래스이다. 메모리 최적화가 db.x1e의 절반이다. |
|                | db.r5 등       | 네트워크의 EBS와 성능을 강화한다. AWS Nitro System을 사용한다.                              |
| 버스트 성능    | db.t3 등       | CPU의 최대 사용률이 버스트 성능으로 사용될 수 있다.                                          |

- 표준, 메모리 최적화, 버스트 성능의 3종류가 존재한다.
- micro, small, medium, large, xlarge, 2xlarge, 4xlarge, 8xlarge, 16xlarge를 제공하며 클래스에 따라 지원하지 않는 DBMS나 버전이 존재한다.
- VPC를 설치해야 사용이 가능하다.

#### 7.2.3 요금

> **스토리지 요금 + 데이터베이스 인스턴스 요금 + 백업 스토리지 요금 + 통신료**

1. **스토리지 요금**
    - 사용하고 있는 스토리지 서비스에 대한 요금
    - 실제 사용한 용량이 아닌 할당하고 있는 양에 대해 과금되기 때문에 주의가 필요하다.

2. **데이터베이스 인스턴스 요금(DBMS 인스턴스 요금 포함)**
    - 인스턴스와 마찬가지로 기본 시간당 요금이 발생한다.
    - 간단하게 사용할 수 있는 소형부터 고성능 인스턴스까지 있으며 성능이 높을수록 요금이 비싸진다.
    - 계산기를 이용하여 예상 사용량과 데이터베이스 옵션(DBMS)에 따라서 요금이 다르다.
    - 또한 AZ를 구성한 이중화를 구축하면 단일 AZ 구성보다 약 2배의 요금이 부과된다.
    - 유료 DBMS의 경우 인스턴스 요금까지 추가되기 때문에 오픈 소스 데이터베이스를 사용하는 것에 비해 비싸다.

3. **백업 스토리지 요금**
    - 데이터베이스 인스턴스를 백업할 수 있다. 이 백업을 스냅샷이라고 한다.
    - 스냅샷은 백업 스토리지 장소에 생성되어 사용 용량에 따라 요금을 부과한다.
    - 단, 스냅샷 요금은 데이터베이스 스토리지 구성의 100%를 넘을 경우만 부과된다.
    - 예를 들면 20GB의 데이터베이스 용량을 할당하고 있을 경우 스냅샷의 용량이 20GB가 넘지 않으면 무료이다.

4. **통신료**
    - 데이터베이스 인스턴스가 인터넷으로 통신할 경우 해당 전송량에 대해 요금이 부과된다.
    - VPC 내의 EC2 인스턴스와 통신하는 경우와 같이 AZ 내에서 통신할 경우 요금이 부과되지 않는다.

#### 7.2.4 RDS 장점과 단점

**장점**

- 매니지드 서비스로 AWS가 업데이트 등을 관리해주며 손쉬운 DB 생성이 가능하다.
- 데이터 이전이 간단하며, EC2 연동 및 통신료 무료 등의 혜택이 존재한다.

**단점**

- 사용자가 자유롭게 사용할 수 없다 - 버전이나 종류가 한정되어 있기 때문이다.
- 업데이트가 곤란한 시점에 수행되는 경우도 존재하기 때문에 도입 시 잘 생각해야 한다.

### 7.3 데이터베이스 엔진

#### 7.3.1 데이터베이스 엔진

- Aurora, PostgreSQL, MySQL, MariaDB, Oracle Database, SQL Server를 지원한다.
- 온프레미스에서 AWS로 쉽게 이전이 가능하며 상용 데이터베이스도 지원한다.
    - 요금 체계도 단순화되어 사용이 가능하다.

#### 7.3.2 종류

| DBMS(제공사)                                      | 내용                                                                                                                                                                     |
|---------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Amazon Aurora (Amazon)                           | MySQL이나 PostgreSQL과 호환될 수 있다. AWS가 만든 관계형 데이터베이스이다.                                                                                             |
| PostgreSQL (PostgreSQL Global Development Group) | 1970년대에 개발된 Ingres라는 데이터베이스부터 만들어진 오픈 소스 데이터베이스이다. MySQL과 관련없지만 블로그를 비롯하여 소셜형 사이트까지 폭넓게 사용되고 있다.      |
| MySQL (Oracle)                                   | 스웨덴의 MySQL AB가 개발한 데이터베이스이다. 그 후 선 마이크로시스템즈를 거쳐 오라클에 매수되었다. 블로그와 같이 소규모 시스템부터 수많은 사이트의 기반 CMS 시스템까지 폭넓게 사용되고 있으며 오픈 소스 RDBMS 중에 인기가 많은 편이다. |
| MariaDB (MariaDB Program Ab)                     | MySQL 개발자가 스핀오프하여 개발한 데이터베이스이다. 기능은 MySQL과 거의 같으며 완벽하게 GPL 라이센스이다.                                                            |
| Oracle Database (Oracle)                         | 오라클이 제공하는 데이터베이스이다. 소규모 시스템부터 엔터프라이즈 시스템까지 폭넓게 지원하는 데이터베이스이며 중앙정부나 금융 시스템에 많이 사용되고 있다. 윈도우와 리눅스 라이센스에서 동작한다. |
| Microsoft SQL Server (Microsoft)                 | 마이크로소프트가 제공하는 데이터베이스이다. 소규모 시스템부터 엔터프라이즈 시스템까지 폭넓게 지원한다. 윈도우와 리눅스에서 사용할 수 있는 소프트웨어이지만 리눅스 라이센스에서 동작한다. |

#### 7.3.3 Amazon Aurora

> **MySQL이나 PostgreSQL과 호환 가능한 Amazon RDS**

- 별도 수정사항 없이 이전 가능하지만 요금이 조금 비싸다.
- AWS 전용으로 설계되어 있기 때문에 기존 모델을 사용하는 것보다 속도가 더 빠르다.
- EC2 설치, RDS 사용, Aurora 사용의 3가지 방법 중 DBMS 변경 시 문제가 없고 높은 성능을 원할 경우 추천한다.

### 7.4 RDS 사용 절차

#### 7.4.1 RDS 조작

1. **데이터베이스 준비**
    - DB를 만들거나 설정하는 조작 등으로 관리 콘솔에서 이루어진다.
    - 버전 등의 정보는 매니지드 서비스이기 때문에 자동으로 관리된다.

2. **데이터베이스 사용**
    - 데이터를 조작하는 경우 관리 도구나 소프트웨어를 통해서 이루어진다.
    - RDS는 소프트웨어가 EC2에 설치되어 있거나 연동하여 사용한다.

#### 7.4.2 RDS 서비스 기능

**데이터베이스 엔진 항목**

| 항목                  | 의미                                                                                                                              |
|-----------------------|-----------------------------------------------------------------------------------------------------------------------------------|
| 데이터베이스 엔진     | DBMS의 종류를 말한다. MySQL, PostgreSQL, MariaDB, Amazon Aurora 등이 있다.                                                      |
| 워크로드              | 클라우드 환경인지, 게임/테스트 환경인지를 표명한다. 프로덕션 환경인 경우 다중 AZ가 기본으로 활성화되는 등 해당 환경에 관한 설정이 표시된다. |
| 라이선스 모델         | GPL을 포함하여 라이선스 모델이 여러 개인 경우는 선택한다.                                                                        |
| 데이터베이스 엔진 버전 | 버전이 여러 개인 경우는 선택한다.                                                                                               |

**데이터베이스 인스턴스 항목**

- 온프레미스 환경의 물리적인 서버로 예산과 관리되며 필요한 사양을 선택한다.

| 항목                       | 의미                                                                                                 |
|----------------------------|------------------------------------------------------------------------------------------------------|
| 인스턴스 클래스            | 데이터베이스 인스턴스의 사양이다. EC2와 같이 여러 인스턴스 클래스를 제공한다.                       |
| 다중 AZ 배포               | 두 개 이상의 AZ에 배포하여 이중화 구성 여부를 설정한다.                                             |
| 스토리지 유형              | 스토리지의 종류이다.                                                                                |
| 스토리지 할당              | 스토리지의 용량이다.                                                                                |
| 자동 스케일링              | 스토리지가 부족할 때 자동으로 늘릴지 여부를 설정한다.                                               |
| 스케일링 임계값            | 자동 스케일링의 임계값이다.                                                                         |
| 데이터베이스 클러스터 식별자 | AWS에서 데이터베이스 클러스터를 관리하기 위한 이름이다. 데이터베이스명이 아니므로 주의해야 한다.     |
| 마스터 사용자명            | 데이터베이스 인스턴스의 관리자 권한을 가진 사용자명이다. 임의로 설정한다.                           |
| 마스터 사용자 암호         | 데이터베이스 인스턴스의 관리자의 암호이다. 임의로 설정한다.                                         |

**네트워크 항목**

- VPC 설치 및 EC2 연동 시 서브넷 그룹 및 가용 영역과 보안그룹도 미리 생성

| 항목               | 의미                                                                                                                                                                                                                        |
|--------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| VPC                | RDS를 설치할 VPC이다. VPC의 생성은 VPC 대시보드에서 수행한다. 기존 VPC도 선택할 수 있다.                                                                                                                                   |
| 서브넷 그룹        | RDS를 설치할 서브넷 그룹이다. EC2 인스턴스와 연동할 경우 동일한 곳에 설치하는 것이 일반적이다(서비스 지연시간에 민감한 경우).                                                                                             |
| 퍼블릭 액세스 기능 | 데이터베이스 인스턴스에 공인 IP 주소를 할당할지 여부를 나타낸다. 기본 VPC 내의 서비스가 아닌 곳에서 데이터베이스에 직접 접속할 경우에는 이 기능을 활성화한다. 그러나 보안 관점에서 직접 RDS에 접속하는 방식보다는 VPC 내의 서비스가 위임받아 접근하는 방식을 선호한다. |
| 기존 보안 그룹     | RDS를 설치할 기존 보안 그룹이다. EC2 인스턴스와 연동할 경우 동일한 보안 그룹에 설치하는 것이 일반적이다(서비스 지연시간에 민감한 경우).                                                                                   |
| 보안 그룹          | 인스턴스 단계에서 변경하는 방법이다. 사용할 포트를 열기 위함이다. 이 단계에서 설정할 수 있지만 보안 그룹의 권한 범위가 크기 때문에 미리 만들어 두자. 설정하지 않아도 생성한다.                                            |

| 항목                     | 의미                                                                                                                    |
|--------------------------|-------------------------------------------------------------------------------------------------------------------------|
| 데이터베이스명           | 데이터베이스 이름이다.                                                                                                 |

| 데이터베이스 파라미터 그룹 | 환경 설정을 위한 옵션 설정이다. 대부분의 경우 기본 설정을 사용한다.                                                    |
| 옵션 그룹                | 추가 기능에 대한 설정이다. 대부분의 경우 기본 설정을 사용한다.                                                         |
| 암호화                   | 암호화 여부를 나타낸다. 인스턴스 종류에 따라서 사용할 수 있는 경우도 있다.                                             |

| 로그 내보내기            | Amazon CloudWatch Logs를 사용하여 로그를 출력한다.                                                                    |
| 유지 관리                | 자동 업데이트에 대한 방법과 시간대를 설정한다.                                                                         |
| 삭제 방지                | 삭제되지 않도록 보호 여부를 나타낸다.                                                                                  |

#### 7.4.3 사용 절차

**1. AWS에 로그인**

- 리전을 선택하고 관리 콘솔에 접속한다.
- RDS 대시보드에 접속한다.

### 7.5 Key-Value 데이터베이스

#### 7.5.1 Key-Value 데이터베이스 (KVS)

> **데이터의 형식에 관계없이 어떤 데이터에 대해 특정 키가 되는 값을 결합하여 저장하는 방식의 데이터베이스**

- NoSQL 데이터베이스의 대표적인 예제이다.
- Key: 데이터를 찾기 쉽게 하기 위한 라벨
- 형식에 구애받지 않고 저장이 가능하지만 상세하게 검색할 수 없다.
- 데이터의 액세스가 빠르기 때문에 빅데이터나 IoT 같은 대용량 데이터를 빠르게 처리하는 경우에도 사용 중이다.
- 스토리지 형식의 DynamoDB와 메모리에 저장하는 Amazon ElastiCache가 존재한다.

#### 7.5.2 DynamoDB

> **VPC가 불필요한 키 밸류 스토어 데이터베이스로 범용적 데이터를 저장하는 데 사용**

- Lambda 등과 같은 애플리케이션 환경과 궁합이 좋다.
- 대규모 데이터를 처리하기 때문에 ACID 트랜잭션, 데이터 암호화, 접근 제한 등의 서비스를 갖추고 있다.
- 글로벌 테이블로 생성 시 전 세계 각 리전에 분산되어 복제되며 자동으로 동기화된다.

#### 7.5.3 Amazon ElastiCache

> **인 메모리 데이터베이스**

- 데이터베이스 조작할 때마다 외부 기억장치에서 R/W를 진행하지 않고 캐시하는 방식으로 메모리를 활용하여 처리속도를 올린다.
- 인스턴스를 재시작할 때 데이터가 삭제되며 캐시 용도로 많이 사용된다.
- Redis용과 Memcached용이 존재하며 현재 사용 중인 애플리케이션을 변경하지 않아도 사용 가능하다.

### 7.6 다양한 DB

#### 7.6.1 그 외의 데이터베이스

- DocumentDB (문서 기반)
- Neptune (그래프)
- Timestream (시계열)
- Quantum Ledger Database (장부)

#### 7.6.2 Amazon DocumentDB

> **MongoDB를 이용하여 대규모의 데이터를 안정적으로 입출력할 수 있도록 설계된 데이터베이스**

**MongoDB**

- 오픈 소스의 문서 기반 데이터베이스로, JSON 형식을 바이너리로 변환하여 BSON 형식으로 데이터를 저장할 수 있다.
- 기본 MongoDB 드라이버와 도구를 사용할 수 있으며 예를 들어 AWS Database Migration Service를 사용하여 Amazon EC2에서 가동 중인 MongoDB 데이터베이스를 Amazon DocumentDB로 다운타임 없이 마이그레이션하는 것이 가능하다.

#### 7.6.3 Amazon Neptune

> **그래프 데이터베이스**

**그래프 데이터**

- 여러 가지 요소 사이의 관계 혹은 처리의 흐름을 나타내기 때문에 노드의 방향을 포함한 노드 사이의 연결을 기록한 데이터
- 대표적인 그래프 모델인 Property Graph와 W3C의 RDF에서 사용하는 쿼리 언어인 Apache TinkerPop Gremlin과 SPARQL을 지원한다.
- 관리가 자동화되어 있고 네트워크를 통한 데이터의 읽기/쓰기는 HTTPS로 암호화된다.
- 추천 시스템이나 소셜 네트워크, 지식 그래프(지식 기반의 발전된 형태로 정보를 축적할 뿐만 아니라 정보 간의 관련성을 가진 기술) 등에 사용되며 데이터 간의 복잡한 관계를 처리할 수 있다.

#### 7.6.4 Amazon Timestream

> **시간의 경과에 따른 사물의 변화를 기록한 데이터로 전형적인 IoT의 데이터 취득 형태를 저장하는 데이터베이스**

- 시간별로 취득한 데이터를 관계형 데이터베이스에 저장하는 것은 가능하지만 집약 및 집계 쿼리를 수행하기는 쉽지 않다.
- 쿼리 처리 엔진이 시간별로 처리하는 데 최적화되어 있으며 평활법, 근사, 보간 등의 분석 함수를 사용할 수 있다.
- 자원이 충돌하지 않도록 새로운 데이터를 삽입하고 기존 데이터의 쿼리를 다른 계층에서 처리한다.
- 필요에 따라 스케일링되기 때문에 용량이나 부하를 고려할 필요가 없다 → IoT 데이터 처리 성능 유지 및 데이터 관리 비용 절약이 가능하다.

#### 7.6.5 Amazon Quantum Ledger Database

> **데이터 변경을 추적하여 이력을 남기는 '저널 형식'을 채용한 장부 데이터베이스**

- 장부는 기업의 상거래 및 재무 기록뿐만 아니라 감사에도 필요하다.
- 관계형 데이터베이스는 감사에 필요한 '데이터 변경 내용의 추적 및 검증'에 대해서는 지원하지 않으므로 시간과 비용을 들여서 감사용 애플리케이션을 개발해야 한다.
- 저널 데이터는 변경, 삭제가 불가능하며 암호화 해시 함수(SHA-256)에서 변경한 내용을 변조하는 것을 방지하고 있다.
- 한편 SQL과 비슷한 API나 문서 기반 데이터 모델을 제공하며 조작은 쉬운 편이다.
