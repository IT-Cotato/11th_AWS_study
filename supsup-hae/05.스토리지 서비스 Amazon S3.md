## 5.1 Amazon S3

### 5.1.1 Amazon S3(Amazon Simple Storage Service)란

스마트한 객체 스토리지 서비스(데이터를 객체 단위로 관리하는 형식)
- 용량 제한이 없어 최소한의 용량으로 시작해도 되며 확장과 축소가 간단하고 사용한 만큼 지불하면 된다.
- 웹 서버 기능과 쿼리 기능 등 다양한 기능을 제공하며 간단하게 웹 서버를 구축할 수 있다.

### 5.1.2 견고하고 스마트한 스토리지 서비스

**확장성**
- EC2와 마찬가지로 확장, 축소가 쉽다.
- 사용 목적에 맞게 다양한 스토리지 클래스가 준비되어 있고 수명 주기 정책을 사용하여 자동으로 이동이 가능하다.

**가용성·내구성**
- 99.999999999%의 데이터 내구성을 가지고 있어 장애나 오류, 위협에 강하다.
- S3 객체는 최소 4개의 가용 영역에 자동으로 복제되어 보존되기 때문에 어느 한쪽에 장애가 발생하더라도 계속 사용할 수 있다.

**신뢰성**
- 암호화 기능과 접근 관리 도구가 있어 공격으로부터 지키기 쉽다.
- 각종 규정을 준수하며 감사 기능을 갖추고 있다.

**다양한 관리 기능**
- 스토리지 클래스 분석, 수명 주기 정책 등 각종 관리 기능이 있다.
- 관리 기능을 활용해 설계 시점 혹은 사용 중에도 스토리지 클래스를 변경하는 것이 가능하다.

**스마트한 기능**
- S3 Select라는 데이터에 쿼리를 실행하는 기능과 서비스가 있다.
- Amazon Athena, Amazon Redshift Spectrum 등의 분석 서비스와 호환되고, AWS Lambda와 연동할 수 있다.

### 5.1.3 요금 체계

보유하고 있는 저장 용량(데이터를 저장한 양에 따라 과금) + 전송량(데이터를 주고받은 전송량에 따라 과금)

1. S3에 저장된 용량에 대한 비용
    - 스토리지 클래스에 따라 일별/단위로 나눠서 계산하는 경우와 30일, 90일, 180일 단위로 계산하는 경우 등 방식이 다르다.
    - 스토리지 클래스에 따라 최소 용량 요금이 설정되어 있어서 이 크기보다 작은 파일인 경우도 올리면 요금이 부과된다.
2. S3에서 파일을 받거나 보낼 때 발생하는 요금
    - 수신 요청(GET)이나 송신 요청(PUT)에 대해서 1GB 단위로 과금된다.

### 5.1.4 전송량에 대한 개념

1. 수신 요청과 다운로드 (GET): 특정 파일이 필요 - 서버에서 다운로드
2. 송신 요청과 업데이트 (UPDATE): 특정 파일을 저장 - 파일 업로드

## 5.2 스토리지 클래스

- S3에서 사용할 수 있는 스토리지 종류
- 사용자 목적에 따라 다양한 종류의 클래스를 선택 가능
- 버킷 단위가 아닌 객체 단위로 클래스를 선택 가능
- 상황에 따라 주기적으로 변경이 가능하며 수동으로 지정해야 한다(수명 주기 정책 사용 시 자동으로 수행)

### 종류

1. **Standard**
    - 가장 일반적인 스토리지 클래스
    - 3곳 이상의 AZ(가용 영역)에 데이터가 저장되어 있기 때문에 99.9%의 가용성을 보장
    - 데이터를 검색할 때의 요금과 최소 용량의 요금이 없고 일일로 계산되므로 쉽게 사용하기에 좋은 클래스
2. **Intelligent-Tiering**
    - 빈번한 액세스와 간헐적 액세스에 최적화한 두 가지 계층에 객체(파일)를 저장
    - 객체별로 모니터링하여 자동으로 이동
    - 검색 요금이 없으나, 액세스 계층 이동에 대한 모니터링 요금이 발생
    - 액세스 빈도가 자주 바뀌는 경우 비용 절감 효과
    - 최소 저장 기간에 대한 요금이 설정되어 있으므로 주의 필요
3. **Infrequent Access**
    - Standard 클래스에 비해 저장 요금이 낮고, 액세스 요금이 조금 높다
    - 액세스 빈도가 낮고 용량이 큰 데이터에 적합
    - Standard-Infrequent Access와 One Zone-Infrequent Access는 저장에 사용하는 AZ의 수가 다름
    - One Zone은 단일 AZ로 저장 영역이 하나이기 때문에 데이터 유실 위험 존재, 대신 가격이 저렴
4. **Reduced Redundancy Storage**
    - 중복성을 줄여서 저장하는 클래스 - 내구성이 99.99%로 낮지만, 비용이 저렴
5. **S3 Glacier/S3 Glacier Deep Archive**
    - 데이터 아카이브와 장기간 백업을 위한 스토리지 클래스
    - 99.999999999%의 내구성, 가격이 낮아 대량 데이터 보관에 적합
    - 데이터는 '블록'이라는 컨테이너에 저장, 읽어올 때 시간이 오래 걸림
    - S3 Glacier와 Glacier Deep Archive를 목적에 따라 구분해 사용

## 5.3 S3 사용 절차

### 5.3.1 S3 조작

- 관리 콘솔의 S3 대시보드를 이용하여 설정, 관리, 업로드가 가능
- API, SDK를 사용하여 편리한 업로드가 가능하다
- AWS Transfer for SFTP가 제공되어 해당 프로토콜을 통한 액세스가 가능

### 5.3.2 S3 기능

| 항목             | 내용                                                         |
|------------------|--------------------------------------------------------------|
| 객체             | 텍스트, 이미지 등 파일 형태의 엔터티 단위                     |
| 버킷             | 객체를 저장하는 컨테이너                                     |
| 리전             | S3 버킷 이름은 전 세계적으로 유일, 객체 사용 시 도메인명 할당 |
| 객체 키          | 객체 식별자, 버킷과 객체 키, 버전이 결합해 고유 식별           |
| 객체 메타데이터  | 이름과 값의 쌍, 파일 크기·마지막 업데이트 일자 등 정보 포함   |
| 버전             | 버킷의 물리적 보관 위치                                      |
| 데이터 일관성 모델 | S3는 데이터를 자동 복제해 저장, 복제·동기화에 시간 소요될 수 있음 |
| 버전 관리        | 여러 버전을 별도 객체로 관리 가능                            |
| 로그             | 버킷·객체 단위의 로그 기록, 객체 수준 로그는 유료             |
| 암호화           | 저장되는 데이터 자동 암호화                                  |
| 액세스 제어      | 버킷별 권한 설정 가능                                        |
| 웹 서비스        | S3 버킷을 웹사이트로 활용 가능                               |

### 5.3.3 S3 사용 절차

1. AWS에 로그인 (관리 콘솔 - S3 대시보드)
2. 버킷을 만든다 (버킷명 설정)
3. 버킷을 설정
    - 웹 서버로 사용할 경우 Static website hosting 설정
    - 접근할 수 있는 사용자 설정
4. 파일을 업로드 (관리 콘솔이나 전용 도구에서 파일 업로드)

### 5.3.4 생성 전 검토

| 웹 사이트로 사용할지 여부 | 소유한 도메인을 사용할지 여부 | 파일 서버인지 로그 저장소인지 |
|--------------------------|-----------------------------|-----------------------------|
| yes                      | yes                         |                             |
| no                       |                             |                             |

- 버킷명을 도메인명과 똑같이 해야 함
- 하고 싶은 이름을 써도 되지만 도메인명의 일부는 호스트명이 되므로 주의
- 익명 접속을 허가한다면 사용법에 맞게 도구나 SFTP를 준비, 접속 가능한 사용자를 관리
- 생성 이후 이름과 리전을 변경할 수 없다
- 용도를 확정하고 클래스를 선정해야 한다
    - 웹서버: 버킷에 대한 공개, 도메인, 익명 접속 허가 등 고려, 테스트 버킷 활용 후 생성
    - 외부 노출이 불가한 경우 주의 필요

## 5.4 객체와 버킷

- 객체: 파일 | 버킷: 드라이브
- 버킷은 폴더가 아니기 때문에 버킷 내부 버킷 생성 불가, 계정당 100개(별도 신청 시 1000개)
- 파일은 관리를 위한 메타데이터 포함(버킷 내부 파일 개수 제한 없음)
- 객체는 버킷에 병렬로 배치, 관리 콘솔에서는 폴더로 표시(CRUD 가능)

### 버킷 생성과 명명 규칙

- 버킷명은 처음과 마지막에 알파벳이나 숫자를 사용해야 함
- 3글자 이상 63글자 이하
- DNS 명명 규칙을 따라야 함
- IP 주소 형식, 대문자, 언더스코어는 버킷명으로 쓸 수 없음
- S3 안에서 유일한 이름이어야 함
- 리전을 변경해도 같은 버킷 명으로 생성 불가

## 5.5 버킷 정책과 사용자 정책 : 액세스 제한 설정

### 5.5.1 버킷에 대한 액세스 제한

- 버킷 정책: 해당 버킷에 접속할 수 있는 사용자 지정
- 사용자 정책: 접속 가능한 버킷을 지정
- ACL(액세스 제어 목록): 자신 외의 다른 AWS 계정의 R/W 권한 설정 목록

### 5.5.2 액세스 제한의 대상과 내용

| 항목     | 내용                                              |
|----------|---------------------------------------------------|
| 리소스   | 제한 대상이 되는 버킷 및 객체, 아마존 리소스 이름으로 대상을 식별 |
| 작업     | 실제로 가능한 작업, GET(취득), PUT(배치), DELETE(삭제) 등, 작업 키워드로 지정 |
| 효과     | 설정 여부, 허가(allow), 거부(deny)로 설정         |
| 보안 주체 | 허가 혹은 거부할 사용자, 계정, 서비스 등           |

- 누가, 무엇을, 어떤 것에 대해 가능한가 여부를 정하는 기능

## 5.6 웹 사이트 호스팅

### 5.6.1 웹 사이트 호스팅이란

- 파일 서버로 사용
- 웹 서버로 사용
- 서버가 스크립트를 처리하지 않는 정적 웹 사이트 호스팅이 가능(단순 HTML, Image)
- 버킷을 단순 웹사이트로 오픈

### 5.6.2 필요한 설정

- 정적 웹 호스팅 활성화
- 퍼블릭 액세스 차단 해제
- 버킷 정책: 모든 사용자
- 버킷명 = 도메인명
- 개인 도메인 소지 시 Route 53 등 DNS 서비스 설정

### 5.6.3 다른 서비스와 차이점

| 서비스   | 서버 프로그램 실행 | 확장성 |
|----------|-------------------|--------|
| EC2      | ○                 | △      |
| S3       | X                 | ○      |
| Lightsail| ○                 | △      |
| Amplify  | ○(독자적 프로그램)| ○      |

- LightSail: 필요한 기능을 선택하면 웹 사이트에 필요한 서비스 전체를 정해진 가격으로 구축할 수 있는 서비스
    - EC2에서 여러 설정과 프로그램을 하나의 패키지로 제공
    - CPU나 메모리, 대수를 변경할 수 있는 유연성은 없음
    - 변경 시 스냅샷을 이용해 백업 후 새로운 LightSail을 계약, 백업에서 복원
- Amplify: 모바일 앱이나 웹 앱을 개발하기 위한 프레임워크, 자바스크립트로 다양한 기능을 호출하여 시스템 구축
    - HTML 파일, S3를 통해 배포 또는 Lambda 기능을 통한 백엔드 프로그램 실행
- 각 서비스별로 실행 여부와 확장성에 따른 차이점 존재
    - 프로그램을 쓰지 않는다면 S3가 적합

## 5.7 파일 업로드와 다운로드

### 5.7.1 업로드와 다운로드

> **관리 콘솔(드래그 앤 드롭(Chrome, Firefox) | 마우스 클릭으로 지원), CLI, API, SDK**

### 5.7.2 다양한 업로드 방법

1. **API | SDK**
    - Third Party 도구를 활용하여 파일을 업로드
    - IAM 사용자에게 액세스키와 보안 액세스 키를 발행하여 사용하고 싶은 도구에 설정

2. **MultiPart Upload**
    - 객체를 여러 개로 나누어 세트 하나로 업로드 가능 (업로드 중 부분별 표시, 완료 시에는 객체 하나가 된다)
    - 부분 실패 시 재전송 진행 | 일시 중지 가능 (종료 기간 X)
    - 100MB 이상의 파일은 파일 업로드를 사용하는 것을 추천 → 해당 기능 사용 시 별도의 요금이 발생하지 않는다.
    - 관리 콘솔 CLI에서는 큰 파일은 자동으로 해당 업로드 방식을 따른다.

3. **AWS Transfer for SFTP**
    - SFTP 서버 엔드포인트를 사용하여 파일을 전송할 수 있는 서비스 (서버 제공)
    - 초기 비용 X + 서버 사용 시간 * 데이터 전송량에 의해 과금 진행

4. **AWS DataSync**
    - 온프레미스 스토리지 시스템 - AWS 스토리지 서비스 간 대용량 데이터 전송을 위한 서비스
    - 복사하는 데이터 양에 따라 요금이 발생

5. **하이브리드 클라우드 스토리지 서비스**

### 대규모 데이터 송신

> **PB, EB 단위처럼 대규모 데이터를 업로드하는 것은 난이도가 높다**

- 물리적인 방법으로 AWS Snowball(HDD 이용 전송), AWS Snowball Edge(데이터 가공 처리), SnowMobile

### 공용 액세스 차단

> **버킷 단위로 모든 사용자에게 액세스를 허가할지 결정하는 기능**

- 각 액세스 제한보다 상위에 있는 제한으로 버킷 정책이나 사용자 정책이 모든 사용자에 대해서 액세스가 가능하도록 허가해도 사용 불가능

## 5.8 액세스 관리 및 변조 방지

### 5.8.1 액세스 로그

> **서버에 어떤 요청이 있었는지 기록하는 기능 (버킷 소유자, 버킷명, 요청자, 총 시간, 응답 시간, 작업, 응답 상태, 오류, 코드)**

- S3 기능으로 액세스 로그 기록 제공 (기능 사용에 대한 요금을 부과하지 않지만 보관에 대한 요금은 발생한다)
- 원격 IP, 요청자, 요청 ID, 작업, 키, 요청 URI, 오류코드, 보낸 바이트, 객체 크기, 총 시간, 반환 시간, Referrer, 사용자 에이전트, 버전 ID, 호스트 헤더

### 5.8.3 그 외 액세스 관리

#### 스토리지 클래스 분석

> **객체에 액세스 빈도를 분석**

- 빈도가 낮은 데이터는 S3 Intelligent-Tiering으로 이동하는 판단 자료로 사용
- 객체는 설정된 날짜별로 어느 정도 그룹화되어 있어 각 그룹의 평균 전송 바이트 수를 감시 (필터링도 가능 - 1000개)

#### 객체 잠금

> **객체에 대한 변경 허용 X → 객체의 삭제, 덮어쓰기 변조 방지 가능**

- 유효 기능이 존재 - 법적 유효가 필요한 경우 무제한으로 보관이 가능하다
- 잠금 시 CRR로 복사할 수 없다
- 거버넌스 모드: 특정 사용자에게만 객체 변경 허가
- 규정 준수 모드: 모든 사용자가 객체를 변경할 수 없다 (root 사용자도 불가능)

## 5.9 버전 관리 수명 주기 복제

### 5.9.1 버전 관리

> **객체를 여러 번 저장하는 기능으로 버킷 단위로 설정**

- 실수로 변경, 삭제한 파일을 복원할 수 있다 → 이전 버전의 객체를 버킷에 그대로 복사
- 미사용(기본), 활성화, 버전 일시 중지 상태가 존재

### 5.9.2 수명 주기 정책

> **객체가 정기적으로 수행할 작업을 설정하는 기능**

- **Transition**: 객체를 다른 스토리지로 이동
- **Expiration**: 유효 기간이 만료된 객체를 삭제 (최신 버전만 삭제, 버전이 여러 개 있으며 삭제 표시가 있는 경우 삭제 X)
- **NoncurrentVersionTransition**: 현재 스토리지 클래스에서 객체의 유지 시간 지정
- **NoncurrentVersionExpiration**: 과거 버전의 객체를 삭제하기 전에 유지 시간을 지정
- **AbortIncompleteMulitipartUpload**: 멀티파트 업로드 진행 상태를 유지할 최대 시간을 지정
- **ExpiredObjectDeleteMarker**: 만료된 객체 삭제 표시를 제거

### 5.9.3 교차 리전 복제

> **다른 리전의 버킷에 객체를 비동기적으로 복사하는 것**

- 복사 대상 버킷은 소유자가 동일하지 않아도 괜찮지만, IAM 역할을 부여해야 한다
- 두 버킷 모두 버전 관리가 활성화되어 있어야 하며 같은 리전에 버킷에 적용 불가능
- 백업본을 만들 경우 유용하게 사용된다 (해외로 반출되어서는 안 되는 내용을 포함하면 안 된다)

## 5.10 데이터 분석과 연계

### 데이터의 분석과 연동

#### S3 Select, Amazon Athena

> **CSV, JSON과 같이 구조화된 텍스트 형식의 데이터를 SQL SELECT 문으로 실행 (서버는 필요하지 않다)**

#### Amazon Redshift Spectrum

> **대용량의 데이터를 처리하기 때문에 Redshift cluster가 필요 (데이터웨어하우스를 제공하는 서비스)**

### 데이터 분석 서비스

#### S3 SELECT

> **S3로 저장된 데이터 파일 하나에 SQL문을 사용하여 집계 및 검색이 가능한 기능 (CSV, JSON, Apache Parquet)**

- 집계는 관리 콘솔에서 가능, CLI, SDK를 지원하며 복잡한 쿼리는 프로그램을 만들어 실행 가능

#### Amazon Athena, Amazon Redshift Spectrum

> **데이터 분석 서비스로 어떤 대상에 대해 어떤 검색을 해야 할지 사전에 구성해야 한다**

- **Athena**: 필요 시 분석용 서버를 자동으로 생성하여 실행 (실행 시에만 요금이 발생)
    - 집계나 검색 방법 저장이 가능해서 반복 작업에 특성화
- **Redshift Spectrum**: 미리 분석용 서버를 시작하고 시행
    - 처리 능력에 따라 서버를 선택 가능하며 분산 처리 가능 (대용량 복잡한 데이터 최적화)
    - 다양한 기준으로 데이터를 분석, 예측 가능

## Amazon CloudFront

### Amazon CloudFront

> **고속 콘텐츠 전송 네트워크(CDN) 서비스로 웹 콘텐츠를 빠르게 전송하는 것에 특화**

- S3 웹사이트 호스팅 기능으로 구축한 웹 서버와 조합하여 많이 사용
- 웹 서버의 내용을 캐시하는 엣지 서버를 사용 → 사용자 요청에 대한 웹 서버의 부담을 줄인다
- 각 리전의 네트워크 말단에 위치하여 클라이언트와 접속하는 네트워크 거리가 가까워 반응 속도가 빨라진다

### 요금 체계

> **사이트 접속자의 요청이나 접속자에게 페이지 전송, 접속자가 업로드한 파일의 전송 등**

- 원본 데이터를 캐시하기 위한 전송량을 요금 부과 X (캐시는 요금이 부과된다)
- HTTP, HTTPS에 따라 요금 체계가 다르다
- 요청 1만 건 단위 | 전송량(GB) 단위 | 캐시 삭제는 1000건까지 무료

### 요금 계층

> **선택한 요금 계층이 포함된 지역의 엣지 서버에서 콘텐츠가 전송 (대한민국은 200, 전체)**
