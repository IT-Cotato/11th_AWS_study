## 3. AWS를 사용하기 위한 도구

### 1. 사용법과 계정

#### 기본 개념

> **AWS는 클라우드 서비스이기 때문에 사용한 만큼 비용을 지불한다**

1. 자신에게 최적화된 상태로 관리한다 → 필요한 것을 필요한 만큼 사용하기.
2. 서비스를 종합적으로 제공하기 때문에 운영 방법과 상황에 따라 지출 비용이 변화하므로 적절히 선택.

#### 종합적인 관리

> **제공하는 서비스가 많기 때문에 이를 종합적으로 관리할 수 있는 기능을 제공**

- 서버 엔지니어 등 전문가가 없어도 운영할 수 있는 유저 환경 제공.
- 단순히 PC에서 로그인하는 것만으로 누구든지 사용 가능.

**대표 서비스**

- **관리 콘솔**: 서비스 설정 화면 → 웹 브라우저 이용.
- **CLI**: 명령줄 도구 → 관리 콘솔에서 할 수 없는 것도 조작 가능.
- **IAM**: 서비스를 이용하기 위한 사용자 계정 → 그룹, 정책으로 일괄 관리 가능.
- **비용 관리**: 비용을 그래프로 확인 가능하며 예산에 따라 관리 가능.
- **CloudWatch**: 감시 도구 → 지정한 임계값을 넘을 경우 조치 가능.

#### AWS 계정

> **AWS를 사용하기 위한 계정 ← 이메일 주소, 암호, 연락처, 신용카드 등록**

- 계정 구분: 하나의 계정에서 여러 프로젝트의 서버나 스토리지 임대 시 비용이 모호해지고 관리도 복잡해진다.
    - 해결하기 위해 프로젝트나 비용을 관리하는 단위로 AWS 계정을 분리한다.
    - 기업 사용자: 규모가 큰 단체가 사용하기 용이하며 관리하는 서비스가 많아진다.

#### root 사용자

> **AWS 계정으로 모든 조작이 가능한 관리자 권한을 가진다**

- 편리하지만 치명적인 보안 문제가 발생할 수 있기 때문에 IAM으로 서비스를 사용하는 사용자를 별도로 관리.

#### 서비스의 개인 최적화

> **언제든지 가동시키거나 중지시킬 수 있다**

- 서비스 한 개에 여러 옵션이 존재하여 성능과 상황에 따라 용이한 서비스 설정을 적용할 수 있다.

### 2. 관리 콘솔과 대시보드

#### 관리 콘솔

> **웹 브라우저에서 AWS 서비스를 관리하는 화면 (사용자 환경)**

- 서비스별 대시보드, 설정, 리전 선택, 계정 관리, 필요한 리소스 그룹 검색 및 사용, AWS 문서 참조.
- 대부분의 서비스는 한국어를 지원하며 모바일 앱도 존재한다.

#### 리전 선택

> **리전별로 같은 서비스여도 구분된다**

> **리전에 따라서 사용할 수 없는 서비스가 존재하기도 한다**

- 관리 콘솔은 지역을 대표하는 리전 단위로 조작한다.
- 우측 상단의 리전 선택 항목을 이용해서 리전을 변경할 수 있다.

#### 대시보드

> **서비스를 조작할 수 있는 메인 화면으로 서비스의 시작 및 종료, 각종 설정과 상태 표시를 제공**

**AWS CLI?**

- 로컬 명령어 단말기 혹은 서버에서 명령어 스크립트로 서비스를 빠르게 수행하기 위한 CLI.
- 스크립트 작성으로 여러 가지 조작을 한 번에 실행하며 자동화 및 프로그램화 진행 시 관리 콘솔보다 편리하다.
- Python - pip을 사용하여 설치하며 `aws` 명령어를 사용하여 CLI를 조작한다.
- `aws configure`에서 인증 정보를 설정한다.
- EC2 조작 및 S3 파일 백업 등의 기능을 수행할 수 있다.

### 3. IAM과 접근 권한

#### IAM(Identity and Access Management)

> **AWS의 인증 기능으로 각 서비스에 대한 접속을 관리하는 기능으로 AWS 계정에 제공되는 무료 기능**

- IAM 사용자: 사람에게 부여하는 IAM.
- IAM 역할: 서비스나 프로그램 등에 부여하는 IAM.
- MFA(Multi-Factor Authentication)를 사용하는 것을 권장한다.

#### 그룹과 정책

> **IAM 사용자 및 역할은 필요한 최소한의 기능만 부여하고 필요한 사람에게만 전달하여 운영해야 한다**

- IAM 그룹: 사용자를 그룹화하여 같은 권한을 부여하며 일괄적으로 관리 가능하다.
- IAM 정책: 실행자가 어떤 서비스에 접속할 수 있는지를 설정한다.
    - 권한 설정 변경 시 정책만 변경하면 같은 그룹 내 사용자가 일괄적으로 권한 설정이 변경된다.
    - 한 그룹에 여러 개의 정책을 설정할 수 있다.

#### 정책 설정

1. 자격 기반 정책: 실행자(사용자, 역할, 그룹)가 어떤 일을 할 수 있는지를 설정한다.
2. 리소스 기반 정책: 조작 대상(서버 및 폴더)에 대해 무엇을 허가할 것인지 설정한다.
3. 고객 관리형 정책: 사용자가 자기만의 정책을 생성하는 것 → 실수할 가능성 있음.
4. AWS 관리 정책: 사전에 준비되어 있는 정책으로 대부분의 사용자 채택.
    - 해당 정책과 다른 부분만 고객 관리형 정책으로 조합하여 사용하는 것이 좋다.

**주요 설정 항목**

- Statement(설정 값 - 대상), Sid(정책 문서 식별자), Effect(사용 여부), Action(허가 혹은 거부하는 특정 작업).
- NotAction(지정한 동작 명령 제외 모든 것), Resource(작업 대상), NotResource(작업 대상 제외 모든 것).
- Condition(정책 실행 타이밍 조건).

### 4. 리소스 상태 감시

#### Amazon CloudWatch

> **AWS 서비스의 리소스 모니터링과 관리를 담당하는 서비스**

- 각 서비스에서 지표와 로그를 수집 및 기록하여 임계값이 넘으면 특정 동작이 일어나도록 설정 가능 → 대처 가능.
    - 이메일 송신, EC2 재조정(Auto Scaling), Lambda 함수 사용 등의 조작 수행 가능.
- 사용한 만큼만 지불하며 지원하지 않는 서비스도 존재한다.
- CPU 사용률, Volume 읽기/쓰기 횟수나 바이트 수, 네트워크 송수신 패킷 수 등 감시 가능하다.

#### Amazon CloudWatch Logs

> **서비스의 각종 로그를 종합하여 기록**

1. 일정 기간 동안 삭제하거나 S3에 저장하는 형식으로 사용 가능하다.
2. CloudTrail: 감사 서비스로 누가 어떤 리소스에 접속했는지 기록으로 남길 수 있다.

### 5. 비용 관리

#### AWS Billing and Cost Management

> **AWS 요금을 관리해주는 서비스로 요금 납부, 사용료 모니터링, 비용 및 사용 현황 보고 등을 사용할 수 있으며 서비스 해지가 가능하다**

1. 청구서: 매월 청구서 및 사용하고 있는 AWS 서비스 상세 내역 확인 가능하다.
2. 요금 대시보드: 지출 현황과 비용 경향 등을 확인 가능하다.
3. AWS Cost Explorer: 시간에 따른 비용과 사용량을 가시화하고 파악 및 관리 가능하다.
    - 월별/일별/서비스별 그래프로 표시되어 직관적으로 파악 가능하다.

4. AWS Budgets: 비용 및 사용량에 지정 예산을 설정하여 특정 조건 시 알림 발송 가능하다.
    - 예산 포트폴리오 업데이트를 받을 수 있다.

5. 비용 및 사용 보고서: 비용과 사용량에 대한 가장 자세한 데이터를 열람 가능하다.
    - 하루 1회 CSV 형태로 S3 버킷에 저장되며 Athena/Redshift/QuickSight 등 집계·통계 도구로 보내기 가능하다.

#### 비용 관리 요령

1. **선택이 적절한가?**
    - 자신에게 어떤 서비스가 바람직한지 확인해야 한다 → 웹 서비스는 S3 | EC2를 이용하는 방법이 있다.
    - 새롭게 출시되는 서비스를 메모해두고 적극적으로 활용해야 한다.
    - 서비스에서 제공하는 옵션을 이용하여 모델을 유동적으로 변경하자.

2. **운영이 적절한가?**
    - 실제로 사용하지 않는 서비스를 유지하여 비용이 발생할 수 있으므로 이를 파악해야 한다.
