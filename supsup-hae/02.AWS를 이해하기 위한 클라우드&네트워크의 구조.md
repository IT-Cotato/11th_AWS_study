## 1. 클라우드와 온프레미스: 클라우드 컴퓨팅 구조

### 클라우드

![image](https://github.com/user-attachments/assets/a96c6c28-dbc6-4e3d-bdfa-ceccc6fbacfb)
> **언제, 어디서든 인터넷을 통해 접속이 가능한 환경**

- Office 365, 파일 스토리지 서비스, 음악 배포 서비스, 동영상 저장 서비스 등.
- 인터넷 상 설치된 소프트웨어, 동영상, 음악 등의 자원을 이용하며 클라우드에 저장이 가능합니다.
- 스스로 만들 수 있고, 빌릴 수 있으며 사업자가 제공하는 서비스를 이용할 수 있습니다.

### 클라우드 컴퓨팅 (== 클라우드)

> **클라우드에 구축된 인프라를 활용하는 서비스나 이를 사용하는 것**

- AWS, Azure, Google Cloud Platform, CloudXper 등.
- 가상화 기술을 사용하여 시간적, 공간적 제약 없이 서버나 인프라를 구축하여 운영할 수 있습니다 → 서버와 인프라 대여가 주류를 이룹니다.

### 온프레미스 (on-premises)
![image](https://github.com/user-attachments/assets/5c8e428b-a396-487f-8b83-1224620097e7)

> **자사가 서버를 구축하는 것으로 네트워크나 장소를 임대하는 경우에 해당합니다. *(데이터 센터에 서버를 두기만 해도 온프레미스입니다.)***

- **장점**: 자사에서 자유롭게 설계 및 운영 가능.
- **단점**: 서버 구성의 빈번한 변경 가능성이 높고 숙련된 기술자가 필요합니다.
- **오프프레미스 (off-premises)**: 온프레미스의 반대말로 자사가 소유 및 운영하지 않고 임대하거나 공공장소에 구축된 것을 사용합니다.

### 공용 / 사설
![image](https://github.com/user-attachments/assets/4c16719e-3bcd-4647-9c57-eaf00214c898)

- **공용 클라우드**: AWS와 같이 임대하는 클라우드.
- **사설 클라우드**: 자사에서 구축하는 클라우드.
    - 클라우드는 인터넷으로 사용할 수 있는 IT 자산으로 꼭 임대할 필요는 없습니다. 경우에 따라 사설 클라우드를 운영하기도 합니다.
- **온프레미스 → 클라우드**: 자사 운영에서 임대로 전환하거나 비클라우드에서 클라우드로 전환.

## 2. 가상화와 분산 처리


### 가상화
![image](https://github.com/user-attachments/assets/c440e60f-5996-4905-972e-c5d2157c57af)

> **메모리, 하드디스크, OS 등의 컴퓨터 작업을 위한 부품을 소프트웨어로 대체하는 기술**

- **가상 서버**: 물리 서버 1대 위에 게스트가 되는 서버를 여러 대 가상으로 생성.
- **가상 네트워크**: 물리적 배선 1개를 가상으로 분할하여 다른 네트워크와 통합하거나 연결 변경.

### 가상화를 이용한 복제
![image](https://github.com/user-attachments/assets/ac7b9546-1d69-4beb-a2f0-4b079e732603)

> 가상 서버에 할당된 메모리와 스토리지는 유동적으로 늘리거나 줄일 수 있습니다 → 유연한 서버 성능 조절 가능. 하지만 한계 존재.

- 물리적 서버는 성능 개선을 위해 서버를 추가해야 하지만, 가상 서버는 그러지 않아도 됩니다.

### 분산 처리와 로드 밸런서
![image](https://github.com/user-attachments/assets/dfbf69ab-a106-4194-9ffb-e0aa8bfb1d35)

> **분산 처리**: 기기 여러 대에 분산하여 처리하는 방법.

- 웹사이트에서 많이 이용되는 방식.
- 트래픽이 몰리는 경우 이를 서버에 분배하여 서버가 다운되는 것을 막습니다.

> **로드 밸런서**: 부하를 여러 대의 서버에 분배하는 장치 (ELB - Elastic Load Balancing).

### 이중화
![image](https://github.com/user-attachments/assets/5e049ea3-06ab-40be-a430-7d069c85869b)

> 시스템이나 서버에 문제가 생겨도 계속 가동할 수 있도록 조치하는 것 → 백업 또는 여러 대의 서버 운영.

## 3. 클라우드 서비스 제공 형태
![image](https://github.com/user-attachments/assets/a14d43e1-9585-46bb-beac-fd98b26f849a)


### SaaS (Software as a Service)

> 인프라나 플랫폼, 애플리케이션까지 제공 → SNS, Blog, Web Mail, Dropbox 등.

- 편리하지만 자유도가 낮습니다.
- 바로 사용 가능하기 때문에 작업량이 적습니다.
- 특별한 지식이 필요 없습니다.
- 단말기 외 준비해야 할 것이 없습니다.

### PaaS (Platform as a Service)

> 플랫폼까지 제공하며 사용자가 별도의 애플리케이션을 설치해야 하는 임대 서버 형태.

- 대응하지 않는 애플리케이션도 존재합니다.
- 서버 관리에 관한 지식이 필요합니다.
- 경우에 따라 애플리케이션을 준비해야 할 필요가 있습니다.

### IaaS (Infrastructure as a Service)

> 인프라만 제공하며 네트워크나 서버 머신을 제공합니다.

- 세팅이 필요하며 서버 관리 지식이 요구됩니다.
- 경우에 따라 애플리케이션을 준비해야 할 필요가 있습니다.

### Essa (Everything as a Service)

> 네트워크 통신부터 소프트웨어까지 제공하는 서비스로 AWS가 이에 해당합니다.

## 4. 서버와 인스턴스

### 서버
![image](https://github.com/user-attachments/assets/3a0c092d-4929-4108-a685-dfa6184e5c85)

> **서비스를 제공하는 것 → Amazon EC2(Elastic Compute Cloud): 서버를 임대하는 서비스**

- 기능은 소프트웨어로 제공되며, OS가 동작하고 소프트웨어가 실행됩니다.
- 특정 용도의 소프트웨어를 설치하면 해당 용도의 서버를 생성할 수 있습니다.
- 컴퓨터 자체도 "서버"로 불립니다.

### 다중 서버
![image](https://github.com/user-attachments/assets/f2ef4e57-d8e2-409a-a15f-c9c0d1332474)

> **소프트웨어를 여러 개 설치하여 여러 대의 OO서버를 사용하는 것도 가능**

- 기능 개수의 제한은 없지만 성능 저하 및 장애 발생 시 모든 기능이 정지할 수 있는 문제점이 있어 많이 사용하지 않습니다.

### 종류

1. **웹 서버**
    - 웹사이트 기능을 제공하며 HTML 파일, 이미지 파일 등을 저장하고 콘텐츠를 제공합니다.
    - 대표적인 소프트웨어: Apache, Nginx, IIS 등.
2. **메일 서버**
    - 메일 송수신을 담당하며 SMTP, POP, IMAP 등을 지원합니다.
    - 대표적인 소프트웨어: Sendmail, Postfix 등.
3. **데이터베이스 서버**
    - 데이터를 저장하고 검색하며 MySQL, PostgreSQL 등이 대표적입니다.
4. **파일 서버**
    - 파일 저장 및 공유용으로 Samba 등이 사용됩니다.
5. **DNS 서버**
    - IP 주소와 도메인을 변환하는 기능을 제공합니다.
6. **DHCP 서버**
    - IP 주소 자동 할당 기능을 제공합니다.
7. **FTP 서버**
    - FTP 프로토콜로 파일 송수신을 담당합니다.
8. **프록시 서버**
    - 외부 인터넷과의 중개 역할을 수행합니다.
9. **인증 서버**
    - 사용자 신원 확인 및 네트워크 인증 역할을 합니다.

### 필수 요소

- 서버 기능을 설치하는 컴퓨터는 특별하지 않으며, 역할이 다를 뿐 기계가 다른 것은 아니다.
- 서버용으로 사용하기 쉽게 구성되어 있으며, 24시간 작동을 기반으로 하기 때문에 불필요한 기능이 생략되고 고장이 적은 제품이 사용된다.

1. **CPU**
   - PC의 두뇌라고 할 수 있는 부품으로 제어·연산 등의 처리를 한다.
   - 프로그램 실행은 CPU가 담당한다.

2. **메모리(메인 메모리)**
   - 임시적인 기억 장치로 CPU에는 기억 장치가 없기 때문에 프로그램을 실행할 때 데이터를 저장 장소로 사용한다.
   - 사용자가 입력한 데이터, 파일 읽기, 네트워크 통신 읽기 등을 처리한다.

3. **메인보드**
   - 전자 회로 기판으로 CPU 및 메모리, 스토리지를 연결한다.

4. **스토리지**
   - 보조 기억 장치로, HDD나 SSD 등이 있다.
   - 메모리에 저장된 내용을 전원이 꺼져도 지워지지 않게 영구적으로 남기고 싶은 데이터를 스토리지에 저장한다.

5. **OS**
   - 컴퓨터를 움직이기 위한 시스템으로 하드웨어와 OS 위에서 동작하는 소프트웨어 사이에서 중간 역할을 한다.


### 서버용 OS
![image](https://github.com/user-attachments/assets/59cdec7a-0f83-4d52-8bea-e1c34005ef70)


- UNIX(Linux, BSD), Windows로 나뉜다.
- 클라이언트용 OS에 비해 종류가 많고, 오픈소스의 특성상 UNIX는 종류가 다양하다.
  - 다양한 배포판이 존재하며 RedHat, CentOS, Ubuntu, Debian 등이 있다.
  - 대부분의 웹 서버와 메일 서버가 UNIX를 이용한다.
- Windows는 Windows Server만 존재하며 파일 서버의 OS로 많이 사용된다.


### 인스턴스

> **실제로 가동되고 있는 가상화 컴퓨터로 AWS에서 서버가 생성되는 방식 (기능으로서의 서버는 인스턴스가 아니다).**

## 5. LAN


### LAN (Local Area Network)

> 회사나 가정에서 PC나 서버를 네트워크에 연결해 상호 소통이 가능하도록 하는 방식.

- 유선 LAN과 무선 LAN으로 구분됩니다.
- 사내 LAN은 상황에 따라 인터넷 연결 여부가 다릅니다 → 인트라넷은 인터넷 연결이 없습니다.
  - ![image](https://github.com/user-attachments/assets/6e597a65-f619-4176-bcde-2cb86ecc4866)


### 구성 요소 및 기술

1. **라우터 (Router)**
    - 네트워크 출입구 역할을 하며 데이터를 목적지 가까운 네트워크로 전송합니다.
2. **허브 (Hub)**
    - 네트워크 배선을 분할하여 같은 네트워크의 다른 단말기에 데이터를 전송합니다.
3. **FW (FireWall)**
    - 데이터 허용 또는 차단으로 보안을 강화합니다.
4. **DMZ**
    - 외부 네트워크와 사내 네트워크 사이의 중간 영역입니다.
5. **DHCP**
    - 단말기에 IP 주소를 자동으로 부여합니다.
6. **서브넷**
    - 하나의 네트워크를 작게 분할한 형태입니다.

## 6. IP Address & DNS

### IP Address

> 인터넷 상에서 호스트(서버나 PC)를 구별하기 위한 주소로 데이터 송수신에 사용됩니다.

- IPv4는 최대 255까지 표현 가능한 4개의 숫자로 구성됩니다 → IPv6는 주소 부족 문제 해결을 위해 개발되었습니다.
- 네트워크 접속 시 최소 1개의 IP 주소가 필요하며 개인적으로 유동적으로 할당됩니다.
- AWS에서는 Elastic IP를 통해 고정 IP 주소 제공이 가능합니다.

### 사설 IP & 공인 IP
![image](https://github.com/user-attachments/assets/72e99b90-2891-4095-92a8-5cb34fd4e2f4)


1. **공인 IP**
    - 인터넷에서 사용되며 중복되지 않는 고유 주소입니다 → 호스트 특정 가능.
2. **사설 IP**
    - 사내 LAN에서 사용되며 공인 IP 범위 내에서 발급받아 통신합니다.

### DNS & Domain
![image](https://github.com/user-attachments/assets/bec351b0-5d2d-43c3-ac6b-df6b7e0fdd2f)

> URL 이름에 해당하는 IP 주소를 알려주는 방식으로 DNS가 백그라운드에서 작동합니다.

- 열람자는 URL만으로 해당 서버에 접속할 수 있습니다.
