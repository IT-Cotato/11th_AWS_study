## 4. 서버 서비스 Amazon EC2

### 4.1. Amazone EC2란

#### 4.1.1 Amazon EC2 (Amazon Elastic Compute Cloud)

> **서버에 필요한 세트를 클라우드에서 빌려 컴퓨팅 용량을 제공하는 서비스**

- 빌린 도구를 이용하여 자신만의 서버를 만들며 하드웨어 구성 및 OS를 탄력적으로 선택 가능하며 구축이 쉽다.
- **매니지드 서비스가 아니다!** → OS를 포함한 소프트웨어는 사용자가 직접 설치하고 운영해야 한다.
    - 자유도가 높은 한편, 관리하기는 번거로운 서비스 → 설계적인 관점에서 서버 생성 및 관리가 필요하다.

#### 4.1.2 클릭 한번으로 최적의 서버를 만들 수 있다

> **다양한 서버 시스템의 조합(인스턴스 유형)과 OS 및 소프트웨어의 조합(AMI)이 준비되어 있기 때문에 선택만 하면 됨**

- 물리적인 기계를 준비할 필요 없어 초기 투자 비용을 줄일 수 있다.

#### 4.1.3 바로 생성할 수 있고, 바로 삭제할 수 있다

> **불확실성이 많은 경우 매우 유용하다**

- 관리 콘솔에 로그인하고 구성을 선택하는 것만으로도 서버를 생성 가능
    - 테스트용 서버, 학습용 서버 개설 시 유용하다
    - 간편하게 사용 가능하며 환경 구축에 필요한 소프트웨어 설치하는 수고를 줄여주므로 시간도 단축된다.
- 불필요한 리소스를 유지할 필요가 없다 → 서버에 문제가 생기더라도 즉시 복구가 가능
- Scale-in, Scale-out 기능 제공으로 이벤트 사이트 등 적용에 유용하다.

#### 4.1.4 인스턴스 유형 및 OS를 선택한다

- 어떤 OS, 소프트웨어, AMI를 선택하냐에 따라 인스턴스 유형을 선택하여 구성 가능하다.
- 기존에 정의된 인스턴스를 사용하거나 사용자가 커스터마이즈 가능하다.

### 4.2. EC2의 사용 절차

#### 4.2.1 EC2 운영

> **클라우드 서비스이기 때문에 관리 콘솔에서 작업할 수 있다**

- 소프트웨어적인 작업은 SSH(서버를 원격에서 작업하기 위한 프로토콜)를 이용해 원격으로 로그인하여 작업을 진행한다.

#### 4.2.2 EC2 서비스의 기능

| 항목         | 내용                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| 인스턴스     | AWS 클라우드에 생성한 가상 서버를 의미한다. EC2는 AMI로 몇 번이고 같은 구성의 서버를 생성할 수 있기 때문에 생성한 서버를 이와 같이 부른다. |
| AMI          | 가상 이미지를 말한다. 인스턴스를 생성하는 기준이 되는 금형과 같은 것이다. OS만 설치된 간단한 유형부터 소프트웨어도 설정된 유형까지 다양한 AMI가 있다. |
| 키 페어      | 인스턴스에 접속할 때 인증을 위해 사용하는 키이다.                                                       |
| EBS          | AWS 클라우드에서 사용할 수 있는 스토리지이다. 인스턴스 스토리지로 사용한다.                             |
| 보안 그룹    | 가상 방화벽으로, 1개 이상의 인스턴스 트래픽을 제한한다.                                                  |
| Elastic IP   | 정적(고정) IPv4 주소이다.                                                                               |

#### 4.2.3 사용 절차

1. **AWS에 로그인한다**
    - 리전을 선택하고 관리 콘솔을 연다.
    - EC2 대시보드를 연다.
2. **EC2 인스턴스를 생성한다**
    - AMI를 선택한다.
    - 인스턴스 유형을 선택한다.
    - 네트워크와 IP 주소를 할당한다.
    - 스토리지를 추가한다.
    - 보안 그룹을 생성(선택)한다.
    - 키 페어를 선택(생성)한다.
3. **EC2에 접속한다**
    - SSH로 EC2에 접속한다.
4. **소프트웨어를 설치하고 설정한다**
    - 소프트웨어를 설치한다.
    - 소프트웨어를 설정한다.

#### 4.2.4 인스턴스 설정 항목

| 항목                       | 내용                                                                                                                    |
|----------------------------|-------------------------------------------------------------------------------------------------------------------------|
| AMI                        | EC2 인스턴스의 가상 이미지이며 소프트웨어 구성의 템플릿이다. 사용할 OS, 소프트웨어 등 어떤 인스턴스를 만들 것인지 정하고 이에 해당하는 AMI를 선택한다. |
| 인스턴스 유형              | EC2 인스턴스의 장비 사양이다. CPU, 메모리, 장비 유형을 결정한다.                                                        |
| 리전                       | 서버를 설치할 지역이다. 전 세계에 이중화를 고려할 경우는 다른 나라에도 설치한다.                                        |
| 네트워크                   | EC2 인스턴스를 배치할 네트워크이다. AWS의 VPC(가상 네트워크)에서 선택한다.                                              |
| 서브넷                     | 설치할 네트워크의 범위이다. VPC 내에 어떤 서브넷을 설치할지 선택한다.                                                  |
| IAM 역할                   | 인스턴스의 접속 권한 정책을 설정한다.                                                                                   |
| 스토리지의 용량과 종류      | 서버에 장착할 스토리지이다. OS가 설치된 장소이며, 기본적으로 EBS를 선택하고 필요에 따라 인스턴스 스토어를 추가한다.     |
| 태그(EC2 인스턴스의 레이블) | 인스턴스를 구분할 수 있도록 이름, 태그를 설정한다.                                                                      |
| 보안 그룹                  | 프로토콜별로 트래픽을 허용할 포트, 허용 IP 주소, 허용 방향 등을 설정한다.                                               |

> EC2 인스턴스에는 사설 IP 주소를 부여하며 NAT에 의해 공인 IP 주소로 변환된다.
> 리전별로 존재하는 ‘기본 VPC’에는 이미 설정되어 있으며 공인 IP 주소도 할당할 수 있다.

### 4.3. 인스턴스 생성과 요금

#### 4.3.1 인스턴스 생성 예시

- 실제 생성 예시는 이미지로 제공되었으나, 절차는 위의 4.2.3을 참고.

#### 4.3.2 인스턴스 요금

> **인스턴스 요금 = 인스턴스 사용량 + EBS 요금 + 통신료 + 그 외 옵션**

- **인스턴스 사용량 (가동 시간 * 단가)**: 가동한 시간(초) 단위 과금 진행 → 인스턴스 유형에 따라 고기능을 사용할수록 비쌈
- **스토리지 요금 (용량 * 단가)**: 보유한 용량 단위로 과금이 결정, 스토리지 성능에 따라 단가가 달라진다 (정지해도 요금 측정)
- **통신 요금 (아웃바운드 통신 요금)**: 인터넷에서 인스턴스로 들어오는 통신료는 무료이며 아웃바운드만 요금이 부과됨
- **그 외 옵션**: Elastic IP 서비스 등 옵션을 사용할 경우 요금에 추가

> 서버 1대로 구성되는 단순한 서비스는 EC2를 사용하는 이점이 없다 → 구축만 하는 시스템에는 적합하지 않다.

### 4.4. AMI

#### 4.4.1 AMI(Amazon Machine Image)

> **소프트웨어 구성을 기록한 템플릿으로 인스턴스를 생성하기 위한 금형 같은 것**

- 같은 설정의 서버를 얼마든지 생성 가능하다면 같은 서버를 여러 대 구축할 경우 유용하다.
- 서버 디스크에 설치된 내용이 통째로 들어있다. AMI에서 인스턴스를 생성하면 전부 복사된다.
    - AMI는 무조건적으로 OS는 설치되어 있으며, 일부 기능만 가능하도록 하는 것은 불가능하다.

#### 4.4.2 제공되는 OS 이미지

- AWS 공식 AMI 뿐만 아니라 OS, 소프트웨어 커뮤니티, 기업이 생성한 AMI도 존재한다.
    - 특정 AMI에 따라서 별도 요금이 필요하기도 하다.

#### 4.4.3 AMI 요금

- 경우에 따라서 무료와 유료가 나뉘며, 개인이 생성할 경우 이미지 용량에 따라서 요금이 부과됨.

#### 4.4.4 AMI 생성 실습

- 같은 구성의 서버를 복제하거나 구축한 서버의 백업용으로 사용 시 마켓플레이스라는 장소에서 배포하여 사용.

### 4.5. 인스턴스 유형

#### 4.5.1 인스턴스 유형

> **머신의 용도 = CPU, 메모리, 스토리지, 네트워크 용량 등이 용도에 맞게 조합되어 있다**

- 범용, 컴퓨팅 최적화, 메모리 최적화, 가속화된 컴퓨팅 최적화, 스토리지 최적화의 5가지 용도로 구분된다.

#### 4.5.2 인스턴스 유형과 크기

> **성능 : 유형 + 크기 → 유형과 크기에 따라 단가가 달라진다 (단가 * 사용 시간)**

| 용도                 | 인스턴스 유형             | 내용                                                                                      |
|----------------------|--------------------------|-------------------------------------------------------------------------------------------|
| 범용                 | T2, T3, M5, M4 등        | 일반적인 서버. 부하가 일정한 서버의 경우 사용하며, 버스트 기능을 지원하는 유형도 있다.      |
| 컴퓨팅 최적화        | C5, C4 등                | 연산 능력이 높은 서버.                                                                    |
| 메모리 최적화        | X1e, X1 등               | 메모리 액세스 속도를 높인 서버.                                                           |
|                      | R4                       | 대용량 메모리를 탑재한 서버.                                                              |
| 가속화된 컴퓨팅 최적화 | P3, P2, G3, F1           | 머신 러닝 등에 사용되는 GPU를 탑재한 유형 및 그래픽 기능이 높은 유형.                      |
| 스토리지 최적화      | H1, I3, D2 등            | 스토리지를 최적화한 유형. I3는 SSD 기반.                                                  |

- t2.micro
    - t2 : 인스턴스 유형
    - micro : 인스턴스 크기
