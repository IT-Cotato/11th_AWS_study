## 6.1 Amazon VPC란: AWS에서 생성하는 가상 네트워크

### 6.1.1 Amazon VPC란

> 웹 서버나 데이터베이스 서버, EC2, RDS와 같은 서버들은 네트워크에 연결돼있어야 한다.
>
- 이러한 네트워크를 구축하기 위해 사용되는 것이 Amazon Virtual Private Cloud 이다.
    - AWS 계정 전용 가상 네트워크 서비스
    - AWS에서 제공하는 리소스만 설치 가능
        - 리소스를 사용하기 위해 반드시 필요

### 6.1.2 VPC의 구성

- VPC 내에 서버를 설치하면 해당 네트워크에 소속되지만, 별도로 설정하지 않으면 VPC 자체는 격리된 네트워크가 된다
- 외부와 통신라려면 VPC를 인터넷, 회사 내 LAN과 연결해야 함


### 6.1.3 VPC의 기능

- VPC는 가상 네트워킹 환경을 설정 가능
    - 네트워크, 서브넷 범위, 라우팅 테이블, 네트워크 게이트웨이 ..

### 6.1.4 VPC 네트워크의 특징과 라우팅 테이블

<aside>
💡

VPC 네트워크(클라우드)와 일반 네트워크의 가장 큰 차이점은 라우터이다.

</aside>

- VPC는 물리적인 라우터가 아닌 소프트웨어가 라우터 역할을 하며 라우팅 수행
    - 라우팅은 설정된 라우팅 테이블에 따라 동작
        - 라우터는 IP주소 갖지 않음
    - 라우팅 테이블 하나에 서브넷 여러개 설정 가능
- 물리적인 서버의 경우 LAN 케이블과 와이파이로 라우터와 연결하는 반면 클라우드는 라우팅 테이블로 연결
- VPC의 경우 서브넷 사이의 통신을 라우텅 없이 직접 통신 가능
- VPC 하나에 인터넷 게이트웨이 한 개만 설정 가능
    - IP 주소 갖지 않음

## 6.2 VPC의 사용 절차: 가상 네트워크를 사용하자

### 6.2.1 VPC 설정을 위해 꼭 필요한 사항

- VPC는 네트워크이다
    - 서버(인스턴스)가 어떤 환경에 설치되어 있는지 그리고 인터넷에 연결해야 하는지에 대한 설정이 필요
- 인터넷 연결 여부와 오토 스케일링이 중요하다
    - 인터넷에 연결해야 한다면 인터넷 게이트웨이를 설정해야 함
    - 오토 스케일링을 설정해야 한다면 서버가 자동으로 늘어나기 때문에 IP 주소를 많이 확보해 두어야 함
- 보안 그룹과 네트워크 ACL을 설정하려면 인스턴스 용도에 맞는 포트를 설정하는 것도 고려해야 한다
    - 모든 포트가 닫힌 것이 기본 설정
    - VPC는 기본 VPC를 비롯해 기본 서브넷과 보안 그룹도 제공

### 6.2.2 VPC 사용 절차

1. AWS에 로그인
2. VPC 생성
    - VPC 이름을 정함
    - CIDR 블록 설정
    - 테넌시(하드웨어 점유 여부)를 선택
3. 서브넷 설정
    - 서브넷 이름 설정
    - 대상 VPC, 가용 영역 선택
    - CIDR 블록(서브넷)을 설정
4. 인터넷에 연결
    - 인터넷 게이트웨이(IGW)를 생성
    - IGW와 VPC를 연결
    - 라우팅을 설정(라우팅 테이블을 생성하고 설정)

## 6.3 기본 VPC: AWS가 제공하는 기본 VPC

### 6.3.1 기본 VPC란

> 리전별로 기본적인 VPC 제공
>
- 특별한 설정 없이 바로 사용 가능

### 6.3.2 기본 VPC의 구성

> 기본 VPC는 서브넷과 인터넷 게이트웨이가 기본적으로 구성되어 있다
>
- 네트워크 범위는 사설 IP 주소 172.31.0.0/16이 부여된다
- 기본 서브넷이라는 서브넷이 가용 영역별로 한 개씩 생성되어 있다
    - 각 서브넷은 /20의 주소 범위로 설정되어 있다
- 인터넷 게이트웨이도 구성되어 있어 인터넷에 접속 가능

## 6.4 서브넷과 DHCP: 사용할 범위 선택

### 6.4.1 서브넷이란

> 서브넷이란 커다란 네트워크를 작게 나눈 네트워크이다
>

<aside>
💡

네트워크를 분할해 직접 통신할 수 있는 범위를 좁히고 방화벽을 설정해 보안 강화 목적

</aside>

- AWS의 경우 어떤 가용 영역에 서브넷을 둘지 설정
    - 즉, 서브넷은 물리적인 장소를 특정
- VPC는 사용자가 사용할 수 있는 네트워크 범위를 생성하고 그 아래에 용도에 따라서 서브넷을 생성
    - 서브넷별로 역할 다르게 부여 가능
    - VPC의 경우에는 라우팅 없이 서브넷끼리 통신 가능

### 6.4.2 네트워크 범위와 CIDR 표기

> 네트워크와 서브넷의 범위를 나누는 데 사용되는 표기법을 CIDR(Classless Inter-Domain Routing)이라고 한다
>
- 슬래시 뒤에 네트워크 길이를 숫자로 표기
    - 프리픽스 표기
- CIDR는 IP 주소의 수를 나타냄
    - /24면 256개, /20이면 4096개 의미 (2의 ‘32-네트워크 길이’ 제곱)


- 네트워크의 범위는 범위 안에서 가장 첫 번째 IP 주소와 CIDR 순으로 표기
    - 172.31.0.0./16 이면 /16은 65536개라는 의미이므로 172.31.0.0 부터 172.31.255.255까지가 네트워크 범위



### 6.4.3 네트워크 클래스

- 네트워크는 규모에 따라서 A, B, C 세 클래스 존재
    - A클래스 : 13만-1677만 개 정도 IP주소 가진 , 범위 가장 넓은 네트워크
    - B클래스 : 중간 규모로, 대략 512-6만 5천개
    - C클래스 : 소규모, 1-255개 범위


- 기본 VPC는 /16(B클래스)로 설정되어 있으며 이를 /20으로 분할한 서브넷이 각 가용 영역에 구성되어 있다

### 6.4.4 IP 주소 할당과 DHCP

- 네트워크 및 서브넷에 사용되는 IP 주소의 범위는 관리자가 설정 가능
- DHCP에서 각 호스트(인스턴스)에서 IP 주소를 자동으로 할당
    - VPC에는 DHCP 서버가 동작하고 있어 인스턴스가 추가되면 해당 서브넷 범위의 IP 주소 중에 하나가 할당됨
- VPC가 일반적으로 사용하는 IP 주소는 사설 IP 주소

## 6.5 라우팅과 NAT: 공인 IP 주소와 사설 IP 주소 변환

### 6.5.1 네트워크와 라우팅

- 네트워크란 PC 여러 대가 서로 통신할 수 있도록 연결되어 있는 상태
    - 과거에는 PC를 서로 1:1로 연결하기도 함
    - 현재는 LAN이나 WAN, 인터넷으로 연결해 라우터를 통해 데이터 주고받음

<aside>
💡

데이터를 라우터로 보내고, 라우터가 목적지로 보내는 방식이 **라우팅**이다. 이는 ****호스트에서 호스트로 데이터를 전달하는 형태로 데이터를 송신한다

</aside>


### 6.5.2 IP 주소와 게이트웨이

- 라우터가 각 PC에 데이터를 전달하려면 대상을 식별할 주소가 필요
    - 이 주소 역할을 하는 것이 IP 주소
    - IP 주소는 클라이언트나 서버 뿐만 아니라 네트워크 안의 모든 호스트에 설정되어 있음

- 목적지에 데이터를 보낼 때
1. 목적지의 IP 주소를 지정
2. 데이터를 네트워크 사이를 연결하는 라우터로 보냄
3. 라우터는 자신의 네트워크 내에 목적지가 있는지 확인하고, 있다면 데이터를 그 목적지(호스트)로 전달, 없다면 다른 라우터로 전송
    - 라우터에는 목적지로 가장 빠르게 전송할 수 있는 경로 정보가 설정되어 있음

- 라우터는 게이트웨이라고 한다
    - 게이트웨이 중에 자신 이외의 접속되어 있는 모든 것을 기본 게이트웨이라고 함

### 6.5.3 IP 마스커레이드

> LAN에서 인터넷으로 데이터를 전송할 때 LAN 내부의 출입구가 되는 것이 게이트웨이이다
>

<aside>
💡

게이트웨이는 기기의 역할을 말하며 실제 기기의 라우터이다

</aside>

- LAN에서 전송되는 데이터를 인터넷으로 보내고, 인터넷에서 돌아오는 데이터를 목적지 PC로 전송
- LAN 내부의 PC에서는 사설 IP 주소 할당이 일반적
- 인터넷 상에서는 공인 IP 주소가 없으면 식별 불가능
    - 게이트웨이가 사설 IP 주소를 공인 IP 주소로 변환하고, 가정 내 혹은 회사 내에서는 공인 IP주소 하나를 공동으로 사용

  **⇒ 주소 변환을 담당하는 것이 IP 마스커레이드(NAPT)**


### 6.5.4 NAT

> IP 마스커레이드를 사용하면 내부에서 외부로 나가는 건 가능하지만, 외부에서 내부로 돌아오는 것은 불가능하다. 즉, 외부에서 내부로 요청하는 것에는 응답하지 않는다
>
- LAN 환경에 서버를 설치한 경우 당연히 외부 요청에 응답해야 함
    - 서버만 양방향으로 통신할 수 있도록 IP 마스커레이드 설정 가능
        - 단, 공인 IP 하나만 설정 가능
    - 서버가 여러 대라면 공인 IP 주소를 여러개 설정할 수 있는 **NAT** 사용

- IP 마스커레이드는 일대다, NAT는 다대다
- IP 마스커레이드는 포트를 변환할 수 있지만 NAT는 포트 변환 불가

## 6.6 인터넷 게이트웨이와 NAT 게이트웨이: VPC에서 인터넷으로 접속

> 라우터란 데이터를 주고받는 기기이다. AWS는 물리적인 라우터가 아닌 소프트웨어적으로 라우팅을 수행한다. 라우팅은 라우팅 테이블에 따라 수행된다.
>

### 6.6.1 인터넷 게이트웨이

- 인터넷 게이트웨이는 인터넷 연결을 담당
    - 웹 사이트(EC2 인스턴스)에 접속하는 사람은 그 페이지에 접속하고 싶다는 요청을 보냄
    - 요청은 DNS에서 변환되어 목적지인 공인 IP 주소롤 전달된다

  ⇒ 하지만 EC2 인스턴스는 사설 IP 주소밖에 설정할 수 없기 때문에, 요청된 EC2 인스턴스의 연결 정보를 가지고 있는 **인터넷 게이트웨이가 공인 IP 주소(목적지)를 사설 IP 주소로 변환**해 해당 EC2 인스턴스에 요청을 보낸다



### 6.6.2 NAT 게이트웨이

> NAT 게이트웨이는 서브넷에서 인터넷으로 접속할 수 있지만, 인터넷에서 서브넷으로 접속하지 못하게 한다

## 6.7 보안 그룹과 네트워크 ACL: 보안 설정

### 6.7.1 보안 그룹과 네트워크 ACL

> VPC의 가상 방화벽으로 보안 그룹과 네트워크 ACL이 있다
>
- 방화벽이란 네트워크 통신을 제어하는 방식
- 보안그룹과 네트워크 ACL은 인바운드 트래픽(데이터 유입)과 아웃바운드 트래픽(데이터 유출)을 제어
    - 반드시 양쪽 모두 설정해야 함


- 네트워크 ACL은 서브넷 단위로 설정하기 때문에 개별 인스턴스에 설정할 필요 없다
    - 인스턴스에 보안 그룹 설정 안해도 네트워크 ACL로 처리 가능
    - 서브넷 여러 개를 설정할 수 있지만, 서브넷 하나에 네트워크 ACL 여러 개는 불가능(덮어쓰게 된다)


### 6.7.2 인바운드 및 아웃바운드 설정과 잘 알려진 포트

- 트래픽은 인바운드와 아웃바운드 각각에 대해 포트 단위로 허가 여부를 설정
- 포트란 통신의 입구를 말한다
    - 어떤 데몬(서비스)이 동작할 때 해당 서비스를 사용하는 포트는 수신 대기 상태가 된다
    - 웹 사이트 운영시 http, https 포트 열어햐 한다
        - 서비스 별로 잘 알려진 포트가 정해져있다

- 보안 그룹은 인바운드는 허가하지 않으며 아웃바운드를 허가하고 네트워크 ACL은 양쪽 모두를 허가하는 것이 기본 설정
