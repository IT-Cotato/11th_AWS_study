## 5.1 Amazon S3란: 사용하기 쉬우며 기능이 강력한 스토리지 서비스

### 5.1.1 Amazon S3란

<aside>
💡

Amazon S3(Amazon Simple Storage Service)는 스마트한 객체 스토리지 서비스이다.

</aside>

- **객체 스토리지**는 데이터를 객체 단위로 관리하는 형식
    - 인터넷상에 데이터를 저장하는 장소를 제공해주는 것
- 용량 제한이 없음
- 다양한 기능이 있는데 대표적으로 **웹 서버 기능, 쿼리 기능**이 있다.
    - 쉽게 웹 서버 만들 수 있음
- 클라우드이기 때문에 확장이나 축소도 간단하고, 사용한 만큼 지불하면 되므로 초기 투자 비용도 최소한으로 할 수 있다.

### 5.1.2 견고하고 스마트한 스토리지 서비스


- 확장성
    - 사용 목적에 맞게 다양한 스토리지 클래스가 준비돼있고 수명 주기 정책을 사용하여 자동으로 이동이 가능
- 가용성과 내구성
    - 데이터 내구성이 매우 높아 장애나 오류, 위협에 강하다
    - S3 객체는 최소 4개의 가용 영역에 자동으로 복제되어 보존되기 때문에 어느 한 쪽에 장애가 발생해도 계속 사용 가능하다
- 신뢰성
    - 암호화 기능과 접근 관리 도구가 있어 공격으로부터 지키키 쉽다
- 다양한 관리 기능
    - 스토리지 클래스 분석, 수명 주기 정책 등을 시작으로 각종 관리 기능이 있다
- 스마트한 기능
    - S3 Select라는 데이터에 쿼리를 실행하는 기능과 서비스가 있다

### 5.1.3 요금 체계


- **S3 요금 = 저장 용량 + 전송량**
    - 저장 용량: 데이터를 저장한 양에 따라 과금
    - 전송량: 데이터를 주고받은 전송량에 따라 과금

- 저장 용량
    - S3에 저장된 용량에 대한 비용이다.
    - 스토리지 클래스에 따라서는 최소 용량 요금이 설정되어 있으며 이 크기보다 작은 파일인 경우도 올림하여 요금이 부과된다.
- 전송량
    - S3에서 파일을 받거나 보낼 때 발생하는 요금이다.
    - 수신 요청(GET)이나 송신 요청(PUT)에 대해서 1GB 단위로 과금된다.

### 5.1.4 전송량에 대한 개념

- 수신 요청과 다운로드
    - 서버에 보내는 다운로드 명령


- 송신 요청과 업데이트
    - 서버에 파일을 전송하는 명령
    - 파일을 저장할 때는 업로드이다

## 5.2 스토리지 클래스: 다양한 종류의 스토리지

### 5.2.1 스토리지 클래스란

> S3 스토리지의 종류를 스토리지 클래스라고 한다.
>


- 스토리지 클래스는 Standard 외에도 엑새스 패턴에 따라 계층을 이동할 수 있는 클래스, 액세스 빈도가 낮은 클래스등 사용 목적에 맞춰 선택할 수 있다.
- 버킷(객체를 저장한는 컨테이너) 단위가 아니고 객체(파일) 단위로 클래스를 선택할 수 있다.
- 스토리지 클래스는 상황에 따라 변경할 수 있다.

### 5.2.2 스토리지 클래스의 종류


- **Standard**
    - 가장 일반적인 스토리지 클래스
    - 3곳 이상의 AZ(가용 영역)에 데이터가 저장돼있어서 99.9%의 가용성을 보장
    - 데이터를 검색할 때의 요금과 최소 용량의 요금이 없고 일할로 계산되므로 쉽게 사용하기에 좋은 클래스이다.
- **Intelligent-Tiering**
    - 빈번한 액세스와 간헐적 액세스에 최적화된 두 가지 계층에 객체(파일)를 저장한다.
        - 어디에 저장할 지는 객체별 모니터링을 통한 결과에 따라 자동 이동
    - 검색과 액세스 계층 간 이동에 대한 요금이 부과되지 않는다.
    - 자주 사용하는 파일과 자주 사용하지 않는 파일이 섞여있어 액세스 빈도가 자주 바뀌는 경우에 비용을 줄일 수 있다.


- **Infrequent Access**
    - Standard에 비해 저장 요금은 낮고 액세스 요금은 높다.
        - 액세스 빈도가 낮고 용량이 큰 데이터에 적합
    - Infrequent Access의 Standard는 최소 3개 이상의 AZ에 저장되지만 One Zone은 한 군데에 저장된다.
        - One Zone의 경우 데이터 유실 위험 존재
- **Reduced Redundancy Storage**
    - Standard에 비해 이중화 수준을 낮춰 낮은 가격으로 제공
    - 저장되는 AZ는 한 군데이다
- **S3 Glacier/S3 Glacier Deep Archive**
    - 데이터 아카이브와 장기간 백업을 고려하여 만든 스토리지 클래스
    - 내구성이 높고 가격이 낮아 대용량 데이터를 저렴하게 보관 가능
    - 데이터는 ‘볼트’라고 하는 컨테이너에 저장됨
        - 저장된 데이터를 읽어야 할 경우 다른 S3 버킷으로 옮겨야함
    - 주로 통째로 검색하고, 검색을 할 때 Glacier상의 데이터와 검색 대상의 데이터 양쪽에 요금이 부과됨

## 5.3 S3의 사용 절차: 스토리지 서비스를 사용하기까지

### 5.3.1 S3 조작

- 버킷의 생성 및 각종 설정과 같은 기본적인 S3 조작은 관리 콘솔의 S3 대시보드에서 수행한다.
- API와 SDK를 사용해 객체의 업로드 수행 (관리 콘솔X)
- AWS Transfer for SFRP가 제공되어 SFTP(SSH로 암호화된 파일 전송 프로토콜)로 액세스 할 수 있다.

### 5.3.2 S3 서비스의 기능

| **객체**  | S3의 저장 단위. 텍스트나 이미지 같은 파일을 의미 |
| **버킷**  | 객체를 저장하는 컨테이너. 모든 객체는 버킷 안에 저장된다 |
| **버킷 명** | S3 버킷의 이름으로, 유일해야 한다. 웹서버로 사용할 경우 도메인 이름이 버킷 이름이 된다. |
| **객체 키**  | 객체의 고유 식별자. 모든 객체는 반드시 하나의 키를 갖는다. 버킷+객체 키+(버전)을 조합하여 객체를 유일하게 식별한다. |
| **객체 메타데이터** | 이름과 값으로 이루어진 데이터. 업로드 시 설정 가능하며, S3가 파일을 식별하는 것이 객체 키라면, 메타데이터는 사람이 파일을 관리하기 쉽게 돕는 데이터 |
| **리전** | 버킷의 물리적인 보관 장소가 있는 지역 |
| **데이터 일관성 모델** | S3는 가용성을 위해 데이터를 자동으로 복제하지만, 데이터 무결성을 보장하기 위해 복제가 모두 완료될 때까지 시간이 걸릴 수 있다. |
| **버전 관리** | 하나의 객체에 대해 여러 버전을 저장할 수 있다. 각 버전은 별도의 객체로 취급된다. |
| **로그** | 버킷 단위나 객체 단위로 접근 로그를 기록할 수 있다. 객체 수준의 로그는 유료 |
| **암호화** | S3에 저장되는 데이터를 자동으로 암호화할 수 있다 |
| **액세스 제어** | 버킷 또는 객체에 대한 권한을 설정할 수 있다 |
| **웹 서비스 기능** | S3 버킷을 웹사이트로 사용할 수 있는 기능 |

### 5.3.3 S3의 사용 절차

1. AWS에 로그인 한다
    1. 리전을 선택하고 관리콘솔을 연다
    2. S3 대시보드를 연다
2. 버킷을 만든다
    1. 버킷명 설정
3. 버킷을 설정한다
    1. 웹 서버로 사용할 경우 Static website hosting을 설정한다
    2. 접근할 수 있는 사용자를 설정한다
4. 파일을 업로드한다
    1. 관리 콘솔이나 전용 도구에서 파일을 업로드한다

### 5.3.4 S3 버킷 생성 전 검토해야 할 것

<aside>
💡

S3 버킷을 생성한 후에는 이름과 리전을 변경할 수 없다.

</aside>

- 용도를 명확히 정해야 한다
    - 웹 서버로 사용할 경우 다른 용도에 비해 차이점이 많음
    - 웹 서버로 사용할 경우 버킷에 대한 공개, 도메인, 익명 접속 허가 등을 고려해야 함

## 5.4 객체와 버킷: 파일과 파일을 저장하는 장소

### 5.4.1 객체와 버킷이란

> 버킷은 윈도우의 드라이브, 객체는 파일과 같은 것이다.
>


- 버킷은 폴더가 아니므로 버킷 안에 버킷을 다시 만드는 것은 불가능하다.
- 객체는 단순한 파일이 아니라 관리를 위한 메타데이터가 포함돼 있다.
- S3는 객체 스토리지이기 때문에 폴더나 디렉터리같은 개념이 없다.
    - 객체는 버킷에 병렬로 배치됨 (편의상 폴더로 표시되는 것)
        - 이 폴더는 생성, 삭제, 업로드, 다운로드가 가능

### 5.4.2 버킷 생성과 명명 규칙

- 버킷을 생성하면 리전과 버킷명을 변경할 수 없다.
- 버킷명은 S3 안에서 유일한 이름이어야 한다.
    - 리전을 변경해도 같은 버킷명으로 생성할 수 없다.
    - 명명 규칙 존재

## 5.5 버킷 정책과 사용자 정책: 액세스 제한 설정

### 5.5.1 S3 버킷에 대한 엑세스 제한

> S3 버킷에 대한 엑세스 제한을 설정할 수 있다.
>


- 버킷 정책 - 버킷 단위 제한
    - 해당 버킷에 접속할 수 있는 사용자 지정
- 사용자 정책 - IAM 사용자 단위 제한
    - 접속 가능한 버킷을 지정
- 관리 정책 - ACL(액세스 제어 목록)
    - 자신 외의 다른 AWS 계정의 ‘읽기/쓰기’에 대해 허가, 거부를 설정한 목록

### 5.5.2 엑세스 제한의 대상과 내용

<aside>
💡

리소스, 작업, 효과, 보안 주체에 대해 설정 가능하다. 즉 ‘누가, 무엇을, 어떤 것에 대해 가능한가 여부’를 정하는 기능이다.

</aside>

| 리소스 | 제한 대상이 되는 버킷 및 객체이다. 아마존 리소스 이름을 사용해 대상 식별 |
| 작업 | 실제로 가능한 작업을 말하며, GET,PUT,DELETE 가 있다. 작업 키워드를 사용하여 지정한다. |
| 효과 | 설정 여부(허가, 거부) |
| 보안 주체 | 허가 혹은 거부할 사용자 및 계정, 서비스 |

## 5.6 웹 사이트 호스팅: 웹 사이트 공개

### 5.6.1 웹 사이트 호스팅이란


- S3는 정적 웹 사이트를 호스팅할 수 있다.
    - 정적 웹사이트란 서버가 스크립트를 처리하지 않은 사이트
        - 서버에서 처리하는 언어X - HTML, 이미지 ..
        - 동적 웹사이트란 PHPP, JSP, ASP 등 서버에서 처리하는 언어 포함된 사이트
- 정적 웹사이트를 호스팅하려면 버킷을 그대로 웹 사이트로 오픈하면 된다
    - URL을 설정하고 버킷을 누구든지 접속 가능하게

### 5.6.2 웹 호스팅에 필요한 설정

- 정적 웹 호스팅 활성화
- 공용 액세스 차단 해제
- 버킷 정책을 ‘모든 사용자’로 설정
- 버킷명을 사용할 도메인 지정
- 개인 도메인을 소지한 경우 Amazon Route S3등의 DNS 서비스를 사용하여 설정

---

> http:// 뒤의 부분을 버킷명으로 지정
>
- 버킷명 + AWS가 지정한 문자열이 URL이 된다.

### 5.6.3 다른 서비스로 구축한 웹 호스팅과의 차이

- Amazon Lightsail
    - 필요한 기능을 선택하면 웹 사이트에 필요한 서비스 전체를 정해진 가격으로 구축할 수 있는 서비스
    - 복잡한 부분을 패키지 하나로 서비스
    - EC2 인스턴스와 달리 CPU나 메모리 같은 사양, 대수를 변경할 수 있는 유연성은 없음
    - 변경해야 할 때는 스냅샷 기능을 이용해 백업, 복원하는 방식
- Amazon Amplify
    - 웹을 개발하기 위한 도구 전체를 제공하는 서비스
    - JS로 AWS의 다양한 기능을 호출하여 시스템 구축

## 5.7 파일 업로드와 다운로드: 다양한 파일 업로드 방법

### 5.7.1 업로드와 다운로드

- 파일을 업로드하거나 다운로드하려면 관리 콘솔을 사용하는 방법과 CLI를 사용하는 방법이 있다
- 모든 파일 형식을 업로드할 수 있지만, 업로드할 수 있는 파일 크기는 제한이 있다.
    - 관리 콘솔의 경우 160GB까지 가능
    - 이보다 클 경우 CLI나 SDK 사용

### 5.7.2 다양한 업로드 방법

- API와 SDK
    - third party 도구를 사용해 파일 업로드
- 멀티 파트 업로드
    - 객체를 여러 개로 나누어 세트 하나로 업로드
    - 업로드 중에는 부분별로 표시되지만 업로드가 완료되면 객체 하나가 된다
    - 요금 발생 X, 큰 파일을 업로드 하는데 적합
- AWS Transfer for SFTP
    - SFTP를 사용해 파일을 전송할 수 있는 서비스
    - SFTP 서버를 제공하는 서비스
        - 서버를 사용한 시간에 대해 과금
- AWS DataSync
    - 온프레미스 스토리지 시스템과 AWS 스토리지 서비스 간에 대용량 데이터 전송을 위한 서비스
    - 복사하는 양에 대해 요금 발생

## 5.8 액세스 관리 및 변조 방지: 부정한 액세스 감시

### 5.8.1 액세스 로그란

> 액세스 로그란 서버에 어떤 요청이 있었는지를 기록하는 기능
>
- 로그에는 버킷 소유자, 버킷명, 요청자, 총 시간, 응답 시간, 작업, 응답 상태, 오류, 코드 등이 기록됨

### 5.8.2 그 외에 액세스 관리 방법

- 스토리지 클래스 분석
    - 객체에 액세스 빈도를 분석하는 기능
    - 액세느 빈도가 낮은 데이터는 S3 Intelligent-Tiering으로 이동하는 판단 자료로 사용
    - 객체는 설정된 날짜별로 그룹화되어 있어 각 그룹의 평균 전송 바이트 수 감시
    - 대상 객체 필터링해서 감시하는 것도 가능
        - 버킷당 최대 1000개 설정 가능
- 객체 잠금
    - 객체를 보호하는 기능
    - 객체에 대한 변경을 허용하지 않음
    - 잠금에 대한 유효 기간 존재
        - 법적으로 보존해야 하는 경우에는 유효 기관 관계없이 보존 가능
- S3 인벤토리
    - 버킷에 들어있는 객체의 메타데이터의 목록을 매일 혹은 매주 생성하는 기능
    - CSV, ORC 등의 파일로 구성

## 5.9 버전 관리, 수명 주기, 복제: 저장된 객체 관리

### 5.9.1 버전 관리


- 객체를 여러 버전으로 저장하는 기능
    - 파일 복원 가능
        - 이전 버전으로 되돌리려면 저장된 과거 버전 중 되돌리고 싶은 버전을 같은 버킷으로 복사
        - 바로 이전 버전으로 되돌릴 경우는 최신 버전을 삭제해도 복원 가능
- 버킷 단위로 설정
- 미사용(기본), 활성화, 버전 일시 중지 이렇게 세가지 상태 중 하나로 설정

### 5.9.2 수명 주기 정책

- S3는 수명 주기 정책을 설정 가능
    - 객체가 정기적으로 수행할 작업을 설정하는 기능



### 5.9.3 교차 리전 복제(CRR)

> 다른 리전의 버킷에 객체를 비동기적으로 복사하는 것
>


- 복제 작업을 수행하기 위해 IAM 역할(접근 권한)을 부여해야 한다
- 복제에 사용할 두 버킷은 버전 관리가 활성화되어 있어야 한다
- 같은 리전에 존재하는 버킷은 복제 설정 불가능

## 5.10 데이터 분석과 연계: 저장된 데이터의 분석

### 5.10.1 데이터 분석과 연동

- S3 Select, Amazon Athena
    - CSV나 JSON과 같이 구조화된 텍스트 형식의 데이터를 SQL의 SELECT문으로 실행하는 기능
    - 쿼리를 실행하기 위한 서버 불필요
- Amazon redshift Spectrum
    - 대용량 데이터를 처리하기 때문에 Redshift cluster필요

### 5.10.2 데이터 분석 서비스

- S3 Select
    - S3로 저장된 데이터 파일 하나에 SQL 문을 사용하여 집계 및 검색이 가능한 기능
    - 집계는 관리 콘솔에서 SQL문을 입력하여 간단히 실행 가능
    - 복잡한 집계의 경우 프로그램을 만들어 실행 가능
- Amazon Athena와 Amazon Redshift Spectrum
    - Amazon Redshift Spectrum은 데이터 분석 서비스
        - S3에 저장된 데이터 분석
        - S3 Select와 달리 어떤 대상에 대해 어떤 검색을 할지 사전에 구성
        - 여러 파일을 대상으로 수행 가능
    - Athena는 매번 필요에 따라 분석용 서버를 자동으로 생성하여 실행해서 실행하는 순간만 비용이 발생
    - Redshift Spectrum은 미리 분석용 서버를 시작하고 이 서버를 사용해 분석
        - 처리 능력에 맞춰 서버 선택, 데이터를 분산 처리

  ⇒ 분석을 위한 서버의 존재 여부가 가장 큰 차이점


### 5.10.3 데이터 분석 도구의 사용 구분


- S3 Select가 가장 심플하다
    - 파일 하나를 대상으로 집계, 검색 가능
- Athena, Redshift Spectrum
    - S3에 저장된 파일 여러 개를 대상으로 분석
    - Athena는 집계나 검색 방법을 저장 가능
        - 이를 사용하면 반복 작업 시 편리
    - Redshift는 뛰어난 분석 기능 가진 데이터 웨어하우스
        - 다양한 기준으로 데이터 분석, 예측

## 5.11 Amazon CloudFront: 콘텐츠 배포 서비스

### 5.11.1 Amazon CloudFront와 엣지 서버


- Amazon CloudFront
    - 고속 콘텐츠 전송 네트워크 서비스
    - 고속화는 웹 서버의 내용을 캐시하는 엣지 서버를 사용하여 이루어짐
- 엣지 서버
    - 캐시한 내용을 반환 해 웹 서버의 부담을 줄임
    - 각 리전의 네트워크 말단에 위치
    - 클라이언트가 접속하는 네트워크의 거리 가까워 빠른 반응 속도

### 5.11.2 Amazon CloudFront의 요금 체계

- 기본적으로 데이터 송신에 대한 요금이 부과
- 사이트 접속자의 요청이나 접속자에게 페이지 전송, 접속자가 업로드한 파일의 전송 등에 요금 부과
- 엣지 서버가 원본 데이터를 캐시하기 위해 전송량은 요금이 부과되지 않음
    - 캐시에 대한 요금은 부과

### 5.11.3 Amazon CloudFront의 요금 계층

- 요금 계층이 존재하고 계층에 따라 사용할 수 있는 엣지 서버가 다르다
- 선택한 요금 계층이 포함된 지역의 엣지 서버에서 콘텐츠가 전송됨
- 엣지 서버별로 요금이 다르므로 접속자 수와 균령을 맞춰줘야 함
