## 1.1 아마존 웹 서비스란: 아마존이 제공하는 클라우드 서비스

아마존 웹 서비스(AWS, Amazon Web Service)란 컴퓨팅, 스토리지, 데이터베이스를 제공하는 ‘클라우드 컴퓨팅 서비스’이다

### 1.1.1 아마존 웹 서비스란

**AWS**는 아마존이 제공하는 클라우드 컴퓨팅 서비스의 한 종류

- Amazon EC2, Amazon S3 ..

<aside>
💡

**클라우드 컴퓨팅 서비스**란 서버 및 네트워크 등을 인터넷으로 빌려주는 서비스로, 언제 어디서든지 사용할 수 있다

</aside>

*⇒ AWS의 다양한 서비스를 조합하여 모든 애플리케이션과 인프라를 구축할 수 있다*

### 1.1.2 시스템 운영에 필요한 서비스 일체를 사용할 수 있다

AWS의 특징

- 여러 사업자에게 각각 빌려야 했던 인프라를 일괄로 빌릴 수 있다는 것
- 운영 체제(OS)나 웹 서버, 데이터베이스 서버(DB 서버) 등에 필요한 소프트웨어까지 통째로 사용할 수 있음

*⇒ 시스템 운영에 필요한 서비스 전부를 AWS로 빌릴 수 있다*

### 1.1.3 서비스를 조합하기 쉽다

<aside>
💡

어떤 서비스를 구축할 때 AWS가 제공하는 서비스 만으로 필요한 기능을 대부분 구축할 수 있으며, **여러 서비스를 조합하여 구축하기 쉽다**

</aside>

- 서비스를 서로 연동하는 부분은 매년 강화되고 있다
- AWS와 AWS 외부의 시스템, 네트워크를 연동하는 사례도 늘고 있다
- 서버의 일부만 AWS를 사용하거나 사내 LAN과 AWS를 연결하는 것도 가능하다

### 1.1.4 종량제이므로 사용할 만큼만 빌릴 수 있다

- AWS의 요금은 종량제로, 사용한 만큼 지불한다

### 1.1.5 전문가가 아니어도 사용할 수 있다

- 컴퓨터 웹 브라우저에 접속하여 조작하기 때문에 인터넷이 가능한 곳이라면 언제 어디서든 가능하다

### 1.1.6 한국어와 한국 원화 결제가 가능하다

- AWS 서비스의 대부분은 한국어를 지원하고 원화로 결제 가능하다
- 한국 전담팀이 있어 상담할 수 있고, AWS 도입을 지원하는 APN(Amazon Partner Network) 파트너 기업과 상담할 수도 있다

### 1.1.7 보안 기준

- AWS는 국내외 보안 통일 기준을 준수하고 있다
    - 한국 기준 - ISMS / 국제 기준 - OSA
- AWS는 각국과 글로벌의 규정 준수, 즉 컴플라이언스(compliance)에 대해 인
  증 및 검증되어 있고, 법령, 규정, 프라이버시 기준을 준수하고 있다

### 1.1.8 글로벌 확장이 쉽다

- AWS는 서버를 설치하여 운영하는 데이터 센터를 전 세계 21개 지역의 66개 시설에서 운영하고 있다

## 1.2 AWS의 서비스: 165개 이상의 서비스 제공

> AWS의 서비스는 165 개 이상 존재하며 서비스할 수 있는 영역 또한 다양하다.
대표적인 서비스인 Amazon EC2 와 Amazon S3 뿐만 아니라 데이터베이스 서
버와 네트워크 , 머신 러닝 , 로봇 개발에 대한 서비스도 제공하고 있다.
>

### 1.2.1 165개 이상의 서비스를 제공

AWS는 165개 이상의 IT 전반과 관련된 인프라의 대부분 서비스를 제공한다.

- 서버 및 네트워크를 시작으로 그에 필요한 소프트웨어와 보안을 위한 장치, 개발 도구, 계정 관리를 위한 장치 등 여러 서비스를 사용할 수 있다

### 1.2.2 목적에 따라 다양한 서비스를 제공

- AWS에서는 필요에 따라 하나만 사용하거나 여러 서비스를 한 번에 세트로 사용할 수도 있다.
- AWS는 일시적인 테스트에 매우 유용하다
    - 보통 테스트를 하기 위해 전체적인 사양을 갖추거나, 비용 등 문제로 쉽지 않다
- AWS의 서비스
    - 웹 서버 구축
        - 서버 (EC2), 서버 OS(AMI), IP 주소(Elastic IP), 스토리지 (S3), 도메인 (Route 53), DB 서버 (RDS)
    - 모바일 시스템 구축
        - 애플리케이션 서버 (EC2), DB 서버 (RDS), 통지 시스템 (SNS), 스토리지 (S3), IP 주소 (Elastic IP), 인증 서버 (Cognito)
    - 콘텐츠 배포
        - 서버 (EC2), 캐시 서버 (CloudFront), IP 주소 (Elastic IP), 도메인 (Route 53)
    - IoT 구축
        - API 서버 (oT Core), DB ME(DynamoDB/RDS), 분석 도구(ElasticSearch)
    - 머신 러닝 개발
        - 머신 러닝 모델(Machine Learning, SageMaker), 이미지 동영상 인식 (Rekognition), 음성 인식 (Transcribe, Lex)
    - 로봇 개발
        - 로봇 프레임워크 (RoboMaker)

### 1.2.3 AWS에서 제공하는 서비스

- Amazon EC2
  - Amazon Elastic Compute Cloud(Amazon EC2)는 컴퓨팅 용량을 제공하는 서비스이다.
- Amazon S3
  - Amazon Simple Storage Service(Amazon S3) 는 오브젝트 스토리지 서비스이다.
- Amazon VPN
  - Amazon VPN 은 AWS 계정 전용의 가상 네트워크이다.
- Amazon RDS
  - Amazon RDS는 관계형 데이터베이스의 대표라고 할 수 있는 6종류 (Amazon Aurora, PostgreSQL, MySQL, Maria DB, Oracle Database, SQL Server) 를 클라우드에서 이용할 수 있는 서비스이다.
- Amazon Route 53
  - Amazon Route 53 는 DNS(도메인 네임 서버) 이다. 웹 서버에 필수인 DNS 기능을 제공한다.
- Elastic IP 주소
  - Elastic IP 주소는 서버에 필수인 정적 공인 IP 주소를 제공한다.
- Amazon Managed Blockchain
  - Amazon Managed Blockchain은 블록체인 네트워크를 생성, 관리할 수 있는 도구이다.
- Amazon SageMaker
  - Amazon SageMaker는 머신 러닝 모델을 구축, 트레이닝, 배포할 수 있다.
- AWS Cloud9
  - AWS Cloud9은 웹 브라우저로 조작이 가능한 통합 개발 도구이다.
- Amazon GameLift
  - Amazon GameLift 는 게임 호스팅 서비스이다.

## 1.3 AWS의 비용 : 초기 비용은 저렴하지만 운영 비용이 조금 비싸다

> 대부분의 서비스가 종량제 형태로 되어 있으며 계산 방법이 조금 복잡하다. 따라서 비용을 계산하는 도구나 비용을 관리하는 서비스도 제공하고 있다.
>

### 1.3.1 사용한 만큼 지불하는 종량제

AWS 는 서비스에 따라 요금 체계가 다르다. 하지만 대부분의 공통적인 서비스에는 종량제를 도입하고 있어서 ' 사용한 서비스 1 개당 금액 + 사용한 분' 의 과금 형태가 많다.

<aside>
💡

향후에 필요하지만 지금은 필요없는 자원을 확보해 둘 필요가 없다. 최소로 필요한 만큼만 준비해서 시작하고 필요할 때 늘리면 된다.

</aside>

### 1.3.2 대표적인 요금 체계

AWS의 서비스 대부분은 종량제이기 때문에 항목별로 산출한 금액을 합산하는 방식이 대부분이다.

### 1.3.3 AWS 요금 산출 방법

- AWS 요금은 서비스에 따라서 계산하는 방법이 다르다.
    - Amazon EC2의 요금 산출 방법

      1.인스턴스 사용량 (가동 시간 x 단가) + 2.EBS 요금 (용량 x 단가) + 3.통신료 + 4.그 외 옵션

- 요금을 계산하는 도구
    - [https://calculator](https://calculator/).[s3.amazonaws.com/index.html](http://s3.amazonaws.com/index.html)

### 1.3.4 AWS 요금의 장점과 단점

- 장점
    - 이벤트나 캠페인과 같이 돌발적으로 접속 수가 늘어나는 웹 사이트의 경우는 AWS 의 유연성이 큰 장점이 된다
    - 운영에 대한 부분을 맡길 수 있기 때문에 관리하는 사람이 없어도 된다.
    - 기술적 지식이 부족해도 사용할 수 있는 서비스가 많기 때문에 전문적인 지식이 필요하지도 않다.
        - 고용 비용 측면에서 절감할 수 있다
- 단점
    - 초기 비용이 들지 않는 대신 운영 비용이 들기 때문에 경우에 따라 정액제 임대나 자사에서 준비하는 편이 저렴할 수도 있다.
    - 종량제라고 해도 최저 요금이 있는 요금 체계도 있고, 사용하는 서비스 1개당 요금이 발생하는 체계도 있다.
    - 변동이 없는 시스템에는 AWS의 유연성이 큰 이점이 되지 않을 수도 있다.
        - 이 경우에 비용 절감에 주목해야 할 것은 종량제보다 인건비의 축소일 것이다

## 1.4 AWS의 사용 방법: 누구라도 쉽게 서비스를 이용할 수 있다

> AWS 는 관리 콘솔과 매니지드 서비스를 제공하는데 이는 누구라도 쉽게 서비스를 사용할 수 있는 구조로 되어 있다. 또한 , 보안적으로 안심할 수 있는 기능도 갖추고 있다.
>

### 1.4.1 서비스를 이용하기 쉬운 구조

AWS는 전문가가 아니어도 쉽게 조작할 수 있도록 다양한 기능을 갖추고 있어 **전문가가
불필요**하다는 점도 큰 장점이다.

- **관리 콘솔과 매니지드 서비스**가 대표적인 기능이다.

### 1.4.2 관리 콘솔

관리 콘솔은 웹 브라우저의 GUI(Graphical tiser Interite)로 AWS를 조작하는 화면이다.

- 서비스별로 고유 화면이 있어서 서비스 설정, 운영할 리전 선택, AWS 계정 관리, 필요한 서비스나 리소스 그룹의 검색과 사용 , AWS 자료 열람 등 다양하게 관리할 수 있다.

### 1.4.3 매니지드 서비스

매니지드 서비스는 **AWS가 관리하는 서비스의 통칭**이다.

> 자동 백업, 자동 알림, 모니터링, 패치 관리, 보안, 장애를 대비한 이중화
>
- 가상 서버인 Amazon EC2는 매니지드 서비스가 아니지만 스토리지인 Amazon S3, DB 서버인 Amazon RDS 등이 대표적인 매니지드 서비스이다.
- 매니지드 서비스는 백업 및 업데이트가 자동으로 이루어진다.
    - **관리자가 수동으로 할 필요가 없기 때문에 관리 부담이 줄어든다.**
    - Amazon S3의 경우는 관리자가 설정하지 않아도 스토리지 용량이 자동으로 증가하기 때문에 편리하다.

### 1.4.4 보안적으로도 안심할 수 있는 구성

- AWS의 매**니지드 서비스**는 소프트웨어 업데이트와 같은 운영 업무를 자동화할 수 있기 때문에 항상 안전한 상태로 운영할 수 있다.
    - 각종 기준을 충족하게끔 운용되므로 일정 수준을 기대할 수 있다

## 1.5 AWS의 도입 사례: 대기업이나 정부기관에서 도입하는 경우도 다수

### 1.5.1 국내에도 많은 기업이 도입하고 있다

- AWS를 도입한다고 해서 모든 것을 AWS 로 할 필요는 없다. 다른 임대 서비스 및 자기 소유의 인프라와 조합하는 것도 좋다.

### 1.5.2 도입 사례 1: 소규모 블로그 사이트

- 웹 서버와 DB 서버로 구성되어 있고, 웹 서버에는 워드프레스가 설치되어 있다

### 1.5.3 도입 사례 2: 중간 규모 EC 사이트

- 웹 서버 2대로 구성하여 부하를 분산하고 상품 등록 서버, DB 서버, 이미지 • 동영상 서버가 분리되어 있다.

### 1.5.4 도입 사례 3: 업무 시스템

- 업무 시스템 서버 및 인증 서버, DB 서버, 파일 서버로 구성되어 있다

### 1.5.5 도입 사례4: 집계 시스템

- EC 사이트의 상태를 집계하는 시스템이다. 웹 사이트에서 수집한 로그 및 매출 데이터를 저장하고, 집계 · 분석한 결과를 내보낸다

### 1.5.6 도입 사례5: 게임 사이트에 온프레미스와 AWS를 병행하여 사용한 예

- 전부 AWS로 구성하면 시스템의 내용에 따라 비용이 올라간다. 그래서 고정 가능한 부분은 온프레미스에 구축하고 이벤트처럼 변동률이 높은 부분은 AWS 에 구축하여 탄력성을 갖췄다.

## 1.6 AWS의 도입 방법: 계정을 만들고 로그인하면 된다

### 1.6.1 계정을 만들고 로그인하기

AWS를 사용하기 위한 계정을 **AWS 계정**은 이메일 주소와 암호, 연락처, 결제에 사용할 신용카드를 등록하면 만들 수 있다.

### 1.6.2 어떤 지식이 필요할까?

- 웹 사이트나 업무 시스템을 구축 • 운영하려면 네트워크나 서버의 기본적인 지식이 필요하다
    - AWS 가 지원하는 것은 실제 사용에 관한 기술적 부분이지 설계에 대한 부분은 아니다
