## 🧑‍💻 GitHub 운영 방식

**1. 초기 설정**


  - 스터디 저장소를 로컬로 clone
  
    ```bash
    git clone https://github.com/IT-Cotato/11th_AWS_study.git
    ```

  - 정리 내용 제출 전 본인 깃허브 핸들명으로 브랜치를 생성

    ```bash
    git checkout -b [본인 깃허브 핸들명]/week[n]
    ```


**2. 학습 내용 업로드**

  - 학습 내용을 [본인 깃허브 핸들명 폴더]/[챕터 주제].md 형식으로 작성 후 커밋


**3. 커밋 및 PR 생성**

  - 커밋

    ```bash
    git add .
    git commit -m "[Docs] 정찬민 n주차 [주제].md 제출"
    git push origin [본인 깃허브 핸들명]/week[n]
    ```

  - GitHub에서 develop 브랜치로 PR을 생성

  - PR 제목은 "[n주차] 이름 - [챕터명] 요약 정리 제출" 형식으로 작성

**4. 다음 과제 세팅**

  - PR이 merge된 후, 최신 develop 브랜치를 pull

    ```bash
    git checkout develop
    git pull origin develop
    git checkout -b [본인 깃허브 핸들명]/week[n+1]
    ```

  - [본인 깃허브 핸들명] 폴더 내에 새로운 .md 파일을 생성하고 작성
  


**5. 발표자 역할**

- 발표자는 팀원들의 PR을 참고하여 챕터 통합 정리본.md 파일을 작성
- 자신의 정리 내용을 보완하여 PR을 업로드
- 이 PR만 리뷰 대상이 되며, 3인 이상 리뷰 후 머지

**6. Merge**
- 발표자의 PR이 3명 이상의 리뷰어에게 승인되면 `develop` 브랜치에 병합
- 발표자 외 팀원 PR도 별도 머지 (팀장 확인 후)

### 💁‍♀️ 발표자료 정리 형식

- 목차 필수
