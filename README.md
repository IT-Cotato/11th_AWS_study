## 🧑‍💻 GitHub 운영 방식

### ⚙️ 프로젝트 초기 설정 및 협업 워크플로우 가이드

#### 1. 초기 설정

✅ **Fork**  
- 원본 저장소를 자신의 GitHub 계정으로 복제하여 수정 가능한 개인 저장소 생성  
- GitHub 원본 저장소 오른쪽 상단의 `Fork` 버튼 클릭

✅ **Clone**  
- Fork한 저장소를 로컬 환경으로 복제  
- 명령어:

  ```bash
  git clone [Fork한 저장소의 URL]
  ```

✅ **Remote upstream**  
- 원본 저장소를 원격 저장소로 추가 → 최신 내용 반영 가능  
- 명령어:

  ```bash
  git remote add upstream https://github.com/IT-Cotato/11th_AWS_study
  ```

### 🕹️ 작업 흐름 (Workflow)

#### 1. 개인 저장소에서 작업 관리
- `main` 브랜치에서 해당 주차의 학습 내용 정리
- 다른 브랜치에서 작업한 경우, `default branch`를 설정해 팀원이 쉽게 확인할 수 있도록 함

#### 2. 폴더 구조

    
    /
    ├── README.md        # 스터디 메인 README
    ├── Chapter 1/       # 챕터별 폴더
    │   └── ...
    ├── Chapter 2/
    │   └── ...
    └── ...
    

#### 3. Pull Request (모든 팀원 해당)
- 각자 정리한 내용을 자신의 원격 저장소에서 원본 저장소로 PR 생성
- 준비 과정:

  ```bash
  git checkout -b {PR용 브랜치명}
  git fetch upstream
  git reset --hard upstream/main
  ```
- 마크다운 파일을 브랜치에 추가하고 PR 생성
- PR 제목 예시: `[1주차] AWS 기초 지식`

#### 4. 발표자 역할
- 발표자는 팀원들의 PR을 참고하여 자신의 PR을 보완 및 첨삭
- 이후 발표자의 PR만 리뷰 대상이 되며, 리뷰 완료 시 `develop` 브랜치에 머지

#### 5. Merge
- 발표자의 PR이 3명 이상의 리뷰어에게 승인되면 `develop` 브랜치에 병합

---

### 📩 Pull Request 및 코드 리뷰 규칙

- PR은 반드시 원격 저장소에서 수행
- 리뷰는 3명 이상 필수
- 리뷰어 피드백 항목:
  - 오타 유무
  - 의미가 모호한 표현
  - 문장/문단의 흐름
  - 템플릿 형식 준수 여부
  - 스터디에서 다룬 내용이 빠짐없이 담겼는지

---

### 💁‍♀️ 발표자료 정리 형식

- 목차 작성 필수
- 핵심 용어는 `백틱` 으로 강조  
  
  예: `EC2`는 AWS에서 제공하는 가상 서버 서비스
- 서술 범주를 명확히 하고 필요한 경우 간결체 허용
- 중요 단어는 문단 끝에 인용 설명 추가  
  
  예: 

  >프라이빗 IP: 사설 네트워크 안에서만 사용 가능한 IP 주소
- 헤더 구조는 책 목차 기반으로 하되 필요 시 세분화
