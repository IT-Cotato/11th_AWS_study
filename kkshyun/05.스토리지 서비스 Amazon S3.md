### 5.1 Amazon S3란: 사용하기 쉬우며 기능이 강력한 스토리지 서비스

- `Amazon S3`
    - 스마트한 객체 스토리지 서비스
    - `객체 스토리지`란? 데이터를 객체 단위로 관리하는 형식
    - 인터넷상에 데이터를 저장하는 장소 제공
    - 용량 제한이 없으므로 최소한의 용량으로 시작해도 됨
    - 기능이 많음
        - 웹 서버 기능, 쿼리 기능 등이 대표적인 기능
    - 클라우드이므로 확장이나 축소 간단
- Amazon S3 특징
    - 확장성
        - 다양한 스토리지 클래스가 있고, 수명 주기 정책을 사용하여 자동으로 이동 가능
    - 가용성 및 내구성
        - 99.999999999%의 데이터 내구성을 가지고 있어 장애나 오류 위협에 강함
        - 최소 4개의 가용 영역에 자동으로 복제되어 보존되기 때문에 장애가 발생해도 계속 사용 가능
    - 신뢰성
        - 암호화 기능과 접근 관리 도구가 있어 공격으로부터 지키기 쉬움
        - 감사 기능 있음
    - 다양한 관리 기능
        - 스토리지 클래스 분석, 수명 주기 정책 등
        - 실제 사용 환경에 맞는 스토리지 클래스를 선택하는 것이 가능
    - 스마트한 기능
        - `S3 Select` : 데이터에 쿼리를 실행하는 기능과 서비스
        - 분석 서비스와 호환되고 AWS Lambda와 연동 가능
- 요금 체계
    - 보유하고 있는 용량 + 전송량
        - 스토리지 클래스와 리전에 따라 다름
        - 저장 용량 : 데이터를 저장한 양에 따라 과금
        - 전송량 : 데이터를 주고받은 전송량에 따라 과금
- 전송량
    - 수신 요청 : 수신 요청(GET)은 ‘이 파일이 필요해’라고 서버에 보내는 다운로드 명령을 말하고 해당 데이터를 다운로드함
    - 송신 요청 : 송신 요청(PUT)은 ‘이 파일을 저장하고 싶다’라고 서버에 파일을 전송하는 명령을 말하고 해당 데이터를 업로드함


### 5.2 스토리지 클래스: 다양한 종류의 스토리지

- `스토리지 클래스`
    - 스토리지 종류
    - 사용자가 사용 목적에 맞춰서 선택 가능
    - 버킷 단위가 아니고 객체 단위로 클래스 선택 가능
    - 상황에 따라 변경 가능(수동 혹은 수명 주기 정책 설정)
- 스토리지 클래스의 종류
    - 어떤 스토리지 클래스를 사용해도 내구성은 99.999999999%
    - `Standard`
        - 가장 일반적인 스토리지 클래스
        - 3곳 이상의 AZ(가용 영역)에 데이터가 저장되어 있기 때문에 99.9%의 가용성을 보장
        - 데이터를 검색할 때의 요금과 최소 용량의 요금이 없고 일할로 계산됨
    - `Intelligent-Tiering`
        - 빈번한 액세스와 간헐적 액세스에 최적화된 두 가지 계층에 객체를 저장함 → 액세스 빈도에 따라 계층을 자동으로 이동시킴
        - 검색 요금이 부과되지 않고 액세스 계층 간 이동에 대한 요금도 부과되지 않음
        - 액세스 빈도가 자주 바뀌는 경우에 사용하면 비용 줄일 수 있음
        - 최소 저장 기간에 대한 요금이 설정되어 있음
    - `Infrequent Access`
        - 저장 요금이 낮게 설정되어 있는 대신 액세스 요금이 조금 높게 설정되어 있음
        - 액세스 빈도가 낮고 용량이 큰 데이터에 적합함
        - `Standard-Infrequent Access` vs `One Zone-Infrequent Access`
            - Standard는 최소 세 개 이상의 AZ에 저장되지만, One Zone은 한 군데에 저장됨
            - One Zone의 경우 해당 지역에 물리적인 문제가 발생하면 데이터 유실 가능성 있으므로 절대 유실되면 안되는 데이터를 보관하기 에는 적합하지 않음
    - `Reduced Redundancy Storage`
        - Reduced Redundancy Storage는 스토리지 클래스가 아닌 옵션으로 분류되지만 한 종류만 있기 때문에 스토리지 클래스의 하나라고 생각하면 됨
        - Standard에 비해 이중화 수준을 낮춰서 낮은 가격으로 이용 가능
        - 저장되는 AZ가 한 군데이므로 문제가 발생할 경우에 데이터 유실 가능성 있음
    - `S3 Glacier / S3 Glacier Deep Achive`
        - 데이터 아카이브와 장기간 백업을 고려하여 만듦
        - 대용량의 데이터를 저렴한 가격으로 보관 가능
        - `볼트`라고 하는 컨테이너에 데이터가 저장되므로 저장된 데이터를 읽는 경우 다른 S3 버킷으로 옮겨야 함
        - 검색할  경우 Glacier상의 데이터와 검색 대상의 데이터 양쪽에 요금이 부과되므로 주의해야함

### 5.3 S3의 사용 절차: 스토리지 서비스를 사용하기까지

- S3 조작
    - 기본적인 S3 조작은 관리 콘솔의 S3 대시보드에서 수행
    - 가장 기본적으로 객체(파일)의 업로드 수행 가능
    - API와 SDK를 사용하여 업로드할 수 있어 편리함
        - `API`란? 운영체제나 프로그래밍 언어가 제공하는 기능을 제어할 수 있도록 만든 인터페이스
        - `SDK`란? 소프트웨어를 만들 때 필요한 도구를 모아 놓은 패키지
    - AWS Transfer for SFTP가 제공되어 SFTP(SSH로 암호화된 파일 전송 프로토콜)로 액세스 가능
- S3 서비스의 용어
    - `객체` : S3의 엔터티 단위, 파일을 말함
    - `버킷` : 객체를 저장하는 컨테이너, 모든 객체는 버킷에 저장됨
    - `버킷명` : 다른 AWS를 포함하여 유일한 이름이어야 함, 웹 서버로 사용하는 경우에는 도메인명이 버킷명이 됨
    - `객체 키` : 객체 식별자, 모든 객체는 반드시 한 개의 키를 가짐, 버킷과 객체 키와 버전을 조합하여 객체를 고유하게 식별
    - `객체 메타데이터` : 이름과 값의 세트, 사람이 파일을 쉽게 관리하기 위한 데이터
    - 리전 : 버킷의 물리적인 보관 장소가 있는 지역
    - Amazon S3의 데이터 일관성 모델 : 가용성을 유지하기 위해 데이터를 자동으로 복제하여 저장하지만 쓰기 지연에 의한 데이터 불일치가 발생하면 안 되기 때문에 데이터의 무결성을 보장함
    - 웹 서비스 : S3 버킷을 웹 사이트로 사용하는 기능
- S3의 사용 절차
    1. AWS에 로그인
        - 리전을 선택하고 관리 콘솔을 염
        - S3 대시보드 열기
    2. 버킷 만들기
        - 버킷명 설정
    3. 버킷 설정
        - 웹 서버로 사용할 경우, Static website hosting 설정
        - 접근할 수 있는 사용자 설정
    4. 파일 업로드
        - 관리 콘솔이나 전용 도구에서 파일을 업로드
- S3 버킷 생성 전 검토해야할 것
    - S3 버킷을 생성한 후에는 이름과 리전을 변경할 수 없음
    - 어떤 용도로 사용할지 정해야 함
        - 웹 서버로 사용할 경우에 버킷에 대한 공개, 도메인, 익명 접속 허가 등을 고려해야 함
        - 구체적으로 정하기 어려운 경우에는 테스트용 버킷 생성해보고 실제 사용할 스토리지를 생성하는 편이 좋음

### 5.4 객체와 버킷: 파일과 파일을 저장하는 장소

- 객체와 버킷
    - 버킷은 윈도의 드라이브와 같은 것이고, 객체는 파일과 같은 것
    - 버킷은 폴더가 아니므로 버킷 안에 버킷을 다시 만드는 것은 불가능함
    - 객체도 단순한 파일이 아니라 관리를 위한 메타데이터도 포함되어 있음
    - 버킷 하나에 저장할 수 있는 객체 수는 제한이 없고 총 용량에도 제한이 없음
    - S3는 객체 스토리지이므로 폴더나 디렉터리와 같은 개념 없음
    - 객체는 버킷에 병렬로 배치됨
- 버킷 생성과 명명 규칙
    - 버킷을 생성하면 리전과 버킷명 변경 불가능
    - 버킷명은 S3 안에서 유일한 이름이어야 함
    - 리전을 변경해도 같은 버킷명으로 생성할 수 없으므로 생성한 버킷을 삭제하고 새롭게 생성해야 함
    - 대표적인 버킷 명명 규칙
        - 버킷명은 처음과 마지막에 알파벳이나 숫자 사용해야 함
        - 3글자 이상 63글자 이하
        - DNS 명명 규칙에 따라야 함
        - IP 주소 형식은 불가
        - 대문자 혹은 언더스코어 사용 불가

### 5.5 버킷 정책과 사용자 정책: 액세스 제한 설정

- S3 버킷에 대한 액세스 제한
    - 제한 설정 방법 3가지 : 버킷 정책, 사용자 정책, ACL에 의한 관리 정책
    - `버킷 정책` : 해당 버킷에 접속할 수 있는 사용자 지정
    - `사용자 정책` : IAM 사용자 단위로 접속 가능한 버킷 지정
    - `ACL` : 자신 외의 다른 AWS 계정의 ‘읽기/쓰기’에 대해서 ‘허가’ 혹은 ‘거부’를 설정한 목록
- 액세스 제한의 대상과 내용
    - 액세스 제한
        - 리소스, 작업, 효과, 보안 주체에 대해 설정 가능
        - ‘누가(보안 주체), 무엇을(작업), 어떤 것(리소스)에 대해 가능한가 여부(효과)’ 정함
    - 액세스 제한 설정 항목
        - 리소스 : 제한 대상이 되는 버킷 및 객체
        - 작업 : 실제 가능한 작업, GET/PUT/DELETE
        - 효과 : 설정 여부, 허가/거부 설정
        - 보안 주체 : 허가 혹은 거부할 사용자 및 계정, 서비스 등

### 5.6 웹 사이트 호스팅: 웹 사이트 공개

- 웹 사이트 호스팅
    - S3는 정적 웹 사이트 호스팅 가능
        - `정적 웹 사이트`란?
            - 서버가 스크립트를 처리하지 않는 사이트
            - 예를 들어 단순한 HTML과 이미지만으로 작성된 웹사이트
            - 자바스크립트와 같은 클라이언트에서 처리하는 스크립트 포함 가능
    - 정적 웹 사이트를 호스팅하려면 버킷을 그대로 웹 사이트로 오픈하면 됨
    - URL 설정 후 버킷에 누구든지 접속할 수 있도록 하면 됨
- 웹 호스팅에 필요한 설정
    - 정적 웹 호스팅 활성화
    - 공용 액세스 차단 해제
    - 버킷 정책을 ‘모든 사용자’로 설정
    - 버킷명을 사용할 도메인명으로 지정
    - 개인 도메인을 소지한 경우 DNS 서비스를 사용하여 설정
    - 버킷은 기본적으로 제 3자가 접속할 수 없으므로 공용 액세스 차단과 버킷 정책을 변경하여 액세스를 허가해야 함
    - 지정한 버킷명 + AWS가 지정한 문자열이 URL이 됨 → 도메인을 지정한 이름대로 사용하고 싶으면 DNS 설정을 해야함
- 다른 서비스로 구축한 웹 호스팅과의 차이
    - EC2, Amazon Lightsail, AWS Amplify
    - `Amazon Lightsail`
        - EC2를 단순화한 서비스로, 한 가지 기능을 조합한 패키지로 제공함
        - 필요한 기능을 선택하면 웹 사이트에 필요한 서비스 전체를 정해진 가격으로 구축할 수 있는 서비스
        - 요금 계산할 때 Lightsail만 계산하므로 단순함
        - 유연성은 없음
    - `AWS Amplify`
        - 모바일 앱이나 웹 앱을 개발하기 위한 프레임워크
        - 웹을 개발하기 위한 도구 전체를 제공하는 서비스로 개발자 대상
        - 자바스크립트로 AWS의 다양한 기능 호출하여 시스템 구축
    - S3는 서버 프로그램 실행이 안되지만 확장성이 가장 높으므로 프로그램을 쓰지 않는다면 S3가 좋음

### 5.7 파일 업로드와 다운로드: 다양한 파일 업로드 방법

- 업로드와 다운로드
    - 파일을 업로드하거나 다운로드하려면 관리 콘솔을 사용하는 방법과 CLI를 사용하는 방법 있음
    - 도구 및 프로그램에서 작업하려면 API나 SDK를 사용해야 함
    - 모든 파일 형식 업로드 가능, 파일 크기는 제한 있음
        - 관리 콘솔을 사용하는 경우 160GB까지 가능
        - 업로드하는 파일의 크기가 160GB보다 크다면 CLI, SDK 사용
- 다양한 업로드 방법
    - `API와 SDK`
        - `서드 파티 도구`를 사용해 파일 업로드
        - IAM 사용자에게 액세스 키와 보안 액세스 키를 발행하여 사용하고 싶은 도구에 설정
    - `멀티 파트 업로드`
        - 객체를 여러 개로 나누어 세트 하나로 업로드 가능
        - 업로드에 실패한 부분은 재전송되지만 일시적으로 정지하는 것도 가능
        - 100MB 이상의 파일은 멀티 파트 업로드를 사용할 것을 추천함
        - 업로드할 때 일반적인 요청이나 업로드에 대한 요금이 발생하지만 멀티 파트 업로드를 사용할 때는 요금이 따로 발생하지 않음
        - 관리 콘솔, CLI는 큰 파일을 업로드할 때 멀티 파트 업로드로 전환됨
    - `AWS Transfer for SFTP`
        - `SFTP`를 사용하여 파일을 전송할 수 있는 서비스
        - SFTP 서버를 제공하는 서비스
        - SFTP 서버 엔드포인트를 설정하면 서드 파티의 SFTP 도구 사용 가능
        - 초기 비용은 없지만 SFTP 서버를 사용한 시간과 데이터 전송량에 대해 과금됨
    - `AWS DataSync`
        - 온프레미스 스토리지 시스템과 AWS 스토리지 서비스(EC2, S3) 간에 대용량 데이터 전송을 위한 서비스
        - 요금은 복사하는 데이터양에 대해 발생함
        - `하이브리드 클라우드 스토리지 서비스`
            - S3와 클라이언트를 연결하는 방법으로 S3 버킷을 마치 온프레미스의 스토리지처럼 사용할 수 있음
- 대규모 데이터 송수신
    - 물리적으로 AWS와 데이터를 주고받는 방법으로 AWS Snowball, AWS Snowball Edge, AWS Snowmobile 이 있음
    - `AWS Snowball` : HDD에 데이터를 넣어서 보내는 방법
    - `AWS Snowball Edge` : 데이터 가공 처리도 가능함
    - `AWS Snowmobile` : 트럭으로 배송하는 방법
- `공용 액세스 차단`
    - 버킷 단위로 모든 사용자에게 액세스를 허가할지 결정하는 기능
    - 각 액세스 제한보다 상위에 있는 제한
    - 버킷 정책이나 사용자 정책이 모든 사용자에 대해서 액세스가 가능하도록 허가되어 있어도 공용 액세스가 차단으로 설정되어 있으면 액세스 불가

### 5.8 액세스 관리 및 변조 방지: 부정한 액세스 감시

- `액세스 로그`
    - 서버에 어떤 요청이 있었는지 기록하는 기능
    - 로그에는 버킷 소유자, 버킷명, 요청자, 총 시간, 응답 시간, 작업, 응답 상태, 오류, 코드 등이 기록됨
    - S3의 기능으로 액션 로그 기록을 제공하고 있지만 요금은 부과되지 않음
    - 로그를 기록한 파일을 보관하는 것에 대한 요금은 발생
- 액세스 관리 방법 (액세스 로그 제외)
    - `스토리지 클래스 분석`
        - 객체에 액세스 빈도를 분석하는 기능
        - 객체는 설정된 날짜별로 어느 정도 그룹화되어 있어 각 그룹의 평균 전송 바이트 수를 감시함
        - 대상 객체를 필터링해서 감시하는 것도 가능
    - `객체 잠금`
        - 객체를 보호하는 기능
        - 객체에 대한 변경을 허용하지 않음
        - 유효 기간이 있지만, 법적으로 보존해야 하는 경우에는 유효 기간 관계없이 보존 가능
        - 잠금으로 보호되는 버킷은 CRR(Cross-Region-Replication)으로 복사 불가
        - 모드 - 거버넌스 모드(특정 사용자에게만 객체 변경 허가), 규정 준수 모드(모든 사용자가 객체 변경 불가)
    - `S3 인벤토리`
        - 인벤토리는 버킷에 들어 있는 객체의 메타데이터의 목록을 매일 혹은 매주 생성하는 기능
        - 빅데이터를 처리하는 도구와 조합하여 사용하면 편리함
- `S3 배치 작업`
    - 객체에 대한 복사, 복원 등 다양한 작업을 실행할 수 있는 기능

### 5.9 버전 관리, 수명 주기, 복제: 저장된 객체 관리

- `버전 관리`
    - 객체를 여러 버전으로 저장하는 기능으로, 버킷 단위로 설정
    - 버전 관리 기능을 활성화하면 실수로 변경한 파일 복원 가능
    - ‘미사용(기본), 활성화, 버전 일시 중지’ 중 하나 설정
- `수명 주기 정책`
    - 수명 주기 정책은 객체가 정기적으로 수행할 작업을 설정하는 기능
    - 수명 주기 정책을 설정할 수 있는 작업 예시
        - Transition : 객체를 다른 스토리지 클래스로 이동함
        - Expiration : 유효 기간이 만료된 객체를 삭제함
- `교차 리전 복제`
    - 다른 리전의 버킷에 객체를 비동기적으로 복사
    - 복제 작업을 수행하기 위해 IAM 역할을 부여해야 함
    - 복제에 사용할 두 버킷은 버전 관리가 활성화되어 있어야 함
    - 같은 리전에 존재하는 버킷은 복제 설정 할 수 없음
    - 해외에 데이터를 보존하는 경우, 국외 반출이 안 되는 데이터를 보존하지 않도록 주의해야 함

### 5.10 데이터 분석과 연계: 저장된 데이터의 분석

- 데이터 분석과 연동
    - S3 Select, Amazon Athena
        - 구조화된 텍스트 형식의 데이터를 SQL의 SELECT 문으로 실행하는 기능
        - 쿼리를 실행하기 위한 서버는 필요하지 않음
    - Amazon Redshift Spectrum
        - 대용량 데이터를 처리하므로 Redshift cluster가 필요함
            - Redshift cluster : 데이터 웨어하우스를 제공하는 서비스로 Amazon Redshift를 사용할 때 필요
- 데이터 분석 서비스
    - `S3 Select`
        - S3로 저장된 데이터 파일 하나에 SQL 문을 사용하여 집계 및 검색이 가능함
        - 집계는 관리콘솔에서 SQL 문을 입력하여 간단히 실행 가능
        - CLI, SDK를 지원하며 복잡한 집계일 경우 프로그램을 만들어 실행 가능
    - `Amazon Athena`
        - 매번 필요에 따라 분석용 서버를 자동으로 생성하여 실행하기 때문에 실행하는 순간만 비용 발생
    - `Amazon Redshift Spectrum`
        - Amazon S3에 저장된 데이터 분석
        - 어떤 대상에 대해 어떤 검색을 할지 사전에 구성해야함
        - 여러 파일을 대상으로 수행 가능
        - 분석을 위한 서버의 존재 여부
        - 미리 분석용 서버를 시작하고 이 서버를 사용하여 분석
        - 대용량의 복잡한 데이터를 빠른 속도로 처리해야할 경우 추천
- 데이터 분석 도구의 사용 구분
    - 간단한 경우
        - S3 Select가 가장 심플함
            - 파일 하나를 대상으로 집계하거나 검색할 수 있음
    - 복잡한 경우
        - Athena, Redshift Spectrum 사용
            - S3에 저장된 파일 여러 개를 대상으로 분석 가능
            - Athena는 집계나 검색 방법을 저장할 수 있으므로 반복 작업할 때 편리함
            - Redshift는 다양한 기준으로 데이터를 분석하거나 예측 가능
- `AWS Lambda`
    - Lambda는 이벤트 기반으로 코드를 실행하는 서비스
    - S3 버킷에 객체를 업로드할 때 트리거로 Lambda 함수를 호출할 수 있음

### 5.11 Amazon CloudFront: 콘텐츠 배포 서비스

- Amazon CloudFront와 엣지 서버
    - `Amazon CloudFront`
        - 고속 콘텐츠 전송 네트워크 서비스
        - 웹 콘텐츠를 빠르게 전송
        - S3의 웹 사이트 호스팅 기능으로 구축한 웹 서버와 조합하여 많이 사용
    - `엣지 서버`
        - 웹 서버의 내용을 캐시함
        - 엣지 서버에 캐시한 내용을 반환하게 하여 웹 서버의 부담을 줄임
        - 각 리전의 네트워크 말단에 위치해 있음
        - 클라이언트가 접속하는 네트워크의 거리가 가깝기 때문에 반응 속도도 빨라짐
- Amazon CloudFront의 요금 체계와 요금 계층
    - 요금 체계
        - 기본적으로 데이터 송신에 대한 요금 부과됨
        - 엣지 서버가 원본 데이터를 캐시하기 위한 전송량은 요금이 부과되지 않음
        - 캐시에 대한 요금은 부과됨
    - 요금 계층
        - 계층에 따라 사용할 수 있는 엣지 서버가 다름
        - 엣지 서버별로 요금이 다르므로 접속자 수와 균형을 맞춰야 함
