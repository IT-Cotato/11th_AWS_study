### 2.1 클라우드와 온프레미스: 클라우드 컴퓨팅의 구조

- AWS는 클라우드 컴퓨팅을 제공하는 서비스
- `클라우드`
    - 언제, 어디서든 인터넷을 통해서 접속이 가능한 환경
    - 대표적인 예시로 MS의 Office365나 파일 스토리지 서비스, 음악 배포 서비스, 동영상 저장 서비스 등
    - 클라우드 환경에서는 인터넷상에 설치된 소프트웨어나 동영상-음악 등 자원을 사용할 수 있고 로컬 환경에 저장하는 것처럼 저장하는 것도 가능함
- 클라우드 컴퓨팅
    - 클라우드에 구축된 인프라를 활용하는 서비스나 이를 사용하는 것
    - 일반적으로 클라우드라고 하면 클라우드 컴퓨팅을 나타냄
    - 가상화 기술을 사용하여 언제 어디서든지 마음대로 서버나 인프라를 구축하여 운영할 수 있도록 구축되어 있음
    - 보통 서버와 인프라를 대여함 왜냐하면 하드웨어 및 네트워크 등 물리적인 설비를 직접 보유할 필요가 없기 때문
- 온프레미스
    - 자사가 서버 등을 구축하는 것
    - 네트워크나 장소를 임대하는 경우 `온프레미스`라고 부름
    - 장점으로는 자사에서 자유롭게 설계, 운영할 수 있는 점
    - 온프레미스의 반대말은 클라우드가 아닌 `오프프레미스`, 좀 더 가까운 말로는 임대나 공용인데 자사가 소유, 운영하지 않고 임대하거나 공공장소에 구축된 것을 사용하는 형태
        - 여기서 임대의 장점은 회사에서 직접 관리할 필요가 없으므로 기술자를 갖출 필요가 없고 번거롭지 않음
        - 임대의 단점은 제공하는 측의 규제를 지켜야 함, OS 업데이트나 설치할 수 있는 소프트웨어, 구성 등에 제한이 있는 경우가 많고 자유도와 비용이 비례하여 증가함
- 공용 클라우드와 사설 클라우드
    - 공용 클라우드란 AWS처럼 임대하는 클라우드이고 사설 클라우드는 자사에 구축하는 클라우드임
    - 클라우드는 인터넷으로 사용할 수 있는 IT자산이기 때문에 꼭 임대할 필요 없고 자사에서 구축할 수도 있음
    - 온프레미스에서 클라우드로 전환할 경우
        - 자사 운영 → 임대
        - 비클라우드 → 클라우드

### 2.2 가상화와 분산 처리: 클라우드를 지탱하는 2대 기술

- 클라우드를 지탱하는 주된 기술은 가상화와 분산 처리
- `가상화`
    - 가상화 기술 : 컴퓨터가 어떤 작업을 하려면 물리적인 메모리와 하드 디스크, OS 등 다양한 부품이 필요한데 이를 소프트웨어로 대체하는 것
    - 예를 들어 물리 서버 한 대에 가상 서버 여러 대를 생성함 본래 서버에 필요한 물리적인 부품을 가상으로 생성하여 가상 서버로 만드는 것
    - 가상 서버에 할당된 메모리와 스토리지는 자유롭게 늘리거나 줄일 수 있음
    - 가상 서버의 성능을 올리는 것은 한계가 있기 때문에 부하가 발생할 때 서버 대수를 늘려야 함 근데 이때 물리적으로 서버를 늘리는 것보다 소프트웨어처럼 구축해서 서버 복제가 쉬운 가상화가 유리함
- `분산 처리`
    - 분산처리는 기기 여러 대에 분산하여 처리하는 방법
    - 아마존과 같이 거대한 사이트일 경우 서버 한 대로는 처리할 수 없을 만큼 접속이 많이 발생하므로 서버 여러 대에 분산하여 처리함
    - 같은 기능이나 정보를 가진 서버 여러 대에 분배하여 처리하면 서버 1대의 부담을 줄이고 서버가 응답할 수 없거나 다운되는 사태를 막을 수 있음
    - `로드 밸런서` : 서버 여러 대에 분배하는 장치, 각 서버를 확인하여 부하를 분산함
        - AWS는 로드 밸런서로 ELB를 제공함
- 클라우드의 ‘언제든지 마음대로 서버나 인프라를 구축할 수 있다’는 특징은 가상화와 분산 처리에 의해 지탱되고 있음
- 가상화나 분산 처리 방식은 이중화에도 크게 도움이 됨
    - 이중화란 시스템이나 서버에 문제가 생겨도 계속 가동할 수 있도록 조치하는 것
    - 가상화나 분산 처리 방식으로 여러 대의 서버를 구축해서 백업을 할 수 있고, 서버 한 대에 문제가 생겨도 다른 서버에 의해 기능이 유지됨

### 2.3 SaaS, PaaS, IaaS: 클라우드의 서비스 제공 형태

- 클라우드 서비스는 어느 수준까지 서비스가 제공되는지에 따라서 SaaS, PaaS, IaaS 3가지로 구분됨
- SaaS
    - 인프라나 플랫폼(OS)뿐만 아니라 애플리케이션까지 제공함
    - 예를 들어 SNS, 블로그, 웹 메일 서비스 등
- PaaS
    - 플랫폼까지만 제공 (인프라 포함)
    - OS가 설치된 서버에 사용자가 애플리케이션 등을 설치해서 사용해야 함
    - 임대 서버가 PaaS에 해당함
- IaaS
    - 인프라만 제공함
    - 네트워크나 서버 머신 등을 제공함
- EaaS (= XaaS )
    - SaaS, PaaS, IaaS를 통칭하는 말
    - 네트워크를 통한 통신부터 소프트웨어까지 제공하는 서비스
    - AWS는 EaaS라고 할 수 있음
- 인프라나 애플리케이션이 제공되는 것이 편리한 반면 자유도가 낮아지고, 자유도가 높을수록 작업이 어려움
    - SaaS, PaaS, IaaS 순으로 갈수록 자유도가 높아지고 작업이 어려움

### 2.4 서버와 인스턴스: 네트워크상에 만들어진 가상 서버

- 서버
    - AWS의 대표적인 서비스인 Amazon EC2는 간단히 말하면 서비스를 임대하는 서비스
    - 서버란 어떠한 서비스를 제공하는 것을 말함
    - 제공하는 서비스의 종류에 따라 ‘OO 서버’라고 함
        - 웹 기능을 제공하면 웹 서버, 메일 기능을 제공하면 메일 서버
    - ‘OO 서버’의 기능은 소프트웨어로 제공됨
    - 서버 기능을 갖춘 컴퓨터는 OS가 동작하고 그 위에 소프트웨어가 동작함
    - OO 서버를 만드는 것은 OO용 소프트웨어를 설치하고 그 기능을 갖추는 것
- 컴퓨터 한 대에 ‘OO 서버’ 여러 대를 같이 사용하는 것도 가능
    - 소프트웨어가 기능을 갖고 있기 때문에 소프트웨어 여러 개를 설치하면 됨
    - 몇 개까지 사용 가능한지 제한은 없지만 너무 많이 설치하면 성능이 떨어지게 됨
    - 따라서 실제 운영할 때는 컴퓨터 한 대에 소프트웨어 여러 개를 같이 사용하는 경우는 별로 없음
- 대표적인 서버
    - 웹 서버, 메일 서버, 데이터베이스 서버, DNS 서버 등
- 서버에 필요한 요소
    - 서버 기능을 설치하는 컴퓨터(서버 머신)는 특별한 컴퓨터가 아님
    - 노트북이나 데스크톱과 마찬가지로 CPU 및 메모리, 메인보드, 스토리지, OS가 있음
    - 평소에 사용하던 PC를 서버로 사용하는 것도 가능하지만 서버용 PC는 서버용으로 사용하기 쉽게 구성되어 있음
        - 불필요한 기능은 생략하고 잘 고장나지 않는 부품으로 구성되어 있음
- 서버용 OS
    - 컴퓨터를 움직이기 위한 소프트웨어
    - 하드웨어와 OS 위에서 동작하는 소프트웨어 사이에서 중간 역할을 함
    - 예로 서버용 OS는 유닉스 계열과 윈도 계열이 있고 서버용 OS로 유명한 리눅스와 BSD는 유닉스 계열
    - 서버용 OS는 클라이언트용 OS에 비해 종류가 많고 특히 유닉스 계열은 원래 오픈 소스로 개발되었기 때문에 종류가 다양함
    - 리눅스에는 다양한 배포판이 있음
        - 배포판이란 커널(OS의 핵심)의 주변 기능(기본적으로 명령이나 소프트웨어 등)을 추가한 패키지
        - 레드햇, 센트OS, 우분투, 데비안 등이 있음
    - 윈도 계열은 윈도 서버만 있음
        - 파일 서버의 OS로 많이 사용됨
    - 웹 서버나 메일 서버 등 인터넷에 사용되는 서버의 OS에는 리눅스 계열이나 BSD 계열이 사용되는 경우가 대부분
- 인스턴스와 서버
    - Amazon EC2에서 서버는 인스턴스로 생성됨
    - `인스턴스`란 ‘실체’라는 의미이며 실제 가동되고 있는 가상화 컴퓨터를 말함
    - 인스턴스라고 하면 서버로 가동되고 있는 가상 서버(물리 서버 머신에 해당하는 컴퓨터)를 말함
    - 기능으로서의 서버는 인스턴스라고 부르지 않음
        - 웹 서버의 인스턴스를 생성한다는 말이 되어도 웹 인스턴스라고 하지 않음
    - AWS에서는 서버가 인스턴스로 생성됨

### 2.5 LAN: LAN을 구성하는 기술

- AWS 서비스에 따라 LAN과 AWS를 연결하는 방식이 필요함
- LAN
    - `LAN` :  회사나 가정에서 PC나 서버를 네트워크에 연결하여 상호 소통이 가능하도록 하는 방식
    - 유선 LAN : 네트워크 케이블을 유선으로 연결한 네트워크
    - 무선 LAN : 네트워크 케이블을 무선으로 연결한 네트워크
    - `사내 LAN` : LAN 중에서도 회사 내에 설치된 네트워크
        - 인터넷에 연결되지 않은 폐쇄된 네트워크 범위가 `인트라넷`
        - 파일 서버나 웹 서버, 시스템을 동작하는 서버 등이 포함되어 있음
        - 최근에는 이러한 서버군을 AWS와 같은 클라우드에 이관하는 경우가 늘어나고 있음
- LAN을 구성하는 기술 - 6가지 요소
    - 라우터 : 네트워크의 출입구가 되는 부분에 설치되는 기기, 일방향으로 들어온 데이터의 목적지를 확인하고 목적지에 가까운 다른 쪽 네트워크에 데이터를 전송함
    - 허브 : 네트워크의 배선을 분할하는 기기, 같은 네트워크의 다른 단말기에 데이터를 전송함
    - FW(FireWall) : 방화벽, 들어오고 나가는 데이터를 확인하고 통신 여부를 조정하는 장치, 보안을 강화하는 데 사용함
    - DMZ : 비무장 지대, 인터넷과 같이 외부 네트워크와 사내 네트워크의 중간에 설치하는 네트워크, 어느쪽에서든 접속이 가능한 서버를 설치
    - DHCP : 접속되어 있는 단말기에 자동으로 IP 주소를 분배하는 방식
    - 서브넷 : 한 네트워크를 작게 분할한 네트워크

### 2.6 IP 주소와 DNS: 네트워크의 장소를 특정하는 방법

- `IP 주소`는 네트워크 주소와 같은 것
- IP 주소는 숫자의 나열이라 알아보기 어렵기 때문에 `DNS`라는 방식으로 사람이 알기 쉬운 문자열로 바꾸어줌
- IP 주소
    - 인터넷상에서 서버나 네트워크, PC 등 호스트를 구별하는 주소나 이름표와 같은 것
    - 웹 사이트를 볼 때나 데이터를 송수신할 때 사용됨
    - `IPv4` : 4개로 구분된 10진수의 숫자(최대치는 255)로 표시됨 ex) 10.210.32.40
    - IP 주소는 네트워크에 접속되어 있는 한 호스트(PC나 스마트폰) 1대에 최소 1개가 필요함
    - 특정 호스트와 IP 주소는 고정적이라 할 수 없고 개인적으로 사용할 경우 유동적으로 할당되는 것이 일반적임
    - 서버는 IP 주소를 고정해둬야 사용자가 접속할 수 있음
    - AWS에는 Elastic IP라는 IP 주소가 있어서 변동이 많은 클라우드 서버라도 고정 IP 주소에 접속할 수 있도록 되어있음
- 사설 IP 주소와 공인 IP 주소
    - 인터넷에서 사용되는 것은 공인 IP 주소
    - 공인 IP 주소는 관리되고 있기 때문에 전 세계에서 중복되는 IP 주소는 없음
    - 사설 IP 주소는 사내 LAN이나 가정 LAN에서 사용되는 IP 주소
    - 공인 IP주소의 수는 한정되어 있기 때문에 가정이나 회사와 같이 큰 단위로 공인 IP를 할당하고 이 안에 있는 PC는 여기에서만 통신할 수 있는 IP 주소를 할당 받음 → `사설 IP 주소`!
- IPv6 : IPv4 주소의 수가 부족해지고 있어서 현재는 IPv6로 바꾸는 것을 추천
- DNS와 도메인
    - 서버와 같은 단말기(호스트)는 IP 주소로 식별됨
    - 어떤 웹 사이트에 접속할 때 원래는 웹 브라우저에 해당하는 웹 서버의 IP 주소를 입력하여 웹 페이지에 접속해야 하지만 우리는 URL로 접속함 → DNS 방식과 관련이 있음
    - `DNS`란 URL에 포함된 이름에 해당하는 서버의 IP 주소를 알려주는 방식
    - 열람자는 URL로 접속한다고 생각하지만 실제로는 DNS가 백그라운드에서 도메인명에 해당하는 IP 주소를 확인하고 그 IP 주소를 가진 서버에 접속함 → 열람자는 URL만으로 해당 서버에 접속할 수 있게 됨
    - AWS는 Route 53이라는 DNS 서비스를 제공함
    - 가정이나 회사의 사설 IP 주소는 `DHCP 방식`에 의해 각 호스트에 할당됨
- `FQDN`(Fully Qualified Domain Name)
    - 호스트명(www)과 도메인명(gilbut.co.kr)을 연결한 것
    - https 는 HTTPS 프로토콜이라는 의미
    - URL은 FQDN에 파일명을 덧붙여 기술하는 방식
        - 파일이 있다면 /파일명.파일 형식을 도메인 뒤에 붙여 표기하면 됨
