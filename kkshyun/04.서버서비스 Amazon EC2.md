### 4.1 Amazon EC2란: 짧은 시간에 실행 환경을 구축할 수 있는 가상 서버

- `Amazon EC2`(Amazon Elastic Compute Cloud)
    - 컴퓨팅 용량을 제공하는 서비스
    - 서버에 필요한 세트를 클라우드에서 빌릴 수 있음
    - 클라우드의 경우, 빌린 도구를 사용하여 자신의 서버를 만듦
        - 클라우드는 하드웨어의 구성과 OS의 조합을 탄력적으로 선택할 수 있고 구축이 쉽다는 특징이 있음
    - 매니지드 서비스가 아니기 때문에, 서버 및 네트워크 운영은 AWS가 담당하지만, OS를 포함하여 필요한 소프트웨어는 사용자가 직접 설치하고 운영해야 함
    - 관리 콘솔에서 클릭 한번으로 생성 가능 : 다양한 서버 시스템의 조합(인스턴스 유형)과 OS 및 소프트웨어의 조합(AMI)이 준비되어 있기 때문에 선택만 하면 되므로 서버에 대한 기술적 지식은 많이 필요하지 않음
    - ‘어떻게 구성할까?’와 같은 설계적인 관점이 필요함
- Amazon EC2는 불확실성이 많은 경우에 유리함
    - EC2는 관리 콘솔에 로그인하고 구성을 선택하는 것만으로도 서버를 생성할 수 있음
    - 바로 생성할 수 있고, 바로 삭제할 수 있기 때문에 불필요한 리소스를 유지할 필요 없음
    - 복제 및 스케일 아웃, 스케일 다운 기능이 있음
        - 스케일 아웃 : 동일 서버를 여러 개 늘려서 수평적으로 확장
        - 스케일 다운 : 기존 시스템보다 작은 용량으로 줄임
    - 일시적으로 접속이 증가하는 경우에 적합

  ⇒ 불확실성이 많은 경우에 유리함

- Amazon EC2에서의 인스턴스 유형 및 OS 선택
    - EC2로 서버를 생성할 때는 인스턴스 유형을 선택하여 구성할 수 있는데, 어떤 OS를 사용할 것인지, 소프트웨어를 설치할지, 어떤 AMI를 선택할지에 따라 결정됨
    - 인스턴스 유형과 AMI 모두 다양하게 준비되어 있어, 자신만의 소프트웨어를 설치, 설정할 수도 있고 미리 구성된 상태의 인스턴스를 사용할 수도 있음

### 4.2 EC2의 사용 절차: 가상 서버를 사용하기까지

- EC2 운영
    - 물리적인 작업 측면에서는 EC2는 관리콘솔에서 작업할 수 있음
    - 소프트웨어적인 작업 측면에서는 `SSH`를 이용해 원격으로 로그인하여 작업
- EC2 서비스의 기능
    - EC2 서비스에는 인스턴스, AMI, 키 페어 등의 기능이 있음
        - `인스턴스` : AWS 클라우드에 생성한 가상 서버를 의미함
        - `AMI` : 가상 이미지를 말함, 인스턴스를 생성하는 기준이 됨
        - `키 페어` : 인스턴스에 접속할 때 인증을 위해 사용하는 키
        - `EBS` : AWS를 클라우드에서 사용할 수 있는 스토리지
        - `보안 그룹` : 가상 방화벽
        - `Elastic IP` : 정적 IPv4 주소
- EC2의 사용 절차
    - EC2를 사용하려면 관리 콘솔에서 EC2 대시보드를 열고 인스턴스를 생성해야 함
    - 인스턴스가 생성되면 SSH에 접속하면 됨
    - 인스턴스를 만들려면 컴퓨터 사양과 OS의 종류, 소프트웨어뿐만 아니라 네트워크와 IP 주소, 보안도 설정해야 함
    - AWS 상의 가상 서버를 구축하는 절차
        1. AWS에 로그인한다
        2. EC2 인스턴스를 생성한다
        3. EC2에 접속한다
        4. 소프트웨어를 설치하고 설정한다
- 인스턴스 설정 항목
    - 인스턴스는 다양한 항목을 설정할 수 있음
        - AMI, 인스턴스 유형, 리전, 네트워크, 서브넷 등
    - 다양한 인스턴스 유형과 여러 AMI를 제공하고 있으므로 적당한 것을 골라도 괜찮음

### 4.3 인스턴스 생성과 요금: 가상 서버 생성 예시

- 인스턴스의 요금
    - ( 인스턴스 사용량 + EBS 요금 + 통신 요금 + 그 외 옵션 ) 4가지 항목의 비용을 합한 것
    - 단위는 US 달러로 표시되지만 원화로 지불됨
- EC2가 적합하지 않은 경우
    - 단순한 서버 1대로 구성되어 변화가 많지 않은 시스템
    - 단순히 구축만 하는 시스템
    - 또한, EC2는 스스로 관리해야 하기 때문에 운영하는데 수고로울 수 있음

### 4.4 AMI: OS 및 소프트웨어가 설치된 디스크 이미지

- `AMI`(Amazon Machine Image)
    - 소프트웨어 구성을 기록한 템플릿
    - 인스턴스를 생성하기 위한 금형과 같은 것
    - 한번 만들어 놓으면 같은 설정의 서버를 얼마든지 생성하는 것이 가능함
    - 같은 서버를 여러 대 구축해야 할 경우에 편리함
    - 같은 서버를 생성하거나 삭제하기 쉬움
- 제공되는 OS 이미지
    - AMI는 AWS 공식 AMI만 있는 것이 아님
    - OS나 소프트웨어의 커뮤니티판, 기업이 생성한 AMI도 제공함
    - AMI는 바로 사용할 수 있는 상태로 설정되어 있는 경우가 많고, 새로운 버전도 빨리 제공하기 때문에 굉장히 편리함
- AMI 요금
    - AMI는 경우에 따라서 무료와 유료가 있음
    - 원래 유료인 소프트웨어는 AMI에서도 유료임
    - AMI를 개인이 생성할 경우에는 이미지의 용량에 따라서 요금이 부과됨
- AMI 생성
    - AMI는 개인이 만들 수 있음
    - 생성한 AMI는 `마켓플레이스`라는 장소에서 배포 가능
    - EC2 인스턴스에서 생성하며, 기본이 되는 인스턴스를 개인의 취향에 맞게 필요한 소프트웨어를 설정한 후 AMI로 내보냄
    - 개인이나 기업/커뮤니티에서 만든 AMI가 있음
        - 반드시 안전하다는 보증은 없기 때문에, 배포자를 잘 확인하고 사용해야 함

### 4.5 인스턴스 유형: 용도에 맞게 머신을 선택하자

- `인스턴스 유형`
    - 인스턴스 유형이란 머신의 용도
    - CPU, 메모리, 스토리지, 네트워크 용량 등이 용도에 맞게 조합되어 있음
    - 용도는 다섯 가지로 구분되어 있고 각 여러 인스턴스 유형이 존재함
        - 범용, 컴퓨팅 최적화, 메모리 최적화, 가속화된 컴퓨팅 최적화, 스토리지 최적화
- 인스턴스의 유형과 크기
    - 인스턴스의 유형과 크기의 조합이 성능을 의미함
    - t2.micro 처럼 유형과 크기를 붙여서 표기함
    - 유형과 크기에 따라서 단가가 달라짐
    - 기본 요금 = 단가 x 사용 시간
