### 4.1 Amazon EC2란: 짧은 시간에 실행 환경을 구축할 수 있는 가상 서버

- `Amazon EC2`(Amazon Elastic Compute Cloud)
    - 컴퓨팅 용량을 제공하는 서비스
    - 서버에 필요한 세트를 클라우드에서 빌릴 수 있음
    - 클라우드의 경우, 빌린 도구를 사용하여 자신의 서버를 만듦
        - 클라우드는 하드웨어의 구성과 OS의 조합을 탄력적으로 선택할 수 있고 구축이 쉽다는 특징이 있음
    - 매니지드 서비스가 아니기 때문에, 서버 및 네트워크 운영은 AWS가 담당하지만, OS를 포함하여 필요한 소프트웨어는 사용자가 직접 설치하고 운영해야 함
    - 관리 콘솔에서 클릭 한번으로 생성 가능 : 다양한 서버 시스템의 조합(인스턴스 유형)과 OS 및 소프트웨어의 조합(AMI)이 준비되어 있기 때문에 선택만 하면 되므로 서버에 대한 기술적 지식은 많이 필요하지 않음
    - ‘어떻게 구성할까?’와 같은 설계적인 관점이 필요함
- Amazon EC2는 불확실성이 많은 경우에 유리함
    - EC2는 관리 콘솔에 로그인하고 구성을 선택하는 것만으로도 서버를 생성할 수 있음
    - 바로 생성할 수 있고, 바로 삭제할 수 있기 때문에 불필요한 리소스를 유지할 필요 없음
    - 복제 및 스케일 아웃, 스케일 다운 기능이 있음
        - 스케일 아웃 : 동일 서버를 여러 개 늘려서 수평적으로 확장
        - 스케일 다운 : 기존 시스템보다 작은 용량으로 줄임
    - 일시적으로 접속이 증가하는 경우에 적합

  ⇒ 불확실성이 많은 경우에 유리함

- Amazon EC2에서의 인스턴스 유형 및 OS 선택
    - EC2로 서버를 생성할 때는 인스턴스 유형을 선택하여 구성할 수 있는데, 어떤 OS를 사용할 것인지, 소프트웨어를 설치할지, 어떤 AMI를 선택할지에 따라 결정됨
    - 인스턴스 유형과 AMI 모두 다양하게 준비되어 있어, 자신만의 소프트웨어를 설치, 설정할 수도 있고 미리 구성된 상태의 인스턴스를 사용할 수도 있음

### 4.2 EC2의 사용 절차: 가상 서버를 사용하기까지

- EC2 운영
    - 물리적인 작업 측면에서는 EC2는 관리콘솔에서 작업할 수 있음
    - 소프트웨어적인 작업 측면에서는 `SSH`를 이용해 원격으로 로그인하여 작업
- EC2 서비스의 기능
    - EC2 서비스에는 인스턴스, AMI, 키 페어 등의 기능이 있음
        - `인스턴스` : AWS 클라우드에 생성한 가상 서버를 의미함
        - `AMI` : 가상 이미지를 말함, 인스턴스를 생성하는 기준이 됨
        - `키 페어` : 인스턴스에 접속할 때 인증을 위해 사용하는 키
        - `EBS` : AWS를 클라우드에서 사용할 수 있는 스토리지
        - `보안 그룹` : 가상 방화벽
        - `Elastic IP` : 정적 IPv4 주소
- EC2의 사용 절차
    - EC2를 사용하려면 관리 콘솔에서 EC2 대시보드를 열고 인스턴스를 생성해야 함
    - 인스턴스가 생성되면 SSH에 접속하면 됨
    - 인스턴스를 만들려면 컴퓨터 사양과 OS의 종류, 소프트웨어뿐만 아니라 네트워크와 IP 주소, 보안도 설정해야 함
    - AWS 상의 가상 서버를 구축하는 절차
        1. AWS에 로그인한다
        2. EC2 인스턴스를 생성한다
        3. EC2에 접속한다
        4. 소프트웨어를 설치하고 설정한다
- 인스턴스 설정 항목
    - 인스턴스는 다양한 항목을 설정할 수 있음
        - AMI, 인스턴스 유형, 리전, 네트워크, 서브넷 등
    - 다양한 인스턴스 유형과 여러 AMI를 제공하고 있으므로 적당한 것을 골라도 괜찮음

### 4.3 인스턴스 생성과 요금: 가상 서버 생성 예시

- 인스턴스의 요금
    - ( 인스턴스 사용량 + EBS 요금 + 통신 요금 + 그 외 옵션 ) 4가지 항목의 비용을 합한 것
    - 단위는 US 달러로 표시되지만 원화로 지불됨
- EC2가 적합하지 않은 경우
    - 단순한 서버 1대로 구성되어 변화가 많지 않은 시스템
    - 단순히 구축만 하는 시스템
    - 또한, EC2는 스스로 관리해야 하기 때문에 운영하는데 수고로울 수 있음

### 4.4 AMI: OS 및 소프트웨어가 설치된 디스크 이미지

- `AMI`(Amazon Machine Image)
    - 소프트웨어 구성을 기록한 템플릿
    - 인스턴스를 생성하기 위한 금형과 같은 것
    - 한번 만들어 놓으면 같은 설정의 서버를 얼마든지 생성하는 것이 가능함
    - 같은 서버를 여러 대 구축해야 할 경우에 편리함
    - 같은 서버를 생성하거나 삭제하기 쉬움
- 제공되는 OS 이미지
    - AMI는 AWS 공식 AMI만 있는 것이 아님
    - OS나 소프트웨어의 커뮤니티판, 기업이 생성한 AMI도 제공함
    - AMI는 바로 사용할 수 있는 상태로 설정되어 있는 경우가 많고, 새로운 버전도 빨리 제공하기 때문에 굉장히 편리함
- AMI 요금
    - AMI는 경우에 따라서 무료와 유료가 있음
    - 원래 유료인 소프트웨어는 AMI에서도 유료임
    - AMI를 개인이 생성할 경우에는 이미지의 용량에 따라서 요금이 부과됨
- AMI 생성
    - AMI는 개인이 만들 수 있음
    - 생성한 AMI는 `마켓플레이스`라는 장소에서 배포 가능
    - EC2 인스턴스에서 생성하며, 기본이 되는 인스턴스를 개인의 취향에 맞게 필요한 소프트웨어를 설정한 후 AMI로 내보냄
    - 개인이나 기업/커뮤니티에서 만든 AMI가 있음
        - 반드시 안전하다는 보증은 없기 때문에, 배포자를 잘 확인하고 사용해야 함

### 4.5 인스턴스 유형: 용도에 맞게 머신을 선택하자

- `인스턴스 유형`
    - 인스턴스 유형이란 머신의 용도
    - CPU, 메모리, 스토리지, 네트워크 용량 등이 용도에 맞게 조합되어 있음
    - 용도는 다섯 가지로 구분되어 있고 각 여러 인스턴스 유형이 존재함
        - 범용, 컴퓨팅 최적화, 메모리 최적화, 가속화된 컴퓨팅 최적화, 스토리지 최적화
- 인스턴스의 유형과 크기
    - 인스턴스의 유형과 크기의 조합이 성능을 의미함
    - t2.micro 처럼 유형과 크기를 붙여서 표기함
    - 유형과 크기에 따라서 단가가 달라짐
    - 기본 요금 = 단가 x 사용 시간

### 4.6 Amazon EBS: Amazon EC2의 스토리지 볼륨

- `Amazon EBS`(Elastic Block Store)
    - 영구적인 블록 스토리지 볼륨
        - 스토리지란? 데이터를 기록하는 장소로 대표적인 스토리지로는 HDD와 SDD가 있음
        - 블록 스토리지 볼륨이란? 데이터를 바이트 블록 단위로 디스크에 저장하는 일반적인 방식
    - EC2 인스턴스와 조합하여 사용함
- HDD와 SDD
    - `HDD` : 대용량을 지원하며 가격이 싸지만 성능이 낮음
    - `SDD` : 가격이 조금 비싸지만 IOPS(Output Per Second:1초간 처리할 수 있는 입출력 수)가 빠름
    - 고성능이면 SSD, 저비용이라면 HHD가 적합함
- EBS의 볼륨 유형
    - HDD, SDD 두 형태 모두 IOPS 성능을 보장하는 유형과 스루풋에 최적화된 유형 등의 볼륨 유형이 있어서 성능과 요금을 비교하고 선택 가능
- EBS의 기능과 요금
    - 기능
        - 탄력적 볼륨 : 볼륨 크기 간단히 조정 가능
        - 스냅샷 : 어떤 시점의 데이터를 통째로 저장하는 기능
        - 데이터 라이프 사이클 매니저 : 일정에 따라서 스냅샷을 생성, 삭제하는 기능
        - 최적화 인스턴스 : 특정 인스턴스 유형을 최적화 인스턴스로써 읽기 쓰기를 고속화하는 기능
        - 암호화 : 데이터 볼륨, 부팅 볼륨 및 스냅샷을 암호화하는 기능
    - 요금
        - 단가 x 저장 시간
        - 사용 여부와 관계없이 저장하고 있는 용량만큼 비용이 부과됨
        - 서버를 정지해도 요금이 부과됨
        - 단가는 디스크의 종류에 따라 다름

### 4.7 SSH를 사용한 접속과 키 페어: 공개키 암호 방식을 이용한 접근 관리

- SSH로 접속하기
    - 서버의 전반적인 작업은 관리 콘솔에서 수행되지만 서버에 설치한 소프트웨어를 조작하려면 일반적으로 `SSH` 방식을 사용해 원격 접속으로 조작함
    - 서버에서는 SSH를 사용하기 위한 프로그램을 가동시키고 클라이언트에서는 조작하기 위한 소프트웨어를 설치해야함
        - OS에 이미 SSH를 사용하기 위한 프로그램이 설치되어 동작하고 있기 때문에 서버측에서는 따로 프로그램을 설치하지 않아도 됨
        - 클라이언트는 Putty나 Tera Term과 같은 소프트웨어를 주로 사용함
- `키 페어`
    - 키 페어는 로그인할 때 인증으로 사용하며, 공개키와 비밀키로 된 한 쌍을 말함
    - `공개키 방식`으로 불림
    - 공개된 키를 `공개키`, 자신만 알고 있는 키를 `비밀키라고` 하며 두 가지 키는 한 세트임
    - AWS는 공개키와 비밀키를 파일 하나로 취급함
    - SSH로 서버에 접속할 때 인스턴스쪽에서 키 페어에 포함되어 있는 공개키를 지정하고, 클라이언트쪽 소프트웨어에는 내려받은 키 페어 파일을 비밀키로 설정하여 사용함
    - 키 페어는 생성했을 때만 내려받기가 가능하며 재발행 안 됨
        - 잊어버린 경우에는 서버를 재구축해야함
    - 같은 리전의 서비스면 공통의 키 페어를 사용할 수 있지만, 다른 리전에서는 사용할 수 없음

### 4.8 Elastic IP 주소: 고정 공인 IP 주소를 부여

- `Elastic IP 주소`
    - AWS가 제공하는 정적인 공인 IPv4 주소
    - 인스턴스는 정지 후 다시 시작하면 공인 IP 주소가 바뀌는 문제가 있는데 이를 해결하고자 고정 IP로 Elastic IP 주소를 사용
    - AWS 계정과 연결되어 있기 때문에 인스턴스 단위가 아님
        - IP 주소를 부여한 인스턴스를 삭제해도 확보한 IP 주소는 그대로 소유하는 것이 가능하므로 다른 인스턴스나 네트워크에 부여 가능함
    - 인스턴스에 이미 할당되어 있는 공인 IP 대신 Elastic IP 주소를 할당하면 AWS IPv4 풀로 되돌아감
    - 이미 할당되어 있는 IP주소는 Elastic IP 주소로 사용할 수 없음
    - Elastic IP 주소는 리전에 속하므로 다른 리전이 보유하고 있는 Elastic IP 주소는 사용할 수 없음\
- Elastic IP 주소의 요금
    - 기본적으로 인스턴스에 부여된 IP 한 개는 무료
    - 추가로 IP를 연결하면 시간에 비례하여 요금이 부과됨
    - 소유한 IP가 중지된 인스턴스나 분리된 네트워크에 연결된 경우에도 요금이 부과되기 때문에 사용하지 않는 IP 주소는 해지하는 것이 좋음

### 4.9 Elastic Load Balancing: 트래픽을 분배하는 분산 장치

- `ELS`(Elastic Load Balancing)
    - AWS가 제공하는 로드 밸런서
    - `로드 밸런서`는 서버에 집중되는 접속을 서버 여러 대나 네트워크에 분배하는 방식으로 부하 분산 장치라고도 불림
- ELS의 종류(ALB, NLB, CLB)
    - `ALB`(Application Load Balancer)
        - HTTP, HTTPS에 가장 적합한 로드 밸런서
        - 애플리케이션 계층에서 동작함
        - 요청되는 명령어의 내용을 보고 판단하므로 대상의 URL 디렉터리 단위로 분배하는 것이 가능함
        - 인스턴스와 로드 밸런서 사이의 통신은 암호화가 가능함
        - 지원 프로토콜 : HTTP, HTTPS
    - `NLB`(Network Load Balancer)
        - 전송 계층에서 동작함
        - 분배 대상의 정적 IP 주소를 설정할 수 있고 서버에 접속한 클라이언트의 IP 주소를 그대로 서버에 전송하도록 설정 가능함
        - 지원 프로토콜 : TCP, TLS
    - `CLB`(Classic Load Balancer)
        - 오래된 유형
        - 지원하는 프로토콜은 많지만 요즘은 ALB나 NLB로 대체되고 있는 추세
- ELS의 요금
    - 사용 요금 + LCU 요금
        - 사용 요금 : 사용단가 x 시간
        - LCU 요금 : LCU 사용량 x LCU 단가 x 시간
    - LCU의 4가지 항목 중 가장 큰 항목만 과금 대상으로 함
        - 새 연결 수 : 초당 새로운 확정 연결 수
        - 활성 연결 수 : 분당 활성 연결 수
        - 처리된 바이트 : 로드 밸런서에 따라서 처리된 HTTP(S) 요청과 응답의 바이트 수
        - 규칙 평가 : 로드 밸런서에 의해 처리된 규칙 수와 요청 속도의 곱
- CLB의 요금
    - 사용 요금(사용단가 x 시간) + 처리 요금(처리 단가 x 처리량)

### 4.10 스냅샷: 서버 데이터 백업

- `스냅샷`
    - 어떤 시점의 서버 디스크 상태를 통째로 보존한 파일이나 폴더 등의 집합
    - 데이터나 소프트웨어뿐만 아니라 OS와 설정 정보 등도 모두 포함됨
    - 백업하기 위해 스냅샷을 사용하는 경우 많음
    - AMI를 만들기 위해 스냅샷을 사용하기도 함
    - Amazon EBS 볼륨의 데이터를 스냅샷으로 보존 가능
    - 최초에는 통째로 보존하고 그 이후부터는 차분만 보존함
- 스냅샷 생성 방법
    - 관리 콘솔에서 볼륨 단위(스토리지 전체)로 선택하여 생성함
    - `데이터 수명 주기 관리자`를 사용하면 스냅샷의 생성, 삭제를 자동화할 수 있음
    - 요금 : 스냅샷의 분량 단위(GB 단위)로 발생함

### 4.11 오토 스케일링: 수요에 맞춰 EC2 대수를 증감

- `오토 스케일링`
    - 서버의 액세스 상태에 따라 서버 대수를 늘리거나 줄이는 기능
    - EC2 외의 서비스를 지원하는 오토 스케일링도 있음
    - CloudWatch에서 서버의 부하 정보 데이터를 참조하여 스케일링에 참고할 수도 있음
- 감시와 인스턴스 수의 결정
    - Auto Scaling 그룹을 생성하고 그룹에 인스턴스의 최소 대수와 최대 대수를 설정하면 그 범위 안에서 인스턴스 수가 증감함
    - Auto Scaling 그룹은 서버 시작에 필요한 AMI와 키 페어, 보안 그룹 등을 설정해야 함
    - 인스턴스 증감 3가지 방법
        - EC2 인스턴스가 정지한 경우에 분리하고 새로운 EC2 인스턴스를 생성하는 방법
        - 일정에 맞춰 스케일링하는 방법
        - CPU와 네트워크의 부하를 참고하여 특정 임계 값을 넘을 때 인스턴스 수를 자동적으로 증감함
