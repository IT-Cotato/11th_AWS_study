### 7.1 데이터베이스와 RDB: 데이터를 관리하는 시스템

- 데이터베이스와 DBMS
    - `데이터베이스` : 구조적으로 정리된 데이터의 집합체
    - `데이터베이스 관리 시스템(DBMS)` : 데이터 저장, 삭제, 검색 등과 같이 데이터베이스를 실제로 조작하는 역할을 담당함
    - `SQL` : 데이터베이스에 명령할 때 사용되는 언어
    - DBMS 종류 : ex) MySQL, PostgreSQL 등
- RDB와 비RDB
    - `관계형 데이터베이스(RDB)` : 표 형태, 정밀한 조작 가능
        - AWS 서비스 : Amazon RDS
    - `비관계형 데이터베이스(비RDB)` : 구조가 단순, SQL을 사용하지 않아 NoSQL 데이터베이스라고도 함
        - AWS 서비스 : Amazon DynamoDB, Amazon ElastiCache

### 7.2 Amazon RDS란: 주요 RDBMS를 제공하는 데이터베이스 서비스

- `Amazon RDS`
    - 관계형 데이터베이스 6종류의 제품을 클라우드에 최적화된 상태로 제공하는 서비스
    - Amazon Aurora, PostgreSQL, MySQL, MariaDB, Oracle Database, SQL Server 지원
    - VPC상에 인스턴스 형태로 구축하며 다양한 인스턴스 클래스를 사용할 수 있음
    - 업데이트 등의 관리가 AWS에 의해 자동으로 이루어짐
- `인스턴스 클래스`
    - RDS는 인스턴스 형식으로 사용함
    - 인스턴스 클래스는 `표준`, `메모리 최적화`, `버스트 성능`의 3종류 있음
    - 데이터베이스 인스턴스는 VPC에 설치해야함
- RDS 요금
    - DBMS에 따라 인스턴스 요금이 다름
    - RDS 요금 = 스토리지 요금(디스크) + 데이터베이스 인스턴스 요금(시간당 요금, 유료 DBMS의 경우 라이선스 요금 추가) + 백업 스토리지 요금(스냅샷 요금은 스토리지 크기의 100%가 넘을 경우 발생) + 통신료(인터넷으로 통신할 경우 해당 전송량)
- RDS의 장점과 단점
    - 장점
        - 매니지드 서비스
        - 간단하게 데이터베이스 생성 가능
    - 단점
        - 사용자가 자유롭게 사용할 수 없음
        - 제공하는 DBMS 종류나 버전이 한정되어 있음

### 7.3 RDS에서 사용할 수 있는 DBMS: 데이터베이스 엔진을 선택한다

- RDS에서 사용할 수 있는 데이터베이스 엔진
    - Amazon Aurora, PostgreSQL, MySQL, MariaDB, Oracle Database, SQL Server 외에도 SQL Server, Oracle Database와 같은 상용 데이터베이스도 지원
    - 상용 데이터베이스의 경우 데이터베이스 라이선스 요금이 인스턴스 사용 요금에 포함되어 있음
- `Amazon Aurora`
    - MySQL, PostgreSQL과 호환할 수 있음
    - AWS가 만든 관계형 데이터베이스
    - 요금이 조금 비싼 편이지만 견고하고 성능이 뛰어남
    - AWS용으로 설계되어 있기 때문에 일반적인 MySQL이나 PostgreSQL 데이터베이스에 비해 속도가 빠름
    - AWS에서 MySQL이나 PostgreSQL을 사용하는 방법 3가지
        - EC2에 설치하는 방법
        - RDS 즉, Amazon Aurora를 사용하는 방법
        - EC2에 MySQL이나 PostgreSQL을 설치하여 이전

### 7.4 RDS 사용 절차: 데이터베이스를 사용하기까지의 절차

- RDS 조작
    - 데이터베이스 작업은 데이터베이스 준비와 데이터베이스 사용으로 나누어짐
    - `데이터베이스 준비 작업`
        - 데이터베이스를 만들거나 설정하는 등의 조작
        - 관리 콘솔에서 이루어짐
        - RDS는 매니지드 서비스이므로 업데이트가 자동으로 이루어짐
    - `데이터베이스 사용 작업`
        - 데이터를 입력, 삭제, 변경하는 조작
        - 데이터베이스 클라이언트나 소프트웨어를 통해 이루어짐
- RDS 서비스의 기능
    - `데이터베이스 엔진 항목`
        - 어떤 DBMS를 사용할 것인지 정해야함
        - 데이터베이스 엔진 항목 : 데이터베이스 엔진, 템플리스, 라이선스 모델, 데이터베이스 엔진 버전
    - `데이터베이스 인스턴스 항목`
        - 온프레미스 환경의 물리적인 서버에 해당하는 항목
        - 사용할 수 있는 예산과 관련되기 때문에 요금과 기대 효과를 고려하여 필요한 사양 선택
        - 데이터베이스 인스턴스 항목 예시 : 인스턴스 클래스, 다중 AZ 배포, 스토리지 유형 등
    - `네트워크 항목`
        - RDS 인스턴스는 반드시 VPC에 설치해야함
        - EC2와 연동하려면 EC2가 사용하고 있는 서브넷 그룹 및 가용 영역을 확인해야함
        - 네트워크 항목 예시 : VPC, 서브넷 그룹 등
    - `데이터베이스 환경 항목`
        - 데이터베이스별로 환경을 설정할 수 있음
        - 유지보수와 관련된 설정 많으므로 운영을 고려하여 설정하는 것이 좋음
        - 데이터베이스 환경 항목 예시 : 데이터베이스명, 포트, 데이터베이스 파라미터 그룹, 옵션 그룹
- RDS의 사용 절차
    - RDS를 사용하려면 관리 콘솔에서 RDS 대시보드에 접속하여 인스턴스를 생성해야함
    - 인스턴스가 생성되면 데이터베이스 클라이언트 혹은 소프트웨어를 통해 데이터를 입력하고 갱신해야함
    - 대부분의 경우, RDS는 EC2에 설치된 소프트웨어와 연동하여 사용
    - AWS 로그인 → DB 인스턴스 생성 → RDS 접속 → 데이터 입력

### 7.5 키 밸류 데이터베이스: 키를 관리하는 데이터베이스 서비스

- `키 밸류 스토어 데이터베이스(KVS)`
    - 데이터의 형식에 관계없이 어떤 데이터에 대해서 특정 ‘키’가 되는 값을 결합하여 저장하는 방식의 데이터 베이스
    - NoSQL 데이터베이스의 대표적인 예
    - 유연성이 높아서 형식에 구애받지 않고 데이터를 입력할 수 있음
    - 데이터로 저장하기 때문에 상세하게 검색할 수 없음
    - 데이터에 대한 액세스가 빠름
    - AWS 종류 : DynamoDB(스토리지에 저장), Amazon ElastiCache(메모리에 저장)
- `Amazon DynamoDB`
    - 키 밸류 스토어 데이터베이스
    - 관계형 데이터베이스에 맞지 않는 범용적 데이터를 저장하는데 사용함
    - 관계형 데이터베이스와 달리 데이터를 저장하는 형식이 정해져 있지 않고 데이터끼리 연관 관계도 없음
    - 응답 속도가 빠름
    - VPC가 불필요해 VPC를 사용하지 않는 애플리케이션 환경과 궁합이 좋음
    - 대규모 데이터를 처리하기 때문에 ACID 트랜잭션, 데이터 암호화, 접근 제한 등의 서비스를 갖추고 있음
- `Amazon ElastiCache`
    - `인 메모리 데이터베이스`
        - 데이터베이스를 조작할 때마다 외부 기억 장치에 읽기/쓰기를 수행하지 않고, 빈번하게 읽고 쓰는 데이터는 일시적으로 메모리에 보관하는 방식
        - 메모리를 활용하여 처리 속도를 빠르게 함
    - 인스턴스를 재시작할 때 데이터가 삭제됨
    - 빠른 속도를 목적으로 하는 캐시 용도로 많이 사용됨
    - 종류 : Redis용, Memcached용 (대표적인 인 메모리형 키 밸류 스토어 DBMS)

### 7.6 그 외의 데이터베이스: 다양한 데이터베이스 서비스를 제공한다

- 관계형 데이터베이스, 키 밸류 데이터베이스로는 처리할 수 없는 데이터 유형을 처리하기 위해 문서 기반 데이터베이스, 그래프 데이터베이스 등이 생김
- `Amazon DocumentDB`
    - MongoDB 호환 데이터베이스 서비스
    - `MongoDB`
        - 오픈 소스의 문서 기반 데이터베이스
        - JSON 형식을 바이너리로 변환하여 BSON 형식으로 데이터 저장
        - 빅데이터 처리, 분산 처리에 적합한 NoSQL 데이터베이스
    - DocumentDB는 MongoDB가 대규모의 데이터를 안정적으로 입출력할 수 있도록 설계됨
    - 기본 MongoDB 드라이버와 도구 사용 가능
- `Amazon Neptune`
    - 그래프 데이터베이스
        - `그래프 데이터`? : 여러 가지 요소 사이의 관계 혹은 처리의 흐름을 나타내므로 노드의 방향을 포함한 노드 사이의 연결을 기록한 데이터
    - 대표적인 그래프 모델인 Property Graph와 W3C의 RDF에서 사용하는 쿼리 언어인 Apache TinkerPop Gremlin과 SPARQL을 지원함
    - 관리가 자동화되어 있음
    - 네트워크를 통한 데이터의 읽기/쓰기는 HTTPS로 암호화됨
    - 추천 시스템이나 소셜 네트워크, 지식 그래프 등에 사용되며 데이터 간의 복잡한 관계를 처리할 수 있음
- `Amazon Timestream`
    - 시계열 데이터베이스 서비스
        - `시계열 데이터베이스` : 시간의 경과에 따른 사물의 변화를 기록한 데이터로 전형적인 IoT의 데이터 취득 형태
        - 시간별로 취득한 데이터를 관계형 데이터베이스에 저장하는 것은 가능하지만 집약 및 집계 쿼리를 수행하기는 쉽지 않음
    - 쿼리 처리 엔진이 시간별로 처리하는 데 최적화되어 있으며 평활법, 근사, 보간 등의 분석 함수를 사용할 수 있음
    - 자원이 충돌하지 않도록 새로운 데이터를 삽입하고 기존 데이터의 쿼리를 다른 계층에서 처리함
    - 필요에 따라 스케일링이 되기 때문에 용량이나 부하를 고려할 필요가 없음
- `Amazon Quantum Ledger Database(Amazon QLDB)`
    - 장부 데이터베이스
    - 데이터 변경을 추적하여 이력을 남기는 저널 형식을 채용함
    - 저널 데이터는 변경, 삭제가 불가능하며 암호화 해시 함수에서 변경한 내용을 변조하는 것을 방지하고 있음
    - SQL과 비슷한 API나 문서 기반 데이터 모델을 제공함
    - 조작은 쉬운편
