### 3.1 AWS의 사용법과 계정: AWS에서 제공하는 유용한 도구

- 필요한 것을 필요한 만큼 사용해야하기 때문에 항상 ‘자신에게 최적화된 상태로 관리한다’가 클라우드를 잘 사용하는 요령
    - 사용한 만큼 지불하므로 사용하지 않으면서 불필요하게 확보하지 않아야 함
    - 사용할 거 같으면 늘리고 필요 없으면 줄이는 등 상황을 보고 자주 조정함
- AWS는 서비스를 종합적으로 관리할 수 있는 편리한 기능을 제공함
    - `관리 콘솔` : 서비스 설정 화면, 웹 브라우저에서 사용 가능
    - `CLI` : 명령어로 조작 가능한 명령줄 도구, 관리 콘솔에서 할 수 없는 것도 가능
    - `IAM` : 서비스를 사용하기 위한 사용자 계정
- AWS 계정 : AWS를 사용하기 위한 계정
    - AWS를 이용하려면 AWS 계정을 사용
    - 이메일 주소, 암호, 연락처, 결제하기 위한 신용카드를 등록해야 함
    - 개인뿐만 아니라 기업 단위도 많이 사용하는데 이때 관리하는 서비스가 커지면 관리하기가 어려우므로 AWS 계정을 구분하여 많이 사용
- root 사용자
    - AWS 계정은 등록한 이메일 주소와 암호로 로그인함
    - AWS 계정은 모든 조작이 가능한 관리자 권한을 가지고 있으므로 root 사용자라고 불림
    - 모든 권한을 가지고 있으면 편리하긴 하지만 실수하면 곤란해짐 → 일반적인 운영에는 IAM 서비스를 사용
- 서비스를 개인에 맞춰서 최적화
    - AWS는 언제든지 시작해서 언제든지 멈출 수 있음 → 즉, 필요할 때만 필요한 서비스를 사용
    - 서비스 한 개에 여러 옵션 있음
        - 서버 서비스인 Amazon EC2의 경우 인스턴스의 유형을 선택하거나 용량을 선택할 수도 있음

### 3.2 관리 콘솔과 대시보드: 심플하고 직관적인 관리 도구

- 관리 콘솔
    - 웹 브라우저에서 AWS 서비스를 관리하는 화면
    - 서비스별로 고유 화면(대시보드)이 있음
    - 서비스 설정, 리전 선택, AWS 계정 관리, 필요한 서비스나 리소스 그룹의 검색과 사용, AWS 문서의 참조 등 다양한 관리를 수행
    - 서비스 대부분 한국어를 지원함
    - `Amazon Console 모바일 앱`을 통해 리소스의 상태를 외출 중에도 확인 가능
    - 복잡한 명령어를 입력해 서비스를 조작할 필요 없이 명령어를 잘 알지 못하는 사람도 관리 콘솔에서 서비스를 사용 가능
- 리전 선택
    - 관리 콘솔을 지역을 대표하는 리전 단위로 조작함
    - 같은 서비스여도 다른 리전은 다른 것으로 간주됨
    - 관리 콘솔의 처음 지역은 버지니아로 되어 있지만 로그인 후 사용하고 싶은 리전으로 전환 가능
    - 리전은 한번 선택하면 저장되기 때문에 같은 리전을 사용하려면 한번만 선택하면 됨
    - 다른 리전의 서비스를 사용할 때는 리전 전환해서 사용
    - 리전에 따라 제공하지 않는 서비스도 있음
- `대시보드`
    - 관리 콘솔에서는 서비스별로 메뉴가 있어서 각 화면에서 조작하는데, 여기서 서비스를 조작할 수 있는 메인 화면은 대시보드라고 함
    - EC2의 경우 EC2 대시보드, S3인 경우 S3 대시보드가 있음
    - AWS의 각 서비스를 조작하려면 AWS 계정으로 로그인한 후 리전이나 서비스를 선택하여 해당 대시보드를 열어야 함
    - 대시보드에서 가능한 조작은 서비스에 따라서 다르지만 공통적으로는 서비스의 시작과 종료, 각종 설정, 현재의 상태에 대한 표시 등을 사용할 수 있음
    - 주요 서비스는 한국어를 지원함
- `AWS CLI`
    - 로컬의 명령어 단말기 혹은 서버에서 명령어나 스크립트로 AWS 서비스를 빠르게 수행하기 위한 CLI(명령줄 환경)
    - AWS의 다양한 서비스 설정이나 조작은 관리 콘솔에서 시각적으로 진행하지만, 스크립트를 작성해서 여러 가지 조작을 한번에 실행하거나 좀 더 자동화되고 프로그램화된 방법으로 조작할 경우에는 AWS가 편리함
    - 파이썬의 패키지 관리 도구인 pip을 사용하여 설치함
    - 작업은 컴퓨터의 명령 프롬프트나 터미널을 열고 aws로 시작하는 일련의 명령어를 사용
    - 먼저, awsconfigure에서 AWS 로그인의 인증정보를 입력하여 설정함

    ```java
    $ aws ec2 start-instances --instance-ids i-12345678
    $ aws s3 ls
    ```


### 3.3 AWS IAM과 접근 권한: 접근 권한 설정

- `AWS IAM`
    - AWS IAM은 AWS의 인증 기능
    - AWS는 서비스 여러 개를 사용하기 때문에 적절한 관리를 위한 인증 방식이 반드시 필요함
    - AWS 계정과의 차이점 : AWS 계정은 계약을 관리하는 계정이고, IAM은 각 서비스에 대한 접속을 관리하는 기능
    - `IAM 사용자` : 사람에 대해 부여하는 IAM
    - `IAM 역할` : 서비스나 프로그램 등에 부여하는 IAM
    - IAM 사용자가 사용한 AWS에는 과금이 되지만 IAM 자체에는 추가 요금이 없고 무료로 사용 가능
    - AWS는 사용자 인증에 `MFA`(Multi-Factor Authentication)를 사용할 것을 권장하고 있음
- IAM 그룹과 IAM 정책
    - IAM 사용자, IAM 역할 두 가지 모두에 필요한 최소한의 기능을 부여하고, 필요한 사람에게만 전달하여 운영하는 것이 기본 → 혹시 몰라서 불필요한 권한을 부여하는 것은 보안적으로 바람직하지 않음
    - 계정 하나를 여러 사람이 돌려쓰면 누가 수행한 작업인지 알기 어렵기 때문에 바람직하지 않음
    - 사용자나 역할을 효과적으로 설정하고 관리할 수 있는 구조로 되어 있음
    - `IAM 그룹`
        - 사용자는 IAM 그룹으로 그룹화할 수 있음
        - 그룹화하면 같은 권한을 부여하고 싶은 사용자를 일괄로 관리할 수 있음
    - `IAM 정책`
        - IAM 정책은 실행자(사용자, 역할, 그룹)가 어떤 서비스에 접속할 수 있는지 정해진 규칙을 설정하는 기능
        - 실행자가 무엇을 할 수 있는지를 개별로 설정하는 것이 아니라 정책을 적용하는 형태로 설정
        - 권한 설정을 변경하고 싶을 때도 정책만 변경하면 그룹에 속한 모든 사용자나 역할의 설정을 변경할 수 있음
        - 정책은 실행자 한 명에 대해 여러 설정을 할 수 있고, 정책 한 개를 여러 사용자나 역할에 설정할 수도 있음
- IAM 정책 설정하기
    - IAM 정책은 무엇에 대해서(Amazon EC2 서버나 Amazon S3의 폴더 등) 어떤 조작을(시작 및 정지, 파일 쓰기 및 읽기, 삭제 등) 허가할지 말지를 설정하는 것
    - `자격 기반 정책` : 실행자(사용자, 역할, 그룹)가 ‘어떤 일을 할 수 있는가’의 형태로 설정
    - `리소스 기반 정책` : 조작 대상(서버 및 폴더 등)에 대해서 ‘무엇을 허가할 것인가’의 형태로 설정
    - 어떤 조작을 지정할 수 있는지는 서비스나 대상에 따라 다르고 세밀하게 설정이 가능함
    - IAM 정책은 자기만의 정책을 생성하는 것(`고객 관리형 정책`)이 가능하지만, 설정할 항목이 많고 실수를 할 수 있기 때문에 기본적으로는 미리 준비되어 있는 `AWS 관리 정책`을 사용하는 것을 추천
    - AWS 관리 정책과 다른 부분만 고객 관리형 정책을 설정하는 식으로 조합하면 좋음
    - 자격 기반 정책과 리소스 기반 정책에 설정할 수 있는 항목이 조금 다름
    - 주요 설정 항목
        - Statement : 설정 값으로, Effect나 대상 등을 기술
        - Sid : 정책 문서에 부여된 임의의 식별자
        - Effect : 사용 여부를 알려줌
        - Action : 허가 혹은 거부하는 특정 작업
- 다단계 인증, 다요소 인증
    - 1단계 인증 : 암호를 알면 관리 콘솔에 로그인 가능
    - `다단계 인증` : 1단계 인증에 두번 이상의 인증을 수행하는 것
        - ID와 암호뿐만 아니라 전용 하드웨어를 사용하거나 생체 인증을 사용하는 등 다른 종류의 인증을 사용하는 것이 일반적임
    - `다요소 인증` : 요소 여러 개로 인증하는 방법
    - AWS에는 ID와 암호 외의 인증으로 MFA 장치를 사용
        - `MFA 장치`란 전용 하드웨어를 사용하는 것도 있지만 아이폰이나 안드로이드 앱을 사용하여 화면에 일정시간마다 바뀌는 숫자가 표시되면 그 숫자를 로그인할 때 입력하여 인증

### 3.4 Amazon CloudWatch: Amazon EC2의 리소스 상태 감시

- `Amazon CloudWatch`
    - 서버의 모니터링을 도와주는 서비스
    - 각 AWS 서비스의 리소스 모니터링과 관리를 담당하는 서비스
    - AWS의 각 서비스에서 지표, 로그 등을 수집, 기록함
    - 감시 상황에 대처하는 관리도 가능함
    - 기본 요금은 없고 종량제 요금제로 사용한 만큼만 지불
    - Amazon CloudWatch는 지원하는 서비스와 지원하지 않는 서비스가 있음
- 사용 가능한 조작과 Amazon CloudWatch Logs
    - CPU 사용률, 볼륨의 읽기 쓰기 횟수나 바이트 수, 네트워크 송수신 패킷 수 등을 감시할 수 있음
    - 감시하고 있는 항목이 임계 값을 넘을 경우에 어떠한 작업을 하도록 설정할 수 있음
    - `Amazon CloudWatch Logs`
        - Amazon CloudWatch Logs를 통해 로그를 기록할 수 있음
        - Amazon EC2 인스턴스에 에이전트를 설치하면 인스턴스 내에서 임의의 로그를 기록할 수 있음
        - 간단한 필터 기능 있음
        - 로그를 확인할 수 있는 화면도 있음
        - 일정 기간이 지나면 로그를 삭제하거나 S3 버킷(Amazon S3에서 데이터를 저장하는 용기)으로 내보내는 것도 가능
    - `AWS CloudTrail`
        - 누가 어떤 리소스에 접근했는지도 기록으로 남길 수 있음

### 3.5 AWS Billing and Cost Management: AWS의 비용 관리

- AWS는 종량제인만큼 비용 관리가 중요함
- `AWS Billing and Cost Management`
    - AWS 요금을 관리해주는 서비스
    - 요금 납부, 사용료 모니터링, 비용 및 사용 현황 보고 등을 사용할 수 있음
    - 서비스 해지도 여기서 실시
    - 주요 서비스
        - 청구서 : 매월 청구서 및 사용하고 있는 AWS 서비스의 상세 내역을 확인할 수 있음 / 무료
        - 요금 대시보드 : 지출 현황과 비용 경향 등을 확인할 수 있음 / 무료
        - 비용 및 사용 보고서 : 비용과 사용량에 대한 가장 자세한 데이터를 열람할 수 있음 / 무료
        - AWS Cost Explorer
        - AWS Budgets
- `AWS Cost Explorer`
    - 매월 어느정도 비용이 발생했는지 서비스 단위별로 확인 가능
    - 월별, 일별로 볼 수 있으며 그래프로 표시되므로 비용의 증감을 직관적으로 파악 가능
    - 부가 사용자 인터페이스 사용시에는 무료, API를 사용하여 프로그램에 접속하는 것은 유료
- `AWS Budgets`
    - 비용이 특정 임계 값을 넘었을 때 알림을 발송할 수 있는 구조로 되어 있음
    - AWS Budgets 보고서 : 이메일로 예산 포트폴리오 업데이트를 받을 수 있음
    - 사용 자체는 무료이지만 3개 이상부터 요금이 부과됨
- 비용과 사용 현황 확인
    - 비용과 사용 현황 보고서는 비용과 사용 현황에 대한 자세한 데이터가 1일 1회, CSV 형식으로 Amazon S3의 S3 버킷에 저장됨
    - 임의의 집계, 통계 도구(Amazon Athena 등)로 보내는 것도 가능
- 비용 관리 요령
    - 유사한 기능을 구현하는 데 다른 서비스를 사용 가능한 경우도 있기 때문에 나에게 어떤 서비스가 바람직한지 잘 분석하고 어떤 서비스를 이용할건지 파악해야함
    - 새로운 서비스가 지속적으로 출시되고 있기 때문에 정기적으로 서비스 확인
    - 서비스 한 개가 여러 유형을 제공하거나 옵션을 추가할 수 있는 경우도 있으므로 정기적으로 확인
    - 선택을 잘 하더라도 잘 운영해야 비용을 최대한 줄일 수 있기 때문에 실태 파악 하기
