### 6.1 Amazon VPC란: AWS에 생성하는 가상 네트워크

- `Amazon VPC`(Amazon Virtual Private)
    - 웹 서버나 데이터베이스 서버와 같은 서버들은 네트워크에 연결되어있어야 하는데 이러한 네트워크 구축을 위해 사용됨
    - AWS 계정 전용 가상 네트워크 서비스로, AWS에서 제공하는 리소스만 설치할 수 있음
    - EC2나 RDS의 경우, VPC를 선택하지 않으면 서버를 생성할 수 없어 리소스를 사용하기 위해서 반드시 필요한 서비스
- VPC의 구성
    - VPC 내에 서버를 설치하면 해당 네트워크에 소속되지만, 따로 설정을 하지 않으면 VPC 자체는 격리된 네트워크가 됨
    - 외부와 통신하려면 VPC를 인터넷 혹은 회사 내 LAN과 연결해야 함
    - AWS에 VPC를 생성하고 그 안에 서버를 설치함
- VPC의 기능
    - VPC는 네트워크와 서브넷 범위, 라우팅 테이블, 네트워크 게이트웨이 등과 같은 가상 네트워킹 환경을 설정할 수 있음
    - `IPv4`, `IPv6` 둘 다 사용 가능
    - 주요 기능
        - `CIDR 블록` : 서브넷, 네트워크를 나눈 범위
        - `서브넷 마스크` : 네트워크의 크기를 계산하는 값
        - `가용 영역` : 서브넷이 구축된 물리적 장소
        - `인터넷 게이트웨이` : 인터넷에 접속하기 위한 출입구, VPC를 인터넷에 연결하지 않을 경우에 불필요함
- VPC 네트워크의 특징과 라우팅 테이블
    - VPC는 물리적인 라우터가 아닌 소프트웨어가 라우팅을 수행
    - `라우팅`은 설정된 라우팅 테이블에 따라 동작하는데, 클라우드는 `라우팅 테이블`로 연결함
    - 라우팅 테이블 한 개에 서브넷 여러 개 설정 가능
    - VPC 하나에 인터넷 게이트웨이 한 개만 설정 가능
    - 라우터와 인터넷 게이트웨이는 명시적인 IP 주소가 부여되지 않음 (클라우드의 특징)
    - 서브넷 사이의 통신은 라우터 없이 직접 통신 가능

### 6.2 VPC의 사용 절차: 가상 네트워크를 사용하자

- `VPC`
    - VPC는 네트워크
    - 인터넷 연결 여부와 오토 스케일링이 중요함
        - 인터넷에 연결해야 하면 인터넷 게이트웨이 설정
        - 오토 스케일링을 설정해야 한다면 서버가 자동으로 늘어나므로 IP 주소를 많이 확보해두어야 함
    - `보안 그룹`과 `네트워크 ACL`을 설정하려면 인스턴스 용도에 맞는 포트를 설정하는 것도 고려해야함
        - 모든 포트가 닫힌 것이 기본 설정
        - 서버를 사용하려면 기본 설정을 변경해야 함
        - VPC는 기본 VPC를 비롯해 기본 서브넷과 보안 그룹도 제공함 → 잘 모르는 상태라면 기본 VPC를 추천함
- VPC 사용 절차
    - VPC 이름을 정하고 CIDR 블록에 네트워크 범위 설정
    - 네트워크를 작게 서브넷으로 나눔
    - 인터넷에 접속하기 위해서는 인터넷 게이트웨이 생성하고 라우팅 설정
    - 보안그룹 및 네트워크 ACL 설정
    1. AWS에 로그인한다.
    2. VPC를 생성한다.
    3. 서브넷을 설정한다.
    4. 인터넷에 연결한다.

### 6.3 기본 VPC: AWS가 제공하는 기본 VPC

- `기본 VPC`
    - 네트워크 지식이 없어도 VPC를 사용할 수 있도록 기본 VPC를 제공함
    - 리전별로 기본 VPC 제공
    - 특별한 설정 없이 바로 사용 가능
- 기본 VPC 구성
    - `서브넷`과 `인터넷 게이트웨이`가 기본적으로 구성되어 있음
    - 네트워크의 범위는 사설 IP 주소 172.31.0.0/16 이 부여됨
    - 기본 서브넷이 가용 영역별로 한 개씩 생성되어 있음
        - 각 서브넷은 /20의 주소 범위로 설정되어 있음
    - 인터넷 게이트웨이가 구성되어 있어 인터넷에 접속 가능
        - 인터넷에 접속하고 싶지 않으면 별도의 VPC를 생성하거나 기본 VPC 변경
            - VPC 마법사를 사용하면 몇 단계에 걸쳐 선택 후 VPC 생성 가능

### 6.4 서브넷과 DHCP: 사용할 범위 선택

- `서브넷`
    - 커다란 네트워크를 작게 나눈 네트워크
    - 네트워크를 분할해 직접 통신할 수 있는 범위를 좁히고, 방화벽을 설정해 보안을 강화함
    - 물리적인 장소를 특정함
    - 서브넷별로 역할을 다르게 부여할 수 있음
    - 라우팅 없이도 서브넷끼리 통신 가능
- 네트워크 범위와 CIDR 표기
    - `CIDR` : 네트워크와 서브넷의 범위를 나누는데 사용되는 표기법 (= 프리픽스 표기)
        - / 뒤에 네트워크 길이를 숫자로 적어서 표기
        - IP 주소의 수를 나타냄 ex) /24 → 2^(32-24) = 256개
    - 네트워크 범위는 범위 안에서 가장 첫번째 IP 주소와 CIDR 순으로 표기함
        - ex) 172.31.0.0/16 → 172.31.0.0(범위 내에 가장 첫번째 IP 주소), 16(CIDR, 65536개의 IP)
- `네트워크 클래스`
    - 네트워크는 규모에 따라서 A, B, C 세 클래스 존재
    - A, B, C 순으로 범위가 좁아짐
    - 기본 VPC는 /16(B 클래스)으로 설정되어 있으며 이를 /20으로 분할한 서브넷이 각 가용 영역에 구성되어 있음
- IP 주소 할당과 `DHCP`(Dynamic Host Configuration Protocol)
    - AWS의 VPC는 EC2 인스턴스나 RDS 인스턴스 뿐만 아니라 라우터나 인터넷 게이트웨이에도 IP 주소를 할당할 수 있음
    - 네트워크 및 서브넷에 사용되는 IP 주소의 범위는 관리자가 설정할 수 있고, DHCP에서 각 호스트에 IP 주소를 자동 할당해줌
        - 인스턴스가 추가되면 해당 서브넷 범위의 IP 주소 중 하나가 할당됨
    - VPC가 일반적으로 사용하는 IP 주소는 사설 IP 주소

### 6.5 라우팅과 NAT: 공인 IP 주소와 사설 IP 주소 변환

- 네트워크 간 데이터를 주고받으려면 라우팅이나 NAT 방식을 사용해야 함
- 네트워크와 라우팅
    - `네트워크` : PC 여러 대가 서로 통신할 수 있도록 연결되어 있는 상태
    - LAN이나 WAN, 인터넷으로 연결해 라우터를 통해 데이터를 주고받음
    - `라우팅` : 데이터를 라우터로 보내고, 라우터가 목적지로 보내는 방식
        - 호스트에서 호스트로 데이터를 전달하는 형태로 데이터 송신
        - 라우터에 연결하면 원하는 목적지에 데이터 송신 가능
- IP 주소와 게이트웨이
    - `IP 주소` : 대상을 식별할 수 있는 주소
        - 클라이언트 PC나 서버뿐만 아니라 라우터 등 네트워크 안의 모든 호스트에 설정되어 있음
    - 목적지에 데이터를 보낼 때 목적지의 IP 주소를 지정
    - 데이터를 라우터로 보낸 후, 라우터는 자신의 네트워크 내에 목적지가 있다면 데이터를 그 목적지(호스트)로 전달하고, 목적지가 없다면 다른 라우터로 전송
    - 라우터에는 목적지로 가장 빠르게 전송할 수 있는 경로 정보 설정되어 있음
    - 라우터 = 게이트웨이
        - 기본 게이트웨이 : 게이트웨이 중에 자신 이외의 접속되어 있는 모든 것
- `IP 마스커레이드`
    - 같은 회사에서 데이터를 전송할 때는 라우터를 사용하지만 멀리 떨어진 곳에 데이터를 전송할 때는 인터넷 이용 → LAN 이외에는 기본적으로 인터넷 거침
    - `게이트웨이` : LAN에서 인터넷으로 데이터를 전송할 때 LAN 내부의 출입구
        - 게이트웨이는 기기의 역할을 말하며 실제 기기는 라우터
        - LAN에서 전송되는 데이터를 인터넷으로 보내고, 인터넷에서 들어오는 데이터를 목적지 PC로 전송
    - 사설 IP 주소를 공인 IP 주소로 변환하고 가정 내에서 혹은 회사 내에서는 공인 IP 주소 하나를 공동으로 사용, 이때 주소 변환을 담당하는 것이 IP 마스커레이드(NAPT)
- `NAT`
    - IP 마스커레이드를 사용하면 내부에서 외부로 나가는 것은 가능하지만, 외부에서 내부로 들어오는 것은 불가능함
        - 외부에서 내부로 요청하는 것에는 응답하지 않기 때문
        - 서버만 양방향으로 통신할 수 있도록 IP 마스커레이드를 설정할 수 있음
        - IP 마스커레이드는 공인 IP 하나만 설정할 수 있으므로 서버가 여러 대라면 공인 IP 주소를 여러 개 설정할 수 있는 NAT 사용해야함
    - IP 마스커레이드 vs NAT
        - IP 마스커레이드는 일대다, NAT은 다대다
        - IP 마스커레이드는 포트 변환이 가능하지만 NAT는 포트를 변환할 수 없음

### 6.6 인터넷 게이트웨이와 NAT 게이트웨이: VPC에서 인터넷으로 접속

- AWS는 물리적인 라우터가 아닌 소프트웨어적으로 라우팅 수행
- 라우팅은 라우팅 테이블에 따라 수행됨
- `인터넷 게이트웨이`
    - 인터넷 연결을 담당
    - 예를 들어, 웹 사이트에 접속하고 싶다는 요청은 DNS에서 변환되어 목적지인 공인 IP 주소로 전달됨 → 인터넷 게이트웨이가 공인 IP 주소를 사설 IP 주소로 변환하여 요청 보냄
- `NAT 게이트웨이`
    - 서브넷에서 인터넷으로 접속할 수 있지만, 인터넷에서 서브넷으로 접속하지 못하게 함

### 6.7 보안 그룹과 네트워크 ACL: 보안 설정

- AWS는 보안 그룹과 네트워크 ACL 두 종류의 가상 방화벽을 제공함
- `보안 그룹`과 `네트워크 ACL`
    - `방화벽` : 네트워크 통신을 제어하는 방식
    - 인바운드 트래픽(데이터 유입), 아웃바운드 트래픽(데이터 유출)을 제어
    - 양쪽 모두 명시적으로 설정하지 않으면 기본 설정 적용됨
    - 네트워크 ACL
        - 서브넷 단위로 설정해 개별 인스턴스에 설정할 필요 없음
        - 네트워크 ACL 하나에 서브넷 여러 개 설정 가능
        - 서브넷 하나에 네트워크 ACL 여러 개 설정 불가
- 인바운드 및 아웃바운드 설정과 잘 알려진 포트
    - 트래픽은 인바운드와 아웃바운드에 대해 포트 단위로 허가 여부 설정
    - `포트` : 통신의 입구
    - 보안 그룹의 기본 설정은 인바운드를 허가하지 않으며 아웃 바운드 허가
    - 네트워크 ACL의 기본 설정은 양쪽 모두 허가
    - `주요 포트 번호`
        - SMTP : 25
        - HTTP : 80
        - HTTPS : 443
        - SSH : 22
        - MySQL : 3306

### 6.8 VPC 엔드포인트: 다른 AWS 서비스 및 엔드포인트 서비스와 연결

- `VPC 엔드포인트`
    - VPC 내부에서 VPC 외부로 접속하기 위한 연결점을 제공하는 서비스
    - VPC 외부의 다른 서비스와 VPC를 연결하려면 인터넷 게이트웨이를 사용해 인터넷으로 접속해야함
    - AWS의 모든 서비스가 VPC 내에 설치되어 있는 건 아님
        - ex) S3, DynamoDB
    - 인터넷 게이트 웨이를 통하지 않고, S3와 같은 VPC 외부에 있는 서비스와 VPC를 직접 연결해주는 것이 엔드포인트 서비스
    - VPC의 출입구로 엔드포인트를 설정하면 S3와 직접 연결 가능
    - 종류 - 인터페이스 엔드포인트, 게이트웨이 엔드포인트
- 인터페이스 엔드포인트와 게이트웨이 엔드포인트
    - VPC 엔드포인트는 가상 서비스로 확장성과 고가용성을 지원하며 네트워크 트래픽에 대해 자동으로 스케일링 됨 → 네트워크 트래픽에 대해 고민하지 않아도 됨
    - `인터페이스 엔드포인트` : 네트워크 인터페이스로 구축하는 유형
        - 사설 IP 주소를 가진 ENI가 존재하며 각 서비스와 연결하는 출입구 역할을 함
        - AWS PrivateLink 방식 사용 → 서비스가 이 방식을 지원하면 사용 가능
    - `게이트웨이 엔드포인트` : 라우팅 테이블에 설정된 내용을 라우팅하는 유형
        - 서비스 리전 단위로 라우팅 테이블을 설정하는 방식
        - S3, DynamoDB는 이 형식 취함
- 요금
    - 엔드포인트 요금은 무료이지만, 인터페이스 엔드포인트의 경우 AWS PrivateLink를 사용하므로 이에 대한 요금이 부과됨
    - 인터페이스 엔드포인트 경우에는 AWS PrivateLink를 사용하므로 이에 대한 요금이 부과되는데, 인터페이스 엔드포인트가 설정되어 있지 않으면 부과되지 않음
    - 인터페이스 엔드포인트 요금 = VPC 엔드포인트 한 개당 사용료 + 데이터 처리량
    - 게이트웨이 엔드포인트 요금의 사용료는 무료지만 데이터 송신료는 부과됨

### 6.9 VPC 연결: VPC와 VPC의 연결과 VPC와 VPN의 연결

- VPC와 다른 네트워크를 연결하는 방법
    - VPC 피어링
    - 전송 게이트웨이
    - VPN 연결
    - AWS Direct Connect
- VPC 연결
    - VPC는 다른 VPC나 네트워크와 연결할 수 있음
    - VPC끼리 연결하려면 VPC 피어링 기능을 활성화해야함
    - VPC는 물리적인 네트워크 혹은 다른 클라우드에도 접속할 수 있음
    - AWS는 인터넷상의 서비스뿐만 아니라 회사 시스템을 구축할 때도 사용할 수 있음
    - 전용선(AWS Direct Connect) 혹은 가상 사설망(AWS VPN)을 사용하면 AWS와 사내 LAN이나 온프레미스를 안전하게 연결할 수 있음
- 전용선과 가상 사설망
    - `WAN` : 네트워크와 네트워크를 연결해 커다란 네트워크를 구축하는 것
    - WAN 구축하는 방법
        - `전용선`
            - 통신 사업자가 직접 연결할 수 있는 회선인 전용선을 임대하여 구축
            - 비싸지만 안전하고 신뢰성이 높음
        - `가상 사설망`
            - 보유하고 있는 회선뿐만 아니라 공용 회선을 사용하여 거점끼리 통신을 암호화하여 연결
            - 비용은 싸지만 신뢰성 낮음
        - AWS와 다른 네트워크를 연결
    - 인터넷 VPN
        - VPN 중에 인터넷을 사용해 구축하는 경우
        - 인터넷 회선만 사용하므로 VPN을 지원하는 라우터만 설치하면 이용할 수 있음
- `AWS Direct Connect`
    - VPC나 AWS 서비스와 다른 네트워크를 전용선으로 연결하는 서비스
    - 도입 규모가 크며 월 비용도 많이 발생함
    - 프라이빗 연결과 퍼블릭 연결 존재
- `AWS VPN`
    - 인터넷 VPN을 사용하여 다른 네트워크와 연결하는 방법
    - VPN 연결 : 인터넷을 이용한 연결, 회사 내 VPN을 지원하는 라우터가 설치되어 있다면 사용할 수 있는 연결
    - VPC에 VPG를 구축함
    - 네트워크 품질과 속도를 보장하지 않음
- `전송 게이트웨이`
    - VPC나 온프레미스 네트워크를 하나로 묶어 서로 연결하는 접속점을 제공하는 서비스
    - 네트워크 여러 개를 중앙 거점으로 집약하여 통신 경로를 통합적으로 처리하는 서비스
